# HEB 暴表源窗内的饱和普查

对 `HEB_list.xlsx` 全部 **832** 条，逐条检查 `[Trig+src_start, Trig+src_stop]` 窗内
HXMT/HE 有没有饱和。一并查出并修掉了 `detect.rs` 两道关卡共有的一处量纲错配：
判据把泊松指数的分母交给了一个 26% 抖动的率估计。

## 结果

| | 条数 |
|---|---|
| `saturated`——窗内至少一次 FIFO A 复位，有真实数据丢失 | **141** |
| `clean`——两个数据产品里都没有洞 | **691** |

其中 **138 条由判据判出**，3 条手工并入——那 3 条的窗口 1B 归档完全没有覆盖，
判据无从跑起，改用 1K 判。`source` 列区分 `criterion` / `manual`。

14513 条复位，总死时间 182.7 s；跨箱重建的丢失事例合计 1.247e7，其中 221009A 一条占 128.2 s / 1.117e7。
其余 140 条合计 54.5 s / 1.29e6 事例。受影响箱体：单箱 88、双箱 25、三箱 28。

## 怎么查的

对每条暴的**绝对 MET 窗**跑两件独立的事（839 个归档小时任务；7 条窗跨小时，
两个小时都跑取并集；221009A 的 `src_*` 列是 `-`，改用 `tstart/tstop` = −50…+2000 s）：

1. `blink sat detect` —— 1B 逐包时间重建出的 FIFO 复位，**权威判据**。
2. `blink sat dump packets` —— 逐包事例率，积出 FIFO 队列占用。MCU 以
   109 事例 / ~7 ms = 15571 evt/s 抽空 FIFO A，容量 455 事例（M67204H，
   4096×9 bit，每事例 9 字节）。**所有非饱和窗的积压峰值 ≤ 350**，
   即没有被漏掉的持续斩波（`detect.rs` 注释里那个已知盲区）。

外加 `blink sat extract --source 1k` 在同样的窗上跑一遍做独立对照：
凡 1B 判饱和的窗，1K 事例流里洞的总长与 1B 逐包洞的总长**逐条相等**
（相对差中位 0.0000）。

**18 条窗口 1B 归档无覆盖**（文件在，但该小时事例流不含这一段；1K 有数据，
已核对）。这 18 条改用 1K 判定，`judged_on` 列标注。其中 HEB240118075、
HEB250824475 判饱和，其余 16 条干净。

## 顺带查出的判据缺陷（已修）

一个空洞要判成 FIFO 复位得连过两关，而**每一关量到的都是整包平均**：
`MCU_READ_RATE_FLOOR` 闸门比的是 `event_rate = n_events / span`，`GAP_FACTOR`
的基线是 `mean_event_interval = span / n_events`；闸门还在 **±5 个包**的范围里
取最大。本底率下一个包横跨约 27 ms，所以这个平均把毫秒尖峰稀释约十倍，而 ±5 包
意味着测量点离空洞可以有几百毫秒（中断段里一个包能横跨 108 s，就是几百秒）。

### 两个测试要用两个不同的 λ

判据问的是两件对 λ 要求相反的事，原来共用一个估计量，这是病根：

| | 问什么 | 需要的 λ | 噪声的后果 |
|---|---|---|---|
| FIFO 闸门 | 缓冲区有没有可能被填满 | **瞬时**，毫秒尺度 | 只让闸门略宽松 |
| 泊松否决 | 这个洞是不是「碰巧没来事例」 | **稳定**的本底率 | 进指数，±26% → e^±26 |

`gap > GAP_FACTOR / rate` 移项是 `rate × gap > GAP_FACTOR`。`rate` 若是真实
泊松率 λ，这就是 **λT**，常量有单位、能直接算全任务的假空洞数。但它除的是
16 个事例估出的 λ̂，相对标准差 1/√15 = 25.8%，两个方向都实测到了后果：向上涨落
放噪声进来（名义降到 30，12 小时冒出 13 条 <5 ms 的洞，而真 λT=30 的算术预期是
全任务 0.32 条，差七个数量级）；向下涨落把真洞挡在外（HEB211105190 的 11.87 ms
洞，λ̂T = 47.5 不过关，稳定 λT 是 61.8）。

### 现在的判据

```
edge_rate   = 洞两侧各 16 个事例的率，取高        （瞬时，σ≈26%）
stable_rate = 洞前后各 0.5 s 的计数 / 活时间      （稳定，σ≈1.4%，包级求和即可）

FIFO 闸门:  edge_rate >= LOCAL_RATE_FLOOR   (2000 evt/s)
泊松否决:  stable_rate × gap > MIN_POISSON_EXPONENT  (30)
           stable_rate 估不出时回退 edge_rate × gap > GAP_FACTOR (100)
上界:      gap <= 1 s
```

活时间而不是窗长做分母：窗口里若含别的空洞，除以窗长会把率压低、λT 跟着压低，
那是漏检方向。

### 两个阈值都是扫出来的

**`LOCAL_RATE_FLOOR`**，12 个整小时：500 / 1000 / 2000 / 3000 / 4000 / 6000 /
8000 给出**逐条相同**的结果（+67, −0），10000 开始丢，15000 丢 406 条（都在斩波
段：洞旁 16 个事例的率到不了 15 kHz，旧判据靠几百毫秒外的尖峰放行）。取 2000，
落在这段平台中间：比中断段包的 1–19 evt/s 高两个数量级，比低速率箱的约 400 evt/s
高 5 倍。

**`MIN_POISSON_EXPONENT`**，8 个整小时上分两群量稳定 λT：

| | n | 洞长中位 | 稳定 λT（p1 / 中位 / max） |
|---|---|---|---|
| 判据已接受的 | 1778 | 16.06 ms | 47.5 / 373.9 / 806.6 |
| 只在名义阈降到 10 才冒出的 | 2836 | 1.50 ms | 0 / 6.4 / **16.1** |

噪声上界 16.1、真值最低（非零）37.8，**16–38 之间空着**。自洽性：这 8 小时
×3 箱 ×4000 evt/s ≈ 3.5e8 个间隔，纯泊松下最大 λT 的期望 ln(3.5e8) = 19.7，
实测噪声最大 16.1——换成稳定 λ 之后尾巴确实是泊松的，试验次数那套算术才能用。
全任务约 3.4e12 个间隔：λT=30 期望 0.32 条假空洞，λT=40 期望 1.4e-5。取 30 而不是
40，因为两头代价不对称——误报只多 ±1 s 掩模（实测曝光 +0.30%），漏检是真缺口没
标出来。30 距噪声上界 1.9 倍、距最低真值 1.26 倍。

### 中途试错，留档

* **整包滑窗峰值做基线**：多出 6 条起止落在整秒的 1.000 s「空洞」。中断段的包
  横跨 5.8 s、12.9 s 甚至 108 s 才凑够 109 个事例（率 1–19 evt/s），里面只要有
  16 个事例挤在一起，整包峰值就虚高、基线塌到极小。这正是发现闸门里 `peak_rate`
  + ±5 包是同一个构造的线索。
* **只用边缘窗做基线**：洞旁 16 个事例恰好偏稀时门槛反被抬高，HEB211105190 从能
  检出变成检不出——捡回一条又丢一条。最后靠稳定 λ 解决，不是靠取 min 凑合。
* **`MCU_READ_RATE_FLOOR` 一名两用**：`reconstruct_gaps` 在 gap 两端都估不出率时
  拿它当形状函数的地板填充值。检测阈值下调时差点把重建的填充率一起改掉，已拆成
  两个常量。
* **注释里「持续斩波一个 reset 都不报」与实测不符**，已删。2024-05-11T20（Gannon
  episode 真正所在的小时，之前误记成 00 点）实跑：旧判据 26866 条、新判据 26871
  条，洞长中位 18.47 ms，正落在注释描述的 16–22 ms 梳齿上。下游关于占空比的后果
  仍然成立。

### 复查查出的真 bug：稳定率的分母，以及它背后的真正原因

`stable_event_rate` 的活时间原先是**逐包交叠求和**，这假定同一个盒的包不重叠。

**FIFO 严格保序，本来就不该重叠**：包 N 的最后一个事例必须早于包 N+1 的第一个。
实测也确实如此——2023-06-16T20、2019-05-30T10、2022-10-09T13（221009A）、
2024-05-11T20（斩波）、2021-02-13T06（断档）五个小时近**两百万个包，
`max_met[i] > min_met[i+1]` 的违规一次都没有**。

但 2026-01-25T19 有 23 次（34 万包里，0.007%）。查到包内，不是物理现象：

```
pkt 112554: 109 个事例，108 个挤在 2.8 ms 内，剩 1 个晚了 591.7 ms，evt_idx 倒退 1 处
pkt 114342: 主体 3.0 ms，离群那个晚了 1051.7 ms ≈ 一个 ptime 回绕周期(1.048576 s)
```

**是单个事例的重建时间错了**（离群量约等于一个 wrap，指向 wrap 误判），把包的
`max_met` 拉到几百毫秒外，于是它跟后面几百个包"重叠"。逐包求和把这近 1 s 全算进
分母却只带 109 个事例，率被稀释约十倍（3,289/s 对真实的约 35,000/s），**漏检方向**。

同一个假定还藏在往前回退找起点的循环里。Rust 提前停、恰好把被污染的包排除了
——**偶然正确**；另写的 Python 不停，两边算同一个量差出两三倍，缺陷就是这样暴露的。

已改：分母取被覆盖时间的**并集**，回退按 `max_met` 的前缀最大值 `reach`。
中断段里那类**合法**的长包（约 1 evt/s，一百多秒凑够 109 个事例，包内无倒退）
并集同样处理得对。影响：50 个跨年份小时里只有 1 个变化（+31，全 <5 ms），
13 个验证小时**一条不变**，832 个源窗的复位明细**逐字节一致**。新增 2 条回归测试。

**这个 bug 我原来那套验证碰不到**——那些小时里一次违规都没有。

### 根因：wrap 误配，已按 FIFO 保序剔除（方案 A）

`min_met`/`max_met` 取包内事例时间的极值，对错配的时间不稳健。查下去是**两层**
独立的缺陷，都违反同一条硬约束——**FIFO 严格保序**：

| 层 | 违反形式 | 实测 |
|---|---|---|
| **包级** | 按 `pkt_idx` 排序后 `min_met` 倒退 | 一整块包被判**早**了一个 wrap，落进前面的死区 |
| **包内** | 按 `evt_idx` 排序后时间倒退 | **单个事例**跳了一个 wrap（pkt 114342 第 104 个跳 1048.6 ms） |

两者互相独立，缺一个都补不齐：包级的错配把真实死区填上、切成碎片；包内那个尖刺
把 `max_met` 撑到 202.05，于是 `gap = 后包.min_met − 前包.max_met` 算成负数，
**整个吞掉**一个真实空洞。

**两层的形状不同，算子也不同**——这一点踩过两次才对：

* **包级**是「两支长度相当」（错配块与它覆盖的正确块各约 100 个包）。先试最长不减
  子序列，**它挑错了边**：近似平局下没有信息分辨谁对，实测保留了错配的 1144xx、
  丢掉真实的 1143xx，报出的洞整体偏 13 ms。可分辨的信息在包号里——错配块**包号
  更大、时间却更早**，所以改成**按包号顺序贪心**（时间一倒退就剔），先被保住的
  必然是正确的那支。
* **包内**是「1 个离群对 108 个正常」。**贪心用在这里正好做反**：它会接受那个尖刺、
  把后面 4 个正常事例全剔掉，`max_met` 反而更糟。改成**剔掉比两侧都晚的孤立尖刺**，
  向下的离群交给后面的单调兜底（若这里也判向下，尖刺后面那个正常事例会被连坐）。

**验收：与 1K 逐齿对照**（1K 是独立产品，同段是干净的 15.2 ms 斩波梳齿）

| 1B（修后） | 1K | 差 |
|---|---|---|
| 443995200.957462 / 15.214 ms | 443995200.957461 / 15.214 ms | +1.0 µs |
| 443995201.000060 / 15.184 ms | 443995201.000060 / 15.184 ms | **0.0 µs** ← 修前整条缺失 |
| …其余 7 齿… | … | 0.0 µs |

**9 齿全中，位置吻合到 1 µs 以内。**修前是 1.6–6.9 ms 的一串碎片。

**影响面**（63 个对照小时，含 SAA、断档、221009A、斩波、跨 2017–2026 的 50 个抽样）：

* **只有 1 个小时变化**：9394 → 9326，剔掉 167 条碎片（<10 ms 占 164）、
  补回 99 条真实梳齿（13.6–15.8 ms）。其余 62 小时**一条不动**。
* 剔除量克制：正常小时 1370 万事例里剔 18–21 个，包级 0 个。
* 832 个源窗的复位明细**逐字节一致**；六条论文暴的重建**逐字节一致**。
* 新增 4 条回归测试（干净包不剔、单事例跳 wrap 要剔、有序包流不剔、错配块整块剔）。

**没做修复，只做剔除**：被剔的包/事例时间不可信，它们覆盖的区间不再产出饱和结论。
真正的修复要回 `rec_sci_data.rs` 的 wrap 指派（深饱和时 SEC 锚点稀疏/损坏），
那是另一件事。另外这条贪心对「被判**晚**一个 wrap」的块不成立（会先接受错的），
实测三处都是判早，没遇到判晚的；真出现要靠包的 UTC 尾戳另行判别。

### 一次失败的复查设计，留档

把分离检验从 8 小时铺到 50 小时时，我把「真值群」定义成「阈值 30 接受的」——
而阈值 30 卡的就是稳定 λT，**用被检验的量本身定义人群，是循环论证**。出来的
「重合」只反映 Python 与 Rust 实现在切点附近的差异。8 小时那一版不循环：两群是
用**边缘率**判据（`GAP_FACTOR` 100 vs 10）分的，量的是**稳定 λT**，两个不同的量。
分离的证据仍以 8 小时那一版为准。

### 顺带修的性能缺陷

`is_in_unreliable` 原是**线性扫描**，逐事例、逐形状格各扫一遍全表。复位稀疏时
无所谓，但 2024-09-18T20 那种一小时两万条复位的小时，每箱七八千段 × 上百万次查询
就是实际意义上的 O(n²)：707 段的小时 8.3 gap/s，7000 段的小时掉到 0.107 gap/s，
慢 78 倍，整小时要跑几十小时，重建根本做不完。区间本来就按 start 排好且互不重叠，
改 `partition_point` 二分，严格等价——190530A / 200415A / 211211A 三条重建事件流
**逐字节一致**，速度 85 s → 68 s（深饱和小时的收益大得多）。

`fifo_resets` 页逐条给 `n_lost_recon` 与 `fill_kind`。它是**整条 gap** 的重建值，
跨窗口边缘的 gap 会比窗级总数多算边缘外那部分（差 0.06% 量级）；窗级数以主表为准。

复核用的光变脚本：`scripts/plot_heb_marginal_holes.py`、`plot_heb_marginal_stack.py`、
`plot_heb_reset_skytest.py`、`plot_heb_hole_vs_rate.py`。
