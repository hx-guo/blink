# 天格（GRID）搜索：已核实的事实与未决项

搜索管线与仪器无关（`blink_search::search_day` 对 `Instrument` 泛型），天格只提供
自己的 `Chunk`/`Event`。四颗有事例产品的星共用一份实现，用类型参数 `Satellite`
区分。本文记录接入时在归档里**实测核实**过的事实，以及尚未定标、需要在跑数据中
迭代的判据。样本：GRID-04 2022-03-11、GRID-03B 2023-08-12、GRID-07 2024-03-15，
及各星各年的抽查。归档自带的两份《GRID科学数据说明》docx 都是 0 字节，格式全靠
读文件本身。

## 已核实（2026-09-05）

**归档布局。** `/gecamfs/Exchange/GSDC/missions/GRID/{GRID-02,GRID-03B,GRID-04,GRID-07}/`，
866 GB、16 万个文件。每星四个产品目录：

| 目录 | 内容 | 用途 |
|---|---|---|
| `fits7/YYYY/MM/DD/evt_vXX_YY/` | 逐过境事例文件 `Gxx_evt_YYMMDDhhmm_YYMMDDhhmm_vXX_YY.fits` | **搜索输入** |
| `fits8/YYYY/MM/DD/posatt_vXX_YY_ZZ/` | 同一批过境的 1 Hz 位姿，文件名时间段与事例文件一一对应（三天抽查 52 次过境全部配上且盖住 GTI） | 定位、姿态 |
| `fits5/NNNNN_YYMMDD_vXX_YY/` | 逐过境遥测监视（SiPM 电压、温度） | 不用 |
| `fits3/` | 观测计划 | 不用 |
| `source_orbit/` | STK 导出的 10 s 星下点表 | 只到 2023 年，不用 |

小写的 `grid-03b/ grid-04/ grid-07/`（2025-06）各只有 2 个子目录，是零星补交，未接入。

**观测日与曝光。** 事例产品的天数：GRID-02 75（2020-11-14..2021-03-08）、GRID-03B 789
（2022-03-11..2024-08-01）、GRID-04 527（2022-03-11..2024-08-22，2023-03..12 缺）、
GRID-07 195（2024-01-01..07-22）。**天格是逐过境记录的**：一天 1–21 次过境、每次
10–25 分钟，一天合计 0.5–10 小时（抽查 2023-01-01 0.49 h、2023-08-12 6.96 h、
2024-03-15 10.64 h）。多数小时没有文件，账本里记 `missing_data`、曝光为零；有文件
的小时曝光按 GTI 算。

**版本目录。** 一天常有多个 `evt_v*`，高版本过境更全（2023-08-12 的 `v03_00` 只有
1 次过境，`v03_01` 有 21 次；2023-06-06 是 6 对 16）。逐日最高版本全是 `v03_xx`
（没有一天以 v02 为最高）。归档自带的 `latest_evt.csv` 过时：GRID-03B 列 763 天而
实际 789 天，GRID-04 列 313 天而实际 527 天，GRID-07 没有这个文件。所以取字典序
最大的目录，不用 csv。

**事例文件结构。** `EBOUNDS`（97 道，GRID-02 是 98 道）、`GTI`（一行：本次过境起止）、
`EVENTS0..3`（4 个探测器）：`TIME`(D, s)、`PI`(I)、`DEAD_TIME`(B, µs，恒为 15)、
`EVT_TYPE`(B)。三天 52 个文件：探测器内时间零回跳、过境之间零重叠、事例全在 GTI 内。

**⚠️ 2026-09-11 更正（grid07，全任务实测）：「过境之间零重叠」不成立。**
逐星统计相邻 GTI 段的重叠：**GRID-07 3774 段里有 53 对重叠**（占相邻对的 1.48%），重叠
总时长 1150.1 s = **GTI 总时长的 0.0245%**，最大一对 44.8 s（2024-03-18）；**GRID-02
903 段里 8 对**，173.2 s = **0.0136%**。三天抽查看不到，是因为发生率只有 1.5%。
**量级可以忽略，但这个断言不能留着**：照它写的代码（例如「段不重叠所以曝光可以逐文件直接
累加」）会静默重复计数重叠区，且重叠区的事例若在两个文件里都出现，该处速率会被加倍。
**可忽略的量和错误的断言不是一回事。**
（对账：只读 GTI 的统计给出 GRID-07 合计 **1305.1 h**，与本文档记录的 1305.1 h 逐位相同。）


**时间基准。** 头里 `DATE_REF = '2018-01-01T00:00:00.000'`，`TIME` 即自此起的秒数。
对账：`TIME = 132217726.086` ↔ `DATE_OBS = '2022-03-11T07:08:46.083'`，按 UTC 直接数
1530 天 + 25726 s = 132217726 s，完全一致；2017 年后无新闰秒。

**能道。** v03 是 97 道、5–2052 keV，对数分布（ch1 = 5–9，ch10 = 43–47，ch20 = 107–114，
ch50 = 421–436，ch97 = 1989–2052 keV）；GRID-02 是 98 道、7–2011 keV，同一道号差几个
keV；v02 产品是 200 道，但没有一天以它为最高版本。**阈值按能量定，不按道号。**
实测 v03 的谱从 ch5–7（21–29 keV）才起、ch12（56 keV）达峰，低端没有 GRM 那种噪声
堆，硬件阈值本身就切在 30 keV 附近。

**`EVT_TYPE`。** 实测只有 1 和 2：2 的 `PI` 恒等于最高道 97（中位=p10=p90=97），是
溢出/饱和一类的标记；GRID-03B 一天 6224 个（0.01%），GRID-07 一天 244 万个（4.6%），
且成簇（10 µs 内相邻的占 1.4%）。3 从未出现。`keep()` 只收 1。

**位姿。** `ORBIT_ATTITUDE` 1 Hz：`Q1..Q4`、角速度、`ATT_TYPE`、J2000/WGS84 坐标、
`Latitude/Longitude/Altitude(m)`、`POS_TYPE`。**位置并不总有**：抽查 32 天，
GRID-02 全程、GRID-03B 到 2024-01、GRID-04 到 2024-01 有位置（`POS_TYPE` 1/2）；
**GRID-03B 2024-04、GRID-04 2024-03/05、GRID-07 2024 年除 01-25 外全部 `POS_TYPE=0`，
经纬度和两套坐标全是 NaN，只剩四元数**。`source_orbit` 也不覆盖 2024 年。这些时段
的候选定不了位，只能丢并计数。

**计数率。** 单探测器约 400 c/s，四路合计约 1700 c/s，`DEAD_TIME` 15 µs/事例约合
0.65% 死时间。

**首次真实数据运行（2026-09-05，四星各一天）。** 账本曝光与归档 GTI 合计逐秒相等
（四天差值全为 0.0 s），没有过境的小时记 `missing_data`，GRID-07 的候选全部落入
`dropped_no_ephemeris`（位姿无位置解，符合预期）。但候选数荒谬：GRID-03B 一天 9213 个
（4776 个 fa≤1e-5，最亮 count=351 对 mean=37、fa=1e-199），GRID-07 28624 个，GRID-02
1641 个，GRID-04 455 个——且 99.6% 落在 |lat| ≥ 40°。

**根因：高计数率下读出成帧丢数。** 最亮候选周围 ±30 ms、1 ms 分格的四路计数长这样：

    0 0 0 0 0 0 0 0 0 27 78 52 79 64 0 0 0 17 80 69 74 60 0 0 0 0 0 0 0 0 67 73 71 88 ...

5–16 ms 的密集帧，帧间 3–12 ms 一个事例都没有，四个探测器同步。搜索窗落在帧内，
本底窗横跨帧与空洞，均值被拉低，帧内的普通计数就成了"暴发"。逐秒统计空洞占比
（四路合计连续 3 ms 无事例）对计数率：2–15 kc/s 的秒空洞占比中位 0.0–0.7%，到
辐射带（|lat| > 40°，5–75 kc/s）才成片出现；三天全部候选所在的秒率中位 5–75 kc/s、
空洞占比 40–80%，**率 < 3 kc/s 且无空洞的秒里一个候选都没有**。成帧的起始速率
各星不同：03B 到 15 kc/s 还干净，02 和 04 在 5 kc/s 附近就开始丢。（注意 3 ms
这个空洞定义在 < 1 kc/s 时没有意义——那里 Poisson 本身的间隔就常超过 3 ms，
表里低速率档的"空洞"是统计涨落，不是丢数。）

据此加了**读出空洞否决**（`search.rs` 的 `has_dead_gap`）：候选的本底窗
（±0.5 s，夹在所在 GTI 段内）里最长空段 L 在本地速率 r 下应有的计数 r·L 超过门槛
就否决，计入 `dropped_dead_gap`。

**全量首跑（1586 天）之后又收紧了两处。** 首跑用 r·L > 14（P < 1e-6）、r 取窗内
速率：03B 仍剩 19346 个候选、638 个显著，一半在 |lat| ≥ 40°，最亮的在 13–17 kc/s
的辐射带里——那里的形态是四路同时一个 1 ms 尖峰（86 个对本底 4/ms）后跟几毫秒
稀疏，四路合并后最长空段只有 0.6 ms，空洞判据抓不到；GRID-04 还有 count=8、
mean=0.00、窗内速率 2 c/s 的"候选"——成片丢数里的孤帧，窗内速率本身被压没了，
r·L 永远到不了门槛。改成：(1) r 取窗内速率与整次过境速率中的大者；(2) 门槛降到
r·L > 9.2（P < 1e-4，1 kc/s 时误否决期望约 1%）；(3) 再加一道**读出可信速率上限
5 kc/s**（`RATE_CEILING`，窗内与过境速率取大者）——各星成帧起始速率不同但都不低于
这个量级，而按首跑结果这道门对 |lat| < 40° 的显著候选一个不砍（03B 277/277），
砍掉的只有辐射带。计入 `dropped_high_rate`。

## 未决项

### 1. 低能阈 30 keV：阈本身没问题，但低能端的**配置在任务期内变过**（2026-09-10 更新）

取在硬件截止之上，等于"不额外砍"。是否需要更高的阈来压本底、或者更低的阈来保
灵敏度，要等第一批候选出来看窗内能谱再定。四颗星、两种道数方案都用能量阈，
跨星一致。实测这个阈没有砍掉暴发的东西：29 个短硬暴的核心事例只有 3.6% 低于 50 keV
（7 个闪电认证 2.4%），把阈从 30 抬到 50 keV 只拿掉 2%–4% 的暴内计数。

**但 30 keV 以下那一段收不收，两颗星都在任务期内变过**（全量实测，f = `EVT_TYPE==1`
里落在 E_MIN < 30 keV 的道的占比）：

- **GRID-03B 有一个干净台阶，落在 2023-03 月内**。逐月 f 中位：2022-04 0.652（峰 ch3）、
  2022-12 0.473（ch7）、2023-02 0.500（ch7）→ **2023-04 起恒为 0.0004–0.0020，峰稳定在
  ch12–13**。按速率分层确认不是速率造成的（2022 的 <600/600–3k/3k–20k c/s 是
  0.044/0.234/0.893，2023 是 0.0009/0.0007/0.198）。788 天、1529 次过境。
- **GRID-02 是渐进切换，不是台阶**。逐月 f 中位：2020-11 0.0862 → 2020-12 0.0581 →
  2021-01 0.0267 → 2021-02 0.0007 → 2021-03 0.0000；147 次过境的 f 直方是"一个 f≈0 的
  尖峰 + 一个 0.04–0.09 的宽包"，像两档配置在过境之间切换，低档占比从 1/24 涨到 10/10。
  **谱峰始终在 ch12（56 keV），147 次里 146 次如此**——变的是 30 keV 以下那一段，不是
  整体增益。
- **GRID-04 也变过**：2022-04..2023-02 的 f 是 0.20–0.59（峰 ch5–8），2024-01 起
  0.0002–0.0006（峰 ch12）。它的高能端满量程堆积包是 2022-03..06 有、2022-07 起消失
  ——**两头的时间对不上，是两次独立的改动。**

**教训：跨星比低能端必须同时按速率和纪元分层。** 三个成员先前给出的 0.07% / 3.09% /
23.6% / 3.24% 全部作废——它们分别是台阶后单过境、纪元混合、台阶前中速率过境、纪元混合
四种取样，没有一个代表全任务。**成因（阈值调整还是读出配置）三颗星都没确认，要天格
团队的配置记录。**

**对搜索没有影响**：30 keV 软阈把这些全切掉了，台阶前后进搜索的事例流口径一致，`keep`
之后的率在全任务里稳定。**对跨年谱比较有影响**，做之前必须先处理这条。

### 2. `EVT_TYPE = 2` 的语义未确认

`PI` 恒为最高道，形态像溢出/饱和标记，且成簇——GRID-07 上占 4.6%，明显多于
03B 的 0.01%，可能与该星的高压或阈值设置有关。目前当作非光子丢弃；若它其实是
"高于量程的真光子"，TGF 的硬谱正好会落进去，那就丢错了。要从天格团队拿定义。

**2026-09-11（grid07）：`EVT_TYPE == 2` 不是带电粒子符合的标记——这一半解决了。**
按时戳精确分簇后量它在**多重同戳簇**里的占比与在**单事例帧**里的占比之比：GRID-07 一次
典型过境是 **0.0094 对 0.0127，富集 0.7 倍**；在 type2 占 22.6% 的那次过境里是 **0.2176
对 0.2261，富集 1.0 倍**。低速率安静过境里富集 3.6–4.2 倍，但绝对量极小（单事例帧里本身
只有 1.2%–1.5%）。**所以「它是贯穿粒子在各探头留下的溢出标记」这个可能性被排除。**

**另一半仍未解决**：它会不会是**高于量程的真光子**（TGF 硬谱正好会落进去）。这一半仍需
天格团队的定义，不能从数据自证。

**一条口径，写在这里免得反复搞错**：**帧是硬件对象，任何被记录下来的事例都占了一个帧槽**，
不管 `EVT_TYPE` 是几、能量多低。所以**数帧、数同戳、算读出参数要用 raw 流**，`Event::keep`
只用于搜索量。实测三档并排（raw / type1 / keep），keep 只改 `joined/帧` 3%–24%，
**改不出量级**——但口径混用（一边 raw 一边 keep）会。


### 3. 2024 年大半时段没有位置解

`POS_TYPE = 0` 的过境搜出的候选全部落入 `dropped_no_ephemeris`。这不是几个小时，
是 03B/04 的 2024-02-09 起、07 的 2024-02-10 起到各自数据结束（2024-07/08）——约五百个
观测日，v8 全量丢了 484/146/135 个候选。归档里没有 TLE，`source_orbit` 的 STK 表止于
2023-12，用户也拿不到别的数据。

**已做（2026-09-06）：从数据本身把轨道找回来。** 三颗星都是太阳同步圆轨道（03B：
倾角 97.36°、升交点地方时 22.48 h、周期 5688 s、高度 508.6 km，连续三天一致），轨道面
由此固定；缺的只是每天的沿轨相位。本底计数率随偶极磁纬陡变（|磁纬| 40° 以上升 4 倍，
SAA 另有特征），`scripts/cluster/grid_orbit_fit.py` 用有位置解的日子定标"率–磁纬"模板，
再对无位置解的日子只用计数率拟合相位与周期（周期以前一天为先验，随阻力慢慢变短）。
方法细节与验证（2026-09-06 定稿）：

- 轨道面：倾角与升交点赤经从位姿的 J2000 矢量（角动量）定。**赤经按时间做多项式**（J2 进动
  近似匀速：03B 实测 +0.997°/天、J2 理论 +1.005°/天，223 天残差 rms 0.003°；07 用任务组 2023
  年的 STK 星历加 2024-01/02 位姿，281 天，+0.998°/天）。早先对"升交点地方时"拟合把太阳时差
  （一年 ±16 min 的季节摆动）也拟了进去，长基线残差 7 min，外推后横轨误差以几 km/天增长。
- 相位：每天用计数率拟合。周期不逐日放开（放开 ±24 s 时相位逐日游走 300–500 s，半年下来
  1/3 的天不自洽），而由最近 20 个接受日的升交点历元对圈数做局部多项式给定；相位只在预测
  ±150 s 内找（模板南北近似对称，放宽会翻到半圈对面）；偏离预测超 120 s 或 loss 超自适应
  门槛的天不接受、不写表（候选按无星历丢，不造假位置），模型继续外推；连续被拒时窗口逐步放宽
  到 600 s 并放开周期重新捕获（2024-04/05 的磁暴让周期几天内掉好几秒，局部模型跟不上）。最后
  再用前后 15 天的局部多项式平滑一遍（全程一条二次曲线会把磁暴前后的天全当离群剔掉）。
- 验证（三周外推，逐日，含平滑）：03B 01-17→02-08 误差中位 47–139 km、最大 ≤ 260 km；07
  01-17→02-04 44–80 km、最大 ≤ 203 km；沿轨相位差 ≤ 16 s，横轨稳定在 37–47 km、不随时间增长。**07 的 02-08/09 位姿本身
  不可信**：那两天计数率 8 kc/s 的峰落在位姿给的磁纬 35–39° 处（正常日同处 500–700 c/s，
  8 kc/s 只出现在磁纬 ≥ 60° 的辐射带），位姿比真实位置错了约 380 s，正是丢位置解前的最后
  两天；拟合与计数率自洽，判定拟合对、位姿错。
- 覆盖（2026-09-06 生产）：03B 158 个无位置日里 84 天有表、04 176 里 62、07 161 里 73。2–4 月
  每月 20–30 天，5 月起稀疏（2024-05 磁暴让周期几天内掉好几秒，跟踪器失锁后重捕获不稳，
  孤立的重捕获不留）。没有表的天候选照旧按无星历丢，账在 `dropped_no_ephemeris`。
- 产物：每次过境 10 s 一行的 `orbit_fit/<星>/<YYYYMMDD>.csv`，Rust 侧位姿无位置解时退回它
  （`io::orbit_fit`，`GRID_ORBIT_FIT_DIR`），计入 `positions_from_orbit_fit`；`smooth_log.csv`
  记每天的 loss、残差、是否保留。工具：`scripts/cluster/grid_orbit_fit.py`（calib / validate /
  validate-range / fit-range / smooth）。
在那之前这些时段只能做判选 A 层、不能做闪电关联。

**2026-09-11（grid07）：天格四颗 POSATT 没有 GECAM 那种坏行。** 地心距落在物理 LEO 带
[6600, 7100] km 外的行：**07 = 0、03B = 0、04 = 0、02 = 0**（各抽 30–38 天、16–33 万行）；
半径直方每 5 km 分格后为**单一连通带、无孤岛**。四星各自的带与高度中位：
07 = 6804.9–6832.7 km（443.9 km）、02 = 6834.1–6861.6（474.7）、
03B = 6836.2–6935.4（516.1）、04 = 6834.9–6934.6（532.8）。

**⚠️ 一个反向的坑，比 GECAM 那个更隐蔽，全队适用：过滤不能用「中位 ± 几十 km」。**
天格的地心距因真实偏心率与高度衰减**连续铺开约 100 km**，而**半径与纬度通过近地点幅角
相关**，所以窄带会**优先切掉真实的高纬行**。实测：按「中位 ± 30 km」过滤会切掉 GRID-03B /
GRID-04 各 **23%** 的行，并造出「03B 高纬曝光只有 8.3%」的假象（正确值约 19%）。

### 9. 读出空洞的正解是当作 GTI 缺口

现在的否决只是把落在成帧区的候选丢掉。正解是把空洞当活时间缺口、让本底按真实
活时间归一，那样帧内的计数会对帧内的速率做检验，辐射带里的数据也能搜。但
`search_new` 的活时间原先夹到候选所在的一段 GTI（假设它覆盖整个本底窗），毫秒级
的洞会把本底窗夹到一帧里、统计反而更差。**核心已改成对多段求交集之和（2026-09-06，
`live_length`）**：窗口跨过比自己短的缺口时两侧都算活时间、缺口不算，与窗内计数同
口径；只与一段相交时和原先逐位相同（GRID 4 天、SVOM 1 天、HXMT 1 天逐字节回归全同）。

**2026-09-11（grid07）：`live_length` 已在真实候选上实测确认，不是只靠注释。**
放开 fa 门查 GRID-07 全部 122 个候选：**120 个的 ±0.5 s 本底窗完整落在所在 GTI 段内**，
**2 个恰好坐在段尾**（距段尾 0.2 s 与 0.0 s，相邻段在 17 s 外）——这两个是检验活时间分母的
天然样本：报的 `mean/bsb` 对「按活时间算的真实速率」是 **0.992 / 0.998**，而对「用标称窗宽」
是 0.577 / 0.645（差 35%–42%）⇒ 分母确实按多段交集之和算。这两个候选的 fa 是
**3.23 和 7.89**（连 fa ≤ 1 都不到），**没有被 λ 低估抬进目录**——这是「不该变的没变」那一侧。

**「内部缺口」那一类也做完了**——天格特有的成帧丢数（3–12 ms 无事例，**GTI 里不标注**）。
口径：**搜索报的 `mean` ÷ 自己重算的本底率**，偏离 1 才算 λ 被低估。GRID-07 全部 17 个
显著候选：**中位 0.9637、四分位 0.9565–0.9722、全距 0.9148–0.9825、偏离 1 超过 10% 的 0 个。**
那 3.6% 的系统性偏低是重算口径造成的、不是 λ 的问题：重算时用了整个 ±0.5 s 窗、**没有挖掉
暴本身**，暴的净超出（中位 47 个计数）被算进「本底」，把分母抬高 1%–9%。**若 λ 真被内部
缺口低估，比值会是几十个百分点级的偏离，而不是四分位只有 1.6% 宽的窄分布。⇒ 这一类也排除。**

**天格不适用 HXMT 那个同义反复**：HXMT 的「距整点 < 1 s 的候选 9/9 都有大缺口」是**构造
决定的**（本底窗被夹到 chunk 边界）。天格 17 个显著候选**最小余量 35.4 s = 本底窗半宽的
70 倍**、最近相邻段 1340 s 外，**一个都不靠近边界**。

把成帧丢数的空洞探测成 GTI 缺口、替代 `has_dead_gap` 否决，现在可以做了，但辐射带
不是 TGF 的地方，收益只是账面曝光，留作以后。

### 13. 姿态解整段缺失：已把姿态改成可选（2026-09-06 定）

### 14. 分群判据重做：旧的"窗长 < 500 µs"作废（2026-09-10）

**旧判据错在哪。** v3–v10 一直按 `bin_size_best`（搜索窗长）500 µs 把 80 个显著候选

显著（净超出中位 47 个计数），但谱与本底一致、时长约 3 ms、集中在高磁纬、零闪电

**B 角的"与本底同谱"是测出来的，不是没功效。** 逐候选对暴内事例有放回自举，硬度的

**"若 B 角是 TGF"的期望关联数。** 按 A 角 7/28 = 25% 的关联率直接外推，40 个应有

那里闪电本身少、WWLLN 探测效率也更低，同一个 TGF 在 B 角位置上被关联到的概率必然
低于 A 角，所以真实期望小于 10 个。40 个全在 WWLLN 覆盖期内，逐候选的偶然符合概率
合计 0.00。

**B 角是什么：GECAM-C 上的同型事件出现在带电粒子沉降环境里（2026-09-10）。** GECAM-C
17 天、61558 个候选里按天格 B 角的形态逐层筛：

口径（GECAM 侧 2026-09-11 核定，照此引用）：GECAM-C 17 天（2023-01-06 .. 2023-12-08）、

0.1%，可忽略但要带着这个限定）。三个筛选条件一个都没用到 CPD，构造上无循环。

**而且它是连续的，不是孤立人群。** 固定 |mlat| ≥ 33 做亮度扫描，**CPD 本底率**随计数

中位 53、5% 分位 18，落在 30–60 与 60+ 两档，**所以这个答案对天格 B 角有效**。

四条边界必须一起记：

- **任何未归一化的 CPD 命中率都不含信息，整类作废**（2026-09-11 由 GECAM 侧撤回，包括
  他们自己文档里亮度扫描表的"CPD 命中"一列）。先撤的是"±10 µs 符合命中率 93%"：那批的
  窗长顶到 1 ms、所在处 CPD 率 2557–3131 c/s，偶然撞上至少一个 CPD 计数的期望本来就是
  92.6%–95.6%，**观测/期望 ≈ 1.0，超出为零**。**上表 85.6% 同理**：该层 CPD 率中位
  3205 c/s、窗长约 1 ms，纯本底下 μ ≈ 3.2、P(≥1) ≈ 96%——**实测 85.6% 比偶然期望还低**，
  所以"85.6% 对基准 12.4%"这个对比是假的，两边的窗长与本底率差着一到两个数量级，比的
  不是同一个量。**立论只能立在环境率上。**
- **CPD 的绝对命中率不可信。** GECAM-C 只有 2 路 CPD 对 12 路 GRD，实测粒子标记效率
  约 14%——约 86% 的粒子 CPD 认不出来。这些数只在相对比较里有意义，**别读成高确定性
  的判决**。
- **只对亮端成立。** 暗端（8–15 计数）的 CPD 率 134–135 c/s、与全样本基准 117 c/s 无异，
  这项测量给不出判决。**B 角若往暗端扩，扩出来的部分不能沿用这个结论。**
- **那几层"闪电关联 0 个（期望 0.0）"不要引**：期望本来就是 0.0，**0 对 0.0 不含信息**。
- **高磁纬不是这个形态的必要条件。** GECAM 的低磁纬对照（计数 ≥ 20 且 |mlat| < 33°）
  也有 50.7% 的 CPD 命中率，只是数量少（73 个对 507 个）——高磁纬处粒子多，所以样本
  多，但同类事件在低磁纬也出现。**对天格的 B 角定义没有影响**：天格里 T90 ≥ 2 ms 且
  |mlat| < 33° 的候选**一个都没有**（40 个长候选的 |mlat| 最小值是 33.3°），所以那道
  磁纬线是在描述数据里已有的空隙，不是在排除一类事件。但**若以后有长而低磁纬的候选
  出现，不能因为它不在 B 角就当成新东西。**

**"B 角是慢读出星特有伪信号"这条解释没有排除，只是不再是唯一解释**（2026-09-11 收回
先前"已排除"的说法）。GECAM-C 的探测器材料（LaBr₃ 对 GAGG）、读出、死时间与天格完全
无关，同形态照样出现——这证明**这个形态本身不必然是慢读出造成的**，但它证明不了天格
B 角那 40 个就是 GECAM 看到的那类东西，而不是天格自己的读出假象。两者在天格数据里
分不开：B 角 40 个里 39 个来自共帧星，03B 上只有 1 个，**没有可用的对照组**。未决项 18
的 CoV 也卡在同一个混淆项上（共帧读出会把高占用率窗里的事例挤到帧边界、机械地压低
CoV，而"亮而短"正是这种窗）。

**所以对外的说法是**：另外三颗星的 40 个候选在计数上确实显著（净超出中位 47 个计数、
过的是 fa ≤ 1e-5 的门），但能谱与本底一致、时长约 3 ms、集中在 |偶极磁纬| ≥ 33°、零
闪电关联，不符合 TGF 的任何一条特征，而且它们几乎不出现在 03B 上；**这三颗星的探头
共帧读出，因此我们无法区分"它们是一类高磁纬的非 TGF 事件"和"它们是慢读出星特有的
伪信号"**。**不要把它们写成"本底涨落"**——与本底一致的是**能谱**，不是**计数**。

**天格自己也有一条判定性的独立证据：B 角的候选是一列，不是一个。** 在候选前后 ±30 s
里按 3 ms 分格、本底取 ±1 s 局部均值，数除自己以外逐格泊松 p < 10⁻⁴ 的尖峰：

| | 个数 | 其他尖峰／分钟（中位） | 有 ≥1 个 | 尖峰总数 |
|---|---|---|---|---|
| GRID-07 的 17 个 B 角候选 | 17 | **182.0**（10–508） | 17/17 | 3308 |
| GRID-03B 的 29 个短硬暴 | 29 | **4.0** | 25/29 | 103 |

纯泊松在该本底下每分钟只该给约 2 个假尖峰（1500 c/s、3 ms 格 µ = 4.5、60 s 里 2 万格
× 10⁻⁴），182 超出约 90 倍，是真实成团。**TGF 是孤立事件；B 角的每一个都坐在一串同类
毫秒尖峰的中间，搜索挑出来的只是那串里最显著的一格。** 加上高磁纬集中不是曝光选择效应
（GRID-07 可定位曝光里 |磁纬| > 40° 只占 23.4%，而 16/17 在 > 40°，期望 4.0、
**P = 1.1×10⁻⁹**；且高磁纬本底更高、探测更难不是更容易），定性为**磁层沉降电子微暴**。

**⚠️ 2026-09-11 撤回（grid07）：上面「182 个尖峰/分钟对纯泊松期望约 2 个、超出约 90 倍」
这个比较作废，由它得出的「TGF 是孤立事件；B 角的每一个都坐在一串同类毫秒尖峰的中间」
也一并撤回。**

**错在零假设，不在判别量。** 纯泊松不是正确的零假设——**高磁纬本底本身就不是泊松的**，
本文档未决项 18 自己实测到天格本底窗 CoV 中位 1.88、GRID-07 是 **2.84**。所以「比泊松多
90 倍」量的是**本底的非泊松性**，不是候选的性质。

**换成配对对照后超出就没了。** 对 GRID-07 的 17 个显著候选，每个配 6 个**同磁纬带
（|mlat| 相差 < 5°）、同一次过境内的随机时刻**，走**完全相同**的量法（±30 s、3 ms 分格、
±1 s 滑动局部本底、逐格泊松 p < 10⁻⁴）：**候选处中位 522.0 个/分钟（四分位 171–915）、
同带随机时刻中位 343.0（四分位 3–889）；候选/对照中位 1.52，候选 > 对照的只有 10/17
——符号检验单侧 p = 0.315，不显著。** 有四个候选的对照比候选本身高一个数量级
（8 对 343、171 对 1537、144 对 2128、228 对 612）。

**改写为**：**B 角候选所在时段的毫秒尖峰率与同磁纬带随机时段不可区分；两者都远高于泊松
期望，说明这是高磁纬本底本身的性质。这条量不能用来区分 B 角候选与其所在环境。**
方向仍与「磁层沉降电子微暴」自洽，但**它不再是独立于「高磁纬」的新信息**。

**`grid04` 在 GRID-04 上报的「522.5 个/分钟对纯泊松 1.23、超出 425 倍」用的是同一个零假设
——两星「独立复现」复现的是同一个零假设错误，不是同一个事实。**

**偏差方向，以及一条结构性限制。** 对照时刻可能落进候选自己那一串里，这会**抬高对照、
让结论偏向「不显著」**。想用「对照离任何候选 > 300 s」排掉它，**实测不可行**：天格一次过境
只有 10–25 分钟，而卫星扫过一个 5° 宽的磁纬带只需几分钟，**「同过境 + 同磁纬带」的对照在
时间上必然靠近候选**——加 300 s 间隔后 10 个候选里有 8 个一个合格对照都找不到。
**这不是抽样运气，是轨道几何决定的；干净对照必须取自其他过境**（未做，记为待办）。
两条理由说明结论仍稳：**符号检验对幅度不敏感**（10/17）；`grid04` 用**速率匹配**这套完全
不同的对照得到同向结果（**候选处反而更低，454 对 1890**），且它那套没有时间邻近问题。

**一条不依赖 CPD 的外部参照，但两边不是同一把尺子。** 已发表的 GECAM-B TGF 目录

**必须先说清楚尺子不同**：他们的 `Duration_us` 是 **Bayesian Block** 的块长，不是 T90，
两个量在低计数下的偏差机制也不同（BB 会把整块并成一块，T90 被首末事例夹住）。所以：

- **可以用来否定 B 角**：B 角 T90 中位 2963 µs、净超出中位 47 个计数，亮度与他们的
  `NetCounts` 中位 66.9 同量级，而时长是他们最大值的 4.4 倍——两把尺子的差别撑不起
  4.4 倍。B 角在这 147 个真 TGF 里没有对应物。
- **不能用来肯定 A 角**。A 角 T90 中位 533 µs 已在他们的 95% 分位（372 µs）之上，而且
  **A 角的净超出中位只有 9.9 个计数，他们是 66.9**——差 7 倍，尺子和亮度两条都不可比。
  在做完"把他们的暴降采样到 10 个计数、再用我们自己的 T90 定义重量一遍"这个检验之前，
  **不要写"天格 A 角的时长与已发表 TGF 一致"**，也不要写"天格 A 角比已发表 TGF 长"。

**谱硬度在低计数下不能用作逐候选的判据。** 零假设（暴内谱与本底相同）下，从本底能谱
里抽同样多的事例算硬度，95% 分位随计数急剧变化：

| 26–60（30 个） | 1.43 | 1.04 |
| 61–200（11 个） | 1.23 | 0.92 |

零假设的中位数在各档都是 1.00，没有小样本偏置——**低计数处的问题是散布，不是偏移**。

**把富集定量归因到噪声**（`null_p_at_1p6` = 零假设下硬度越过 1.6 的概率，对全表求和）：

| T90 内事例数 | 实测硬度 ≥ 1.6 | 该档候选数 | 纯噪声期望个数 |
|---|---|---|---|

**所以这一刀不是纯噪声**：实测 39 个超阈，纯噪声只解释得掉 7.6 个（19%）。但**在低计数档
里每四个"硬"候选就有一个是噪声**（7–9 计数档 14 个超阈、噪声期望 3.5），而且判据在两个
方向上都会出错。最直接的反证是**7 个闪电证实的真 TGF 里有 3 个的硬度在统计上不显著**
（单侧 p = 0.235 / 0.109 / 0.082）——判据连已知真值都认不出来，就不该拿它逐个切别人。

结论：**硬度可以在群一级用**（A 角合并 p = 4.7×10⁻⁴³），**逐候选用不行**；真要逐候选
用，必须带自举区间和零假设分位一起报。`t90_v15.csv` 里 `hard_e_lo/hi/hard_e_95`、
`null_p50/null_p95/null_p/null_p_at_1p6`、`ks_p` 就是为这件事留的。

（方法上照 SVOM 那边否决同戳判据的三条：(a) 拿真值扫阈值、(b) 把富集定量归因到噪声、
(c) 确认真值与其余候选在该量上重合。上面 (a)(b) 都做了；(c) 在天格不成立——真值确实
比其余候选硬，所以天格是"**群一级可用、逐候选不可用**"，不是 SVOM 那种"整个判死"。）

**A 角里还混着带电粒子，用 f₃ 挑得出来。** 现行的同戳判据只数"最长的一串"，拦不住
"几百微秒里重复出现 2–4 次三重同戳"这种形态（每一串都不到 0.35）。加一个 f₃ = 落在任意
≥3 重同戳簇里的计数占比（03B 的 38 个显著候选，从暴内事例流算）：

| | f₃ > 0 | f₃ ≥ 0.5 |
|---|---|---|
| A 角（28 个，全是 03B） | 8 | 4 |
| 中间带里的 03B（9 个） | 4 | 4 |
| **7 个闪电证实** | **0** | **0** |
| 本底对照（17500 次抽样） | 7.0% | — |

**7 个闪电证实的 f₃ 全是 0，一个例外都没有**——这个量不误伤真 TGF。去掉 f₃ > 0 之后
A 角剩 20 个干净的（T90 中位 612 µs、硬度中位 3.57、7 个闪电证实全在里面）。f₃ 只用作
**污染标记**不用作分群轴：另外三星是共帧读出，时戳本来就塌在帧上，f₃ 在那里含义不同，
要单独论证。

**f₃ 的富集不是偶然符合**（三步法的第 (b) 步，`diag/lead/` 逐候选算）。n 个事例散在
时长 T 上、量化步 q 时，二重同戳的偶然期望是 (n−1)·q/T，**三重是它的平方量级**——
`Σ_{k≥3} k·m·C(n,k)p^k(1−p)^{n−k} / n`，`m = T/q`、`p = 1/m`：

| | 偶然期望 | 实测 | 实测 / 偶然 |
|---|---|---|---|
| f₂（≥2 重） | 中位 0.0113 | 中位 0.427 | 24× |
| **f₃（≥3 重）** | **中位 5.6×10⁻⁵、最大 2.1×10⁻³** | 非零的 12/38，中位 0.33 | **最小 1.1×10⁴、中位 7.2×10⁴** |

**f₃ 的富集比偶然高四到五个数量级**，不可能是量化偶然造出来的。7 个闪电证实的 f₃ 偶然
期望在 1×10⁻⁴–2×10⁻³ 之间，实测全 0——完全符合偶然，即"它们确实没有三重同戳"。这就是
现行判据（"最长的一串"）为什么会漏掉那批粒子：**它们是几百微秒里重复 2–4 次三四路同戳，
不是一次大同戳，最长串除以总计数当然过不了 0.35**。"最长的一串"这个统计量对**重复发生**
的粒子事件天然失明，f₃ 不失明，而且三重的偶然基底被平方压掉了，不会像 f₂ 那样被偶然
符合淹掉。

**污染范围**：29 个短硬暴里有 6 个 f₃ > 0（2022-11-28、2023-03-30、2023-06-02、
2023-06-22、2023-07-04、2023-11-18），9 个"软暴"里有 4 个——**天格 TGF 样本的六分之一
带粒子签名**。7 个闪电认证不受影响。所以"29 个短硬暴"这个数要改口径，用到它的地方
（讲图、A 角计数、Fisher 检验）都按 f₃ 标记后的干净子集重报。

**谱硬度还受量程上限堆积污染（未决项 15），但 A/B 的谱差别经得起扣。** 把 1.2 MeV 以上
的事例从暴内和本底里同时扣掉再算（`t90_v15.csv` 的 `hardness_e_cut`）：

### 15. 逐探头量程上限：超量程沉积以硬光子身份进了搜索（2026-09-10）

三颗星上分别实测到同一个现象：**每个探头有自己的满量程位置，位置之下有一个堆积包、
之上基本为零**，而 `Event::keep` 只把最高道（`pi >= n_channels`）当溢出道，所以这些
超量程沉积全部以 1.2–1.9 MeV 硬光子的身份进了搜索、也进了谱硬度。

| 星 | 满量程位置（逐探头） | 峰道单道占该探头事例 |
|---|---|---|
| GRID-03B | det3 ch83–85、det0 ch84–87、det1 ch88–93、det2 ch88–94（1.24–1.81 MeV） | 0.01%–7.3% |
| GRID-07 | det0 ≈ ch89、det1 ≈ ch91、det2 ≈ ch95（约 1.5 MeV 起） | 最高 7.1%（det0 ch88） |
| GRID-04（2022 段） | det0 ch90、det1 ch89、det2 ch92、det3 ch90（1.55–1.70 MeV） | 0.31%–0.84% |
| GRID-04（2024 段） | **没有堆积包**，ch90–97 是平的（每道约 0.5%），一直平到 ch97 | — |

三条性质：**位置逐探头不同**、**逐次过境漂移**（03B 同一天两次过境，det1 的 ch86–92
占比从 8.2% 掉到 0.5%；GRID-07 同一探头峰从 ch88 漂到 ch92）、**上限之上陡降**。真伽马
线不会这样，判断是满量程堆积。GRID-04 的 2024 段看着像增益掉了、堆积被推到 ch97 以上
（进溢出道被 `keep` 丢掉），高道剩一条平尾——这也解释了 GRID-04 那 21 个候选的硬度
中位 1.08 不是堆积撑出来的（21 个里 18 个在 2024 段）。

**影响已量化**（见未决项 14 末尾）：扣掉 1.2 MeV 以上后 A 角硬度中位 4.24 → 2.09，逐候选
显著的从 21/28 掉到 11/28。**方向不变，量级要打折。**

**已定（2026-09-10）：`Event::keep` 不改，改成记账。** 理由是**超量程沉积的计数是真的，
只有能量是假的**：`keep()` 的低能阈是 30 keV，超量程事例无论如何都在阈以上，所以**准入
不受影响、搜索的计数不受影响**，受影响的只有谱学量。改 `keep()` 反而会砍掉真实的高能
计数（TGF 是硬谱），代价大于收益。

**记账的内容**：上限之上的能量不可信，**任何谱学分析必须排除上限以上的道**。上限逐探头
不同且随过境漂移，写不成常数；诊断脚本里用保守版——取所有已知上限里最低的那个当统一
截止（`grid_t90.py` 的 `OVER_RANGE_KEV = 1200.0`），产出的 `hardness_e_cut` 是硬度的
**下限**，用来做敏感性检验。要更准就得按探头按过境从数据里估陡降位置，复杂且低计数
过境估不准，暂不做。

**"上限之上是不是零"这个形状判据在暴内给不出信息**（03B 实测，逐候选取所在过境定
"包峰 P"与"上限 R"）：

| | 包内 [P−2, R) | 上限之上 [R, 96] |
|---|---|---|
| 本底（整次过境，38 个的中位） | 7.93% | **0.047%** |
| 暴内（最佳格合计 408 个事例） | **35.0%** | **0.98%** |
| ├ 7 个闪电认证（85 个） | 27.1% | 1.18% |
| └ 9 个软暴（101 个） | 42.6% | 0.99% |

本底里上限之上只有 0.047%，说明上限是真的；**但暴内上限之上也只有 0.98%**——任何真的
> 1.8 MeV 光子本来也只会被记进包里、不会出现在上限之上，所以**没法用形状把"堆积"和
"真高能"分开**。

因此 `hardness_e_cut` 是硬度的**紧下限**，不是修正值：暴内包内占比 35.0% 对本底 7.9%
是 **4.4 倍富集**（7 个闪电认证 27.1%，3.4 倍），而一个 RREA 谱的 TGF 本来就该有四分
之一到三分之一的计数在 1.3 MeV 以上——**这个富集不能当污染证据**。所以结论要写成"硬度
下限"，不能写成"修正后的硬度"；那个扣后掉到 0.87 的闪电认证候选也不代表它变软了。
一个副产品：**包内占比与 f₃ 同向**（包内占比最高的 10 个里 0 个是闪电认证，全是判为

**没验成**：堆积的成因没跟天格团队核实过（缺读出/标定文档）；`EVT_TYPE == 2` 与量程上限
不是同一件事（GRID-07 上 det2 量程最高但 type2 最高、det0 反之）。

**一条没对齐的分歧，记录在案。** 本底谱低能端（< 30 keV 占比）：grid03b 在 03B 24 个
过境上量到安静过境 0.07%、含辐射带过境 9.03%，谱峰在 ch13–14（61–68 keV）；grid02 报
03B 是 23.6%–44.1%、峰在 ch6–7；grid07 先前报 56%–76% 后自行撤回、复核后说安静过境下
07 与 03B 低能端相同、峰都在 ch12–15。差别应该在过境选取（低纬安静 vs 含辐射带），但
**没有对到一起**，而低能端占比直接关系到能阈判据，不能一直挂着。三方要按同一套过境
选取重算一次。目前可确定的是能阈本身不是差别来源：29 个短硬暴的核心事例只有 3.6% 低于
50 keV（7 个闪电认证 2.4%），把阈从 30 抬到 50 keV 只拿掉 2%–4% 的暴内计数。

**跨仪器**：GECAM 的溢出块按 EBOUNDS 里静态的 `ch >= 448` 切，而 GECAM-A 实测
`PI >= 448` 的占比逐日在 0.56%–19.38% 之间摆动且与标定新旧无关——同一个征象，那边已在查。

### 16. 时刻被截断两次、事例准入比搜索松（已修，2026-09-10）

对账口径：候选的最佳格是 `t0 = start + delay`、`t1 = t0 + bin_size_best`，窗内计数
应当等于 `count`（`Candidate::merge` 会把 `stop` 拉长，所以不能拿 `[start, stop]` 对账）。
`grid_features.py` 用的一直是最佳格，但对账只有 6/80 命中。逐步修：

| 版本 | 改动 | `n_core − count` 分布 | 一致 |
|---|---|---|---|
| v10 | 原样 | −4:7, −3:3, −2:5, −1:57, 0:6, +1:1, +2:1 | 6/80 |
| v11 | 修 `met()` 的纳秒→微秒截断 | 0:70, +1:7, +2:2, +3:1 | 70/80 |

**缺陷一：`met()` 把小数秒截到微秒。** 写法是 `(frac + "000000")[:6]`。搜索产物的
时刻带纳秒，候选窗两端都是事例本身的时刻，窗口整体左移不到 1 µs 就把落在窗末端的
那个事例挤出去（同戳的几个一起丢，所以有 −2/−3/−4）。修法是整秒交给 `datetime`、
小数部分按浮点单独加。仓库里 `grid_features.py`、`grid_t90.py`、`grid_profile.py`、
`grid_lightcurve.py`、`grid_gaps.py`、`grid_conserve.py` 六个脚本都有，已全修。

**缺陷二：`grid_features.py` 写 CSV 时把时刻截到毫秒**（`c["start"][:23]`）。这一条
比缺陷一严重三个数量级，而且当时没人注意到：下游 `grid_t90.py` / `grid_profile.py` /
`grid_conserve.py` / `grid_lightcurve.py` / `grid_footpoints.py` 全都从这一列重新定位
窗口，等于 1 ms 的定位误差。实测后果——T90 有 65/80 变了，相对变化中位 0.8%、p90 23%、
最大 +258% 与 −92%；一个候选的谱硬度从 13.00 掉到 1.25。`start` 列现在写全精度；要和
旧表对齐取 `start[:23]` 即可。

**缺陷三：Python 侧只筛 `EVT_TYPE == 1`，比搜索松。** `Event::keep` 还要求道号在
`[1, n_channels)` 内（最高道是溢出道）且该道下限能量 ≥ 30 keV。松了之后窗内计数偏大

中位数**。`grid_features.py`、`grid_t90.py`、`grid_lightcurve.py` 已对齐；
`grid_profile.py`、`grid_conserve.py` 只用计数不用谱，暂未改，用它们的结论时注意口径。

**受影响、需要重跑的下游**：未决项 10 里的足点检验数字、`grid_profile.py` 的宽窗轮廓
（"真实时长 3–4 ms"是从截到毫秒的时刻量的）、`grid_conserve.py` 的守恒检验。T90 与

### 17. 只有 GRID-03B 能探测 TGF：读出差别，不是曝光差别（2026-09-10）

29 个短硬暴与 7 个闪电证实的 TGF 全部来自 GRID-03B，另外三颗一个都没有。**这条反常
已经解释掉了，根因是读出，不是曝光。** 原先的"GRID-04 期望 19.4、实测 0、P = 4×10⁻⁹"
里，19.4 那个期望隐含"两颗星探测能力相同"，而这个前提实测不成立。

**(1) 时戳栅格四星完全相同。** `TIME × 2²²` 的小数部分**严格为 0**（四颗星各取文件、
80 万–250 万事例、零例外；grid07 在 10 过境 × 50 份表上复核，最大残差 0.000e+00）。
tick = 2⁻²² s = 0.238419 µs。这不是 float64 的精度极限：该 MET 量级（0.9–2.0×10⁸ s）
的 ulp 是 2⁻²⁶ 与 2⁻²⁵，栅格比 ulp 粗 16 倍与 8 倍，所以是真的仪器/编码量化。
以前记的"时间戳分辨率 4.77 µs"是错的——那是 03B 的探头死时间（正好 20 个 tick）。

**(2) 探头死时间差 6 倍**：03B 4.7684 µs（20 tick），02/04/07 都是 28.6102 µs
（120 tick），见未决项 6。两个值都精确落在整数 tick 上、比值恰好 1:6，说明它是**以
tick 为单位写进寄存器的配置值**，不是电路固有常数。GRID-04 已扫的 132 天抽样里边沿
一直在 120 tick，没有任何一段被设成 20；03B 三年的半高 tick 集合都是 {20,21}。
逐过境的全量序列在跑，**如果发现某颗星中途改过，结论的性质会从"仪器固有差别"变成
"运行配置差别"**（后者在后续任务里可以改正），所以这条一定要跑完。

**(3) 更要紧的是读出结构不同，不只是死时间数值不同。** 判据是跨探头间隔的分布形态
（GRID-04 2022-04-14 与 GRID-03B 2022-10-04）：

| | GRID-04 | GRID-02 | GRID-03B |
|---|---|---|---|
| 跨探头间隔落在开区间 (0, τ) | 4.3×10⁻⁴（1034/1060 在 tick 119） | **4.8×10⁻⁶**（102/2.11×10⁷） | 34.4%（连续铺满） |
| 四路独立模型的预期 | 5.5×10⁻² —— **差 130 倍** | 1.9×10⁻² —— **差 3900 倍** | 符合 |
| 跨探头 dt == 0 | 3.9×10⁻² | 1.4×10⁻² | 1.4×10⁻² |

GRID-02 那一列还做了算子自检：把共帧算子施加在 **GRID-02 自己的真实本底流**上**近乎

0.14%、改 1.1% 的时戳——**这个算子就是 GRID-02 数据本身的结构，不是拟合出来的。**

每路最多贡献 1 个事例，全帧共用触发那一击的时戳，帧结束才能开下一帧。** GRID-03B 则是

**(11) `MAX_SIMULTANEOUS_FRACTION = 0.35` 在共帧星上测的东西和它以为自己在测的东西
不是一回事。** 这道门建立在"同戳 = 穿星粒子"这个假设上。在 GRID-03B 上假设成立（同一

裕度检验（`diag/lead/simul_margin.py`）：偶然同格占比的期望 ≈ (n−1)·q/T，q = 2⁻²² s。

**当下的风险：这道门在 GRID-03B 上已经没有余量了。** 38 个显著候选的实测同戳占比

### 18. CoV（窗内事例间隔的变异系数）：B 角的窗比自己的本底还规则（2026-09-10）

判别量来自 HXMT：泊松过程 CoV = 1，真暴发成团 CoV > 1，缓冲区顺序倾泻或读出定速的
假信号 CoV < 1（他们实测正常候选 1.52/1.63、开关机假信号 0.76–0.99）。只要候选窗内的
事例时戳，不需要任何仪器专属信息。天格 80 个显著候选各算一遍（`grid_cov.py`，窗取
T90 区间、准入与搜索一致）：

**先说一条会让人读错的：天格的本底本身就不是泊松的。** 本底窗的 CoV 中位是 **1.88**，
逐星 1.59（03B）/ 2.17（04）/ 2.78（02）/ 2.84（07）——**HXMT 那个"泊松 = 1"的绝对基准
在天格不成立**，必须拿每个候选自己的本底窗当参照。归一之后：

| | n | 候选窗 CoV ÷ 自己本底窗 CoV | 四分位 | < 1 的 |
|---|---|---|---|---|
| A 角 | 27 | **1.02** | 0.74–1.34 | 13/27 |
| B 角 | 40 | **0.40** | 0.30–0.56 | **35/40** |
| 7 个闪电证实（未归一） | 7 | CoV 中位 2.23（本底 1.37–1.97） | — | 1/7 |

**B 角的窗比自己的本底规则 2.5 倍**，形态上与 HXMT 那类读出伪信号一致；A 角与自己的
本底一样团。

**但有一个混淆项没法用现有数据排除，写在前面免得被当成结论。** B 角全部来自共帧星，
而共帧读出会把事例挤到帧边界上——**窗内速率越高、帧占用率越高，间隔就越接近帧长的
整数倍，CoV 机械地被压低**。所以 B 角的低 CoV 究竟是"读出伪信号"还是"共帧仪器上任何
一个亮而短的超出都会这样"，分不开。一个反证方向：共帧星的**本底**窗 CoV 反而更高
（2.17–2.84，比 03B 的 1.59 高），说明共帧本身不会一律压低 CoV，压低只发生在高占用率
的窗里——这恰恰又是"亮而短"的定义。**要真正分开，需要在非共帧星上找到 B 角形态的候选
做对照，而 03B 只有 1 个，不够。**

7 个闪电证实里 2022-10-04 的 CoV 是 0.93（本底 1.67，归一 0.56），是唯一一个明显低于
自己本底的——它也是 A 角最亮最短的那个（78.7 µs、21 个计数）。**这说明"亮而短"本身就
会压低 CoV**，与上面那条混淆项同源。**所以 CoV 在天格只能当人群统计，逐候选判不了。**
HXMT 自己也列了这条限制（对照只有 2 个、十几个间隔上标准误约 0.25）。


### 21. 当地太阳时（LST）第二条真值腿：**方法不适用，不是没测到**（2026-09-11，grid07）

**实测（GRID-07，848.8 h 曝光；GRID-02 独立复核，354.6 h）：** 升交点地方时
**LTAN = 22.61 h（07）/ 22.49 h（02）**，环形集中度 **R = 0.9998 / 0.9999**；07 在 195 天内
逐段 22.58 → 22.63 → 22.71 h（**150 天漂 0.13 h**），02 漂 0.02 h。与 GRID-03B 先前记录的
LTAN 22.48 h 同族。

**曝光的 LST 分布（8 格，格心 1.5, 4.5 … 22.5 h）在 |偶极磁纬| < 33° 只落在两个格：**

| 星 | 10.5 h | 22.5 h | 其余六格 | 幅度 A |
|---|---|---|---|---|
| GRID-07 | 51.6% | 48.4% | **恰好 0.000** | **2.062** |
| GRID-02 | 51.1% | 48.9% | **恰好 0.000** | **2.045** |

**A ≈ 2.05 是 8 格分布两格等分时的理论上限**（对照 GBM 陆地模板 A = 0.988、GBM 全体 0.597、
完全均匀 0）——**连「幅度」都不是测出来的，是分格决定的**。这是轨道逼出来的：LST 与轨道相位
一一对应，逐相位八分区的 LST 环形集中度 **R = 0.985–1.000**（升段永远在午夜前后、降段永远在
上午十点半）。

**三条理由要分层写，缺一条都会被误读：**
1. **结构性（绑定约束）**：**六格零曝光**，模板的定义域缺了四分之三，两成分拟合退化成在两个
   点上解两参数。**这不随样本量改善。** 等价的说法（`grid02`，从自由度侧）：**被检验样本的
   地方时只有两个取值 ⇒ 模板拟合无自由度 ⇒ 确定用不了，不是大概率用不了。**
2. **统计性（即使曝光均匀也会失败）**：按 GBM 陆地模板，**N = 17 时期望瑞利 p 中位 0.076、
   58% 的概率给不出 p < 0.05**；N = 28 时中位 0.018。——「没测到结构」分不清是没有结构还是
   样本太小。
3. **仅剩的那一个自由度也不可用**：两格之比里 **22.5 h 正是 VLF 传播污染的午夜峰**
   （WWLLN 夜间效率高），量到的比值分不清雷暴日变化和台网探测效率日变化。

**一条对外有价值的副产品**（`grid02`）：雷暴模板的峰在 **LT 16.5 h（相对均值 1.6–2.9）**，
而天格只在 **10.5（0.26–0.46）和 22.5（0.79–1.13）** 观测 ⇒ **天格完全错过雷暴的地方时峰，
这解释了一部分「天格 TGF 产率偏低」，且是轨道设计决定、不可改。**

**按四颗星一起写**，依据是**两星实测 + 一星记录 + 四星倾角实测相同到 0.07°**（GRID-04 未单独验）。
**不要写成「四星实测」。** 论文限制措辞：

> 天格四颗卫星均为太阳同步轨道（实测倾角 97.46°–97.53°，GRID-07 升交点地方时 22.61 h、
> 195 天内漂移 0.13 h）。这类轨道的当地太阳时被锁定在两个值附近：GRID-07 在 |偶极磁纬| < 33°
> 的曝光有 51.6% 落在当地太阳时 10.5 h、48.4% 落在 22.5 h，**其余六个三小时区间的曝光为零**。
> 因此当地太阳时的日变化在本数据集上**没有定义域**，无法用它对候选样本作成分分解；
> **这是轨道类型的性质，不随样本量改善。**
