# GRID-03B 凭什么能出短硬暴

天格四颗星的 29 个短硬暴、7 个闪电认证 TGF 全部出自 GRID-03B。本文记录为回答
「为什么只有它」而做的实测，以及那 9 个被旧判据归为「毫秒级软暴」的 03B 候选的
事例级情况。日期 2026-09-10，v10 产物（`gridrun/data`）。

标注约定：**实测**＝从归档文件或账本直接量出来的；**推断**＝由实测量加模型算出来的；
**没验成**＝提出了但没有做到或做不了。

---

## 0. 一句话结论

**推断。** 三条，按重要性排：

1. **读出死时间差 6 倍。** 03B 是 4.7684 µs（20 tick），GRID-02/04/07 是 28.61 µs
   （119–120 tick）。TGF 恰恰是最会在探头里堆积的东西：把 03B 那 7 个闪电认证的 TGF
   按 28.61 µs 重放，计数从 85 掉到 44–52。
2. **时戳被读出塌到帧上，然后被反粒子判据当粒子否掉。** grid04 从 GRID-04 实测出
   它是**四路共用一条读出链**（帧内每路最多 1 个事例、全帧共用触发那一击的时戳），
   不是四路独立。我用这个模型重放 03B 的暴：最佳窗的同戳占比中位从 0.10–0.22 涨到
   **0.400**，35 个里 27 个越过 `MAX_SIMULTANEOUS_FRACTION = 0.35`。最典型的是
   2022-10-04（79 µs / 21 计数 / 有闪电认证）——共帧后计数仍有 8 个、fa = 9.7×10⁻⁷
   本来够显著，但同戳占比 0.500，**被当带电粒子否决**。
3. **低磁纬本底高 2–3 倍**（不是任务书里的 4–5 倍，那是选择效应）。同口径实测：
   03B 239–328 c/s，GRID-02 678–720，GRID-04 678，GRID-07 520。这条只是次因。

三条一起把三星应有的短硬暴期望从 **39.8** 压到 **5.5**（P(实测 0) = 0.004），再叠上
曝光可用性（GRID-07 实测 ×0.55）还要更低。剩下的 2–3 σ 完全落在「注入源是已探到的
那 29 个、偏亮」这个已知的向上偏倚里。**不需要新的物理。**

（早先版本用 r = 1300 c/s 算出「P = 0.06、异常基本消失」，那个本底值是另外三星
**显著候选处**的中位、而它们的候选全在高磁纬，是选择效应。**那个 0.06 作废。**）

「时戳分辨率不同」这个最初的猜测是错的：四颗星的时戳栅格都是 2^-22 s（grid04 定案，
本文独立复核 03B），4.77 µs 是 03B 的死时间不是它的时戳精度。

## 1. 时戳栅格与死时间（实测）

### 1.1 栅格

**实测。** 事例 `TIME`(D) 落在 2^-22 s = 0.2384186 µs 的整数格上。03B 的 38 个显著
候选里出现过的最小跨探头间隔全是它的整数倍（0.24 / 0.48 / 0.72 / 0.95 / 2.38 /
4.77 / …）。栅格定案由 grid04 给出（判据：`TIME × 2^22` 的小数部分严格为 0），四星
相同，本文不重复。

`TIME` 的绝对值约 1.3×10⁸ s < 2^28，f64 的 ulp ≤ 2^-25 s = 0.0298 µs，所以 2^-22 s
的栅格在绝对时间上可精确表示，判栅格不必减基准。

### 1.2 死时间 = 20–21 tick = 4.7684–5.0068 µs

**实测。** 用 grid04 的脚本 `diag/grid04/grid04_deadtime.py`（未改），跨 2022/2023/2024
取 12 天 × 每天 2 次过境 = 24 个文件、96 个「过境 × 探头」，只取 `EVT_TYPE==1`，
探头内相邻 dt 逐 tick 直方，合计 1.112×10⁸ 个相邻对：

| tick | µs | 计数 |
|---|---|---|
| 0 | 0 | **0** |
| 1–18 | 0.24–4.29 | 每格 17–42，合计 477 |
| 19 | 4.5300 | 676 |
| 20 | 4.7684 | 90 091 |
| 21 | 5.0068 | 236 721 |
| 22–39 | 5.25–9.30 | 每格 238 000–245 000（坪） |

- 半高点落在 tick 20 或 21，**96 个「过境 × 探头」全部如此**，没有例外。
- **逐年不变**：2022 / 2023 / 2024 的半高 tick 集合都是 {20, 21}，跨过的速率范围
  142–23 946 c/s。**死时间在 789 天里没有改过。**
- **四路一致**：det0/1/2/3 的半高 tick 集合都是 {20, 21}。
- **19 tick 以下不是严格零**，但只有 477 / 1.112×10⁸ = **4.3×10⁻⁶**。
- **`tick 0 恒为 0`**：同一个探头上从来没有两个事例落在同一个时间戳。所以搜索里
  `simultaneous_fraction` 数到的同戳事例**必然来自不同探头**，这条判据量的就是跨探头
  符合，不是同探头堆积。

**实测（独立复核另外三星的数）。** 直接读 grid04 产出的 `diag/grid04/dt_g04.json`：
GRID-04 的直方在 tick 119 之前恒为 0（累计 536 / 478 296 = 0.1%），tick 120 = 28.6102 µs
跳到 23 606，坪高 1 242。**GRID-04 死时间 = 120 tick = 28.6102 µs，与 03B 之比 6.00。**
grid02 后来实测 **GRID-02 是 119 tick = 28.3718 µs**（147 次过境、2.26×10⁷ 个间隔），
GRID-07 是 120 tick。本文的注入统一用 28.6102 µs，对 GRID-02 保守 0.8%。

**实测。** FITS 的 `DEAD_TIME` 列在 7.93×10⁷ 个事例上恒为 15（µs），与实测的 4.77 µs
不符，是占位值，不能用。

### 1.3 死时间是配置值，789 天里没有变过（实测，全量）

死时间落在整数 tick 上（03B 20 tick、GRID-02 119 tick、GRID-04/07 120 tick），基本
断定是以 tick 为单位写进寄存器的配置值而非电路固有常数。所以必须查它在任务期内变过
没有——若有某几段被设成 120 tick，那几段 03B 的探测能力就跟另外三颗一样差，注入
检验里的曝光要相应扣掉。

**做法。** `grid03b_dt_series.py`，农场 4 个 worker。逐天取 2 次过境（按文件大小排序
取中间两个，避开几十秒的碎片过境和辐射带巨文件），逐探头做 dt 的逐 tick 直方，
用两套坪窗口（tick 25–60 与 125–180，对应 20 tick 与 120 tick 两种配置）各定一次
半高边沿、取坪高大的那套。覆盖 **2022-03-11 .. 2024-08-01 共 788 天、1531 次过境、
6102 个「过境 × 探头」、2.22×10⁹ 个事例**。

**覆盖率要写出来（2026-09-11 现算补）：这 1531 次是归档 11,792 次过境的 13.0%。**
789 个有 `evt_v*` 的天、最高版本目录下合计 11,792 次过境；"每天取中间两个"给出
`47×1 + 742×2 = 1531`（47 天只有 1 个文件），与上面的数逐个对上。**选法是有意的、
理由就写在上一句里**（避开碎片过境和辐射带巨文件，因为这个估计量在高计数率下会飘
——本节后面那 657 行 22–32 tick 的伪影正是这个）。**所以这不是抽样失误。**

**但要认一件事**：归档里 **448 天每天有 18–22 次过境**，它们各自只贡献 2 次中位大小
的过境，**最大的 16–20 次一次都不进样本**。于是「788 天没变过」是在**估计量最稳的
那一档**上得出的。这对"配置有没有变"是合理的取舍（高速率档的边沿本来就测不准），
但**不能读成"全部过境都查过了"**。要升级成 100% 覆盖得把选法改成全取重跑一轮
（约 1.7×10¹⁰ 个事例，与一轮全量扫描同量级），尚未做。

结果：

| edge_tick | 行数 |
|---|---|
| 20 或 21（= 4.77–5.01 µs） | 5268（86.3%） |
| 22–32 | 657 |
| ≤ 19（零星） | 12 |
| 定不了（统计不足） | 165 |
| **≥ 40** | **0** |
| **≥ 100** | **0** |

- **没有任何一天、任何一路落在 120 tick 附近。** 估计量对 120 tick 是敏感的（那种
  配置下 tick 25–60 的坪会是 0，第二套窗口就会给出 ~120），所以这是阴性结论不是盲区。
- 22–32 的 657 行是**估计量在高率下的伪影**，不是死时间变了：它们的速率中位 409 c/s，
  而 20/21 那些行是 138 c/s。高率下 dt 分布本身衰减快，「tick 25–60 的中位」低估了
  tick 21 处的高度，半高点就往后挪。
- 边沿以下的相邻对合计 294 395 / 2.22×10⁹ = **1.3×10⁻⁴**（12 天精细样本给的是
  4.3×10⁻⁶，逐日样本因为把高率过境也算进来所以偏高）。
- 逐年逐月看（表见 `dtseries/all.csv`）：每个月都是 20/21 占多数，没有台阶。

**结论：GRID-03B 的死时间配置在整个 789 天任务期里没有变过。** 注入检验用的曝光不必
扣。

### 1.4 死时间给出的窗长硬下限（推断）

非瘫痪型死时间 τ 下，跨度 S 的窗口里一个探头最多给 ⌊S/τ⌋+1 个事例，四路合计
4(⌊S/τ⌋+1)。搜索要求 `min_number = 8`，所以 **8 个计数的窗长硬下限 = τ**：

| | τ (µs) | 8 计数窗长下限 | 实测最短显著窗 | 比值 |
|---|---|---|---|---|
| GRID-03B | 4.768 | 4.77 µs | 26 µs（全候选）/ 30.5 µs（显著） | 5.5 |
| GRID-02/04/07 | 28.610 | 28.61 µs | 330 / 211 / 467 µs（全候选） | 11.5 / 7.4 / 16.3 |

下限本身四星只差 6 倍，但要凑到下限附近要求四路都恰好以 τ 的间隔各打两发，概率
极低；实测的最短窗都在各自下限的 5–16 倍处。

## 3. 注入检验：把 03B 的暴放到另外三星的条件下（决定性）

**做法。** 脚本 `gridrun/diag/grid03b/grid03b_burst_export.py`。对 03B 的 38 个显著
候选（fa ≤ 1e-5），取所在过境的完整事例流（准入与 `Event::keep` 完全一致：
`EVT_TYPE==1` 且 `PI ∈ [1, 97)` 且 `E_MIN[PI-1] ≥ 30 keV`），按探头施加非瘫痪型
死时间 τ = 28.6102 µs，再在同一段里用与 `snapshot_stepping` 逐条对齐的判据重搜：

```
sf = P(X > count)                      # statrs 的 Poisson::sf 是严格大于
fa = sf × 365.25 天 / bin_size_best
lambda = (本底窗计数 − 空窗计数) × duration / (本底窗活时长 − 空窗活时长)
本底窗 ±0.5 s、空窗 ±5 ms，两端夹到 GTI 内；min_number=8，max_duration=1 ms
```

**对账。** 最佳格 `[start+delay, +bin_size_best]` 内的准入事例数 **38/38 等于 JSON 的
`count`**；`fa` 用 JSON 的 `mean`/`count` 复现，|log10 比值| 中位 5×10⁻¹⁵（顺带定死
了两件事：`sf` 是严格大于，`DAYS_PER_YEAR` 是 365.25）。**基线重搜（不施加任何注入）
38 个全部复现出与 JSON 相同的 `fa`，|log10 比值| 中位 4.3×10⁻¹⁵、最大 3.7×10⁻¹⁴**——
所以下面的注入结果是同一套判据下的对照，不是另一个算法的结果。

**实测结果**（存活 = 仍达 fa ≤ 1e-5；三列分别是 38 个全部 / 29 个短候选 / 7 个闪电
认证。死时间两种模型：非瘫痪型 = 死期只由被记录的事例起算，读出型；瘫痪型 = 每个
到达的事例都重新起算，成形时间型。归档里看不出是哪种，两个都给）：

### 3.1 共帧读出模型：时戳塌陷 → 反粒子判据把暴当粒子否掉

**背景。** grid04 从 GRID-04 的跨探头间隔分布实测出：GRID-04 的跨探头间隔要么恰好 0、
要么 ≥ 28.610 µs，开区间 (0, τ) 里 246 万个间隔只有 26 个（1×10⁻⁵，独立模型预期
5.5×10⁻²，差 130 倍）；而 03B 在 (0, 4.768 µs) 里连续铺满（4.6×10⁻³，独立模型预期
4.1×10⁻³，符合）。**所以 GRID-02/04/07 是四路共用一条读出链，03B 是四路独立。**

**我的独立实现**（`grid03b_frame_inject.py`，没看 grid04 的代码）：任一路击中开一个
τ = 28.6102 µs 的帧，帧内每路最多记 1 个事例，帧内所有事例共用触发那一击的时戳，
帧结束才能开下一帧。再用同一套判据重搜，并把搜索里真正会跑的两道否决加上：
`simultaneous_fraction > 0.35` 与 `detector_share > 0.8`。对账 38/38。

| 本底 r (c/s) | 共帧、不加否决 | 共帧 + 同戳 0.35 + 单路 0.8 |
|---|---|---|
| 400 | 22 / 18 / 5 | 7 / 5 / 2 |
| 600 | 11 / 10 / 4 | 6 / 5 / 2 |
| **678**（grid04/grid02 实测） | 10 / 9 / 3 | **5 / 4 / 1** |
| 800 | 9 / 8 / 3 | 5 / 4 / 1 |
| 1300 | 5 / 5 / 0 | 2 / 2 / 0 |

（三列 = 38 全部 / 29 短 / 7 闪电认证）

**共帧后最佳窗的同戳占比中位 0.400，35 个里 27 个越过 0.35 的门。** 计数合计
408 → 338（0.828），7 个闪电认证 85 → 52（0.612）。所以**否决而不是计数不足**才是
主要杀手：2022-10-04（21 计数 / 79 µs / 闪电认证）共帧后仍有 8 计数、fa = 9.7×10⁻⁷
够显著，却因同戳占比 0.500 被当粒子丢掉。grid04 用完全独立的实现做 200 次随机重放，
得到同一个候选**74% 的试验被同戳门否掉**——两边对上了。

**最终账（共帧 + 两道否决，r = 678）：**

| | 三星朴素期望 | 存活率 | 修正后期望 | P(实测 0) |
|---|---|---|---|---|
| r = 600 | 39.8 | 0.172 | 6.86 | 0.001 |
| **r = 678** | 39.8 | **0.138** | **5.49** | **0.004** |

再叠上曝光可用性（只有「可定位 ∧ 低磁纬」的曝光才可能产出目录候选）：grid07 实测
GRID-07 的可用占比 31.5% 对 03B 的 57.1%，即 ×0.55；02/04 的还没量。

**结论：剩下的是 2–3 σ，而且方向已知——注入源是 03B 已经探到的那 29 个暴，它们按
定义偏亮；真实族群里更暗的那些在共帧仪器上损失只会更大，所以 5.5 是期望的上界。
不需要第四个因素。**

| 2022 | 0.044 | 0.234 | 0.893 |

> **总速率**，而总速率本身被低能成分抬高——台阶前的过境因为多收了 30 keV 以下的事例，
> 被系统性地推进高速率档，等于把因变量塞进自变量。改用 **30 keV 以上的速率**

### 7.6 用 03B 自己做的纪元对照：本底降一半，短硬暴产率没涨（实测）

## 10. f₃ 判据：三步法第 (b) 步，以及它的结构性缺陷（2026-09-11）

第 5 节提出的 f₃（落在 ≥3 重同戳簇里的计数占比）在上一轮被写进 `search.rs`
（`MAX_TRIPLE_FRACTION = 0.5`）。本节补齐当时缺的第 (b) 步，并报告在补这一步的过程中
查出的一个结构性缺陷——**那个阈值对「一次穿越」的带电粒子恒不触发**。

脚本：`f3_chance.py`（偶然期望，解析＋MC）、`f3_background.py`（本底对照，农场）、
`f3_summary.py`（合表）、`f3_pool.py` + `f3_pool_scan.py`（全池扫描，农场）、
`f3_structure.py`（λ₃ 的均匀假设检验）、`f3_injection.py`（亮而短注入网格）。

### 10.1 结构上限：`f₃ > 0.5` 对一次穿越恒不触发（实测＋推导）

**推导。** GRID-03B 四路探头，同一探头从不同戳（1.12×10⁸ 个探头内相邻对里严格为 0，
第 1.2 节）⇒ **同戳簇最多 4 重**。搜索的 `min_number = 8` ⇒ 只含**一个**簇的候选
f₃ = 簇重 / n ≤ 4/8 = **0.500**。判据是严格大于，所以：

| n | 单个 4 重簇的 f₃ | 单个 3 重簇的 f₃ |
|---|---|---|
| 8 | **0.500** | 0.375 |
| 9 | 0.444 | 0.333 |
| 10 | 0.400 | 0.300 |
| 12 | 0.333 | 0.250 |

**任何 n 下的一次穿越都漏，不只是 4/8 那一个边界值。** 把阈挪到 0.45 只堵住 n = 8
那一档。`f₃ > 0.5` 实际等价于「窗内有 ≥2 个三重簇」。

**实测印证（38 个显著候选）：** k₃ = 1 的 4 个候选 f₃ 最大 **0.333**，k₃ ≥ 2 的 8 个
f₃ 最小 **0.600**。当初立阈的理由「实测 f₃ 在 0.333 与 0.600 之间有干净空隙」
**是算术不是两个人群**——那就是「一个簇」与「两个簇」在 n = 9–12 上的间隙。

**注入实证：** 第 10.5 节的九宫格里，`f₃ > 0.5` 在 **9 格全部精确为 0**，连最亮最短的
格子都没让它响过一次。

**为什么 38 个显著候选看不出这一点：选择效应。** 一次穿越的候选在 v10 就被旧门
（f₂ > 0.35，即 4/n > 0.35 ⇒ n ≤ 11）砍掉了，不在这 38 个里。**拿被旧判据筛过的样本
去标定新判据**，与 HXMT 那次「负样本按本底被压低选出、而判别量就是本底低的同义表述」、
GECAM 那次「阈定在自己判据选出的幸存者的 95 分位」是同一个内核：**标定样本受被标定
对象污染**。

### 10.2 第 (b) 步：三种「偶然」要分开算

| 偶然的来源 | 逐候选 | 38 个显著候选合计 |
|---|---|---|
| ① 量化偶然，**朴素口径**（n 个可区分事例独立均匀落 m = T/q 格） | E[f₃] 中位 5.59e-5、最大 2.12e-3 | λ₃ = 0.0429 |
| ① 量化偶然，**逐探头口径**（同探头不重格，三重必须来自 ≥3 路） | E[f₃] 中位 **2.23e-5**、最大 8.85e-4 | λ₃ = **0.0181** |
| ② 本底粒子落进窗（本底三重簇率 × 窗长） | λ₃ᵇᵏᵍ 中位 2.24e-4 | **0.0118** |
| **合计** | | **0.0299** |

**实测 12 个候选带三重簇、共 22 个簇 → 实测 / 偶然 = 401 倍（个数口径）；非零者逐候选
实测 f₃ / 偶然 E[f₃] 中位 1.5×10⁵、最小 2.7×10⁴。** 富集不是偶然，这一步立住了。

三条核对：
- 朴素口径**精确复现**了 `OPEN-QUESTIONS` 第 14 条那张表（中位 5.59e-5 对 5.6e-5、
  最大 2.12e-3 对 2.1e-3、最小比值 1.1e4）。那张表本身是对的，只是当时没有产出物。
- 逐探头口径把偶然再压低 2.3 倍（逐候选比中位 0.437），**分离不降反升**。以它为准，
  朴素口径当交叉核对保留。
- MC 验证解析式（8×10⁶ 次/候选）：E[f₃] 差 1%。
  （**「把 20 tick 死时间加进 MC 后偶然再低 3–7%、所以解析式是保守的」这句已作废**：
  那 3–7% 是拒绝抽样的噪声。死时间项后来求出了闭式，见第 13 节——这 38 个候选上
  精确的修正是 **×1.00–1.01**，既不升也不降；只有 saturation > 0.5 时才显著。）

**7 个闪电认证的 f₃ 全为 0，但这条不能单独引。** 它们各自的 λ₃ 合计只有 **0.0112**
——**即便它们全是普通光子暴，本来也不该出现三重簇，f₃ = 0 与偶然完全相容**。这个量在
它们那个亮度和时长上**没有分辨力**，真正的考验在第 10.5 节。

### 10.3 本底对照：旧的「7% 非零」作废，口径错了

旧文写的「本底对照（暴外 ±50 ms，17500 次），f₃ > 0 的占 7.0%」以及由它得出的
「12/38 = 32% 是 7% 的 4.5 倍超出」**作废**。作废理由不是数错，是**窗长不匹配**：
那个对照取的是 **n 个连续本底事例**，匹配的是计数不是窗长。复刻实测（20 万次/候选）：
f₃ > 0 的占比中位 **2.67%**（最大 6.4%），而**这 n 个事例的跨度中位是候选窗长的 92 倍**
（四分位 59–208，最大 979）。它量的是「几十毫秒里有没有粒子」，不是「候选窗里有没有」。

**同窗长口径的本底对照**（`f3_background.py`，逐候选在自己那次过境上量）：

| | 实测 |
|---|---|
| 本底率（keep 后，四路合计） | 中位 346 c/s |
| **本底三重簇率** | 中位 **1.06 个/s**（四分位 0.96–1.22） |
| λ₃ᵇᵏᵍ = 率 × 窗长 | 中位 **2.24e-4** |
| 随机同长窗实测 f₃ > 0 的占比 | 中位 2.34e-4（与解析折算对上） |
| 同一批随机窗里计数 ≥ 8 的占比 | 中位 **0**（最大 3.3%） |

**所以超出是 1400 倍，不是 4.5 倍。** 最后一行顺带说明本底在这个窗长上根本凑不出候选。

### 10.4 λ₃ 的均匀假设：偏差存在、方向是低估、幅度 ≤ 2 倍

解析式假定 n 个事例在 T 上均匀独立。真暴发在窗内成团，**非均匀会抬高真实的偶然三重率**，
低估 λ₃ 会让 P 偏小、判据偏向误杀——不安全的方向，必须量。两个独立做法，都只看
**k₃ = 0 的干净子集**（26 个，含全部 7 个闪电认证）：带真簇的候选会用自己的粒子簇去
定义「结构」，是循环。

| 保结构的尺度 | 逐探头随机平移 | 局部密度解析 |
|---|---|---|
| 最细（±1 µs / w = 5 µs） | **1.87×** | 5.04×（w 已低于死时间 4.77 µs，不可用） |
| ±2 µs / w = 10 µs | 1.13× | **1.91×** |
| ±5–10 µs / w = 20 µs | 0.76–0.78× | 1.34× |
| ±20 µs / w = 50 µs | 0.60× | 0.96× |

7 个闪电认证单独看：均匀 0.0105 → 平移 ±10 µs 0.0097（0.92×）→ 局部 w=20 µs 0.0125（1.18×）。

**取 ≤ 2 倍作为均匀式的低估上界。**

**做这条时踩的坑，记下来。** 第一版平移量是四路独立抽的，结果 ±1 µs 档虚高到 45×。
根因：**两路平移量恰好相等时，它们原本的同戳对会原样复原**，真簇整批漏回「偶然」里
（±4 tick 有 9 个取值，一对撞上 1/9，三重复原 ~1/81，22 个真簇漏回 0.27 个，比要测的
量还大）。改成**四路平移量互不相同**后漏项精确归零，45× 变成 1.87×。这又是一次
「标定样本被被标定对象污染」。

### 10.5 亮而短的注入网格：判据真正的考验

7 个闪电认证都不亮不短（计数 8–21、窗长 41–173 µs），它们过关说明不了问题。九宫格：

## 13. 含死时间约束的 λ₃ 有闭式解，所以这一项不必留安全系数（2026-09-11）

第 12.2 节说「死时间的修正方向随窗的致密程度翻转」，当时是用拒绝抽样量的，高占用度
的格子上有效抽样只剩几百次、噪声比效应还大。**其实这个量可以精确算。**

零模型：探头 d 的 n_d 个事例等概率落在窗内 m 个时戳格上、**同探头两两间隔 ≥ g = 20 格**，
四路独立。令 y_i = x_i − (i−1)(g−1)、M = m − (n−1)(g−1)，合法组态与 C(M, n) 个子集
一一对应，于是逐格占据概率
    P_d(t) = Σ_i C(y_i, i−1)·C(M−1−y_i, n_d−i) / C(M, n_d)，y_i = t − (i−1)(g−1)
再由期望的线性性
    λ₃ = Σ_t Σ_{|S|≥3} Π_{d∈S} P_d(t) · Π_{d∉S} (1 − P_d(t))
精确。代价 O(m·Σn_d) 次组合数（m ≤ 4000、Σn_d ≤ 30），Rust 里可忽略。
脚本 `f3_deadtime_exact.py`；g = 1 且 P_d(t) = n_d/m 时退回原来的均匀式。

**修正幅度随 saturation = n / n_max(W) 走（全部是精确值，无抽样噪声）：**

| saturation | 含死时间 λ₃ / 均匀 λ₃ |
|---|---|
| < 0.30 | **1.00–1.01** |
| 0.30–0.50 | 1.01–1.06 |
| 0.50–0.80 | 1.09–2.29 |
| 0.80–1.00 | **2.64–33.9** |

**对现有样本可忽略**：38 个显著候选的 Σλ₃ 从 0.0181 变成 0.0183（**×1.01**），逐候选
最大也只有 ×1.01——第 10 节的结论一个字不用改。**只在读出快被占满时才要紧**：
2022-03-19 那个 saturation = 1.000 的候选，均匀式给 P(≥1) = 2.34%，含死时间的精确值
**5.31%**（独立的 MC 给 5.5%，对上了）。

**所以第 12.2 节建议的「saturation ≥ 0.3 当适用性开关」可以撤销**——既然闭式可算，
判据里直接用含死时间的 λ₃ 就行，不必设开关也不必为这一项留安全系数。

**注意别把两种偏差混为一谈。** λ₃ 有两个独立的模型偏差，来源和处理方式都不同：

| 偏差 | 来源 | 现状 |
|---|---|---|
| 死时间约束 | 同探头两两间隔 ≥ 20 格 | **已精确求解**，不必留系数 |
| 窗内非均匀 | 真暴发在窗内成团（第 10.4 节） | 实测 ≤ 1.9×，**仍需安全系数 2** |

### 14.5 **撤回**：「死时间对偶然的影响符号会翻」这个说法作废

第 12.2 节的标题「死时间的修正方向翻了过来」说的是**先前那个「偶然再低 3–7%」的说法错了**，
**不是**「符号随窗的致密程度而变」。闭式给的是单调的：

λ₃(含死时间) / λ₃(均匀) **恒 ≥ 1**。机制是死时间把同探头事例互相推开，逐格占据概率 P_d(t)
在窗中间抬高、两端压低，而 Σ_t P_d(t) = n_d 不变；λ₃ 是 ≥3 个占据概率的乘积之和，按凸性
只能升。**稀疏窗上只是趋近 1，不会掉到 1 以下。** 实测（精确值）：saturation 0.01 处
1 + 2e-7、0.08 处 1.0001、0.29 处 1.011、0.50 处 1.142、1.00 处 2.64。

**38 个真候选上最大 1.029、中位 1.0001。** 闭式的价值是把这一项钉死成可忽略、省掉一个安全
系数，**不是修正量本身有多大**。

### 14.6 建议

问题不在 λ₃ 精不精确，在于「k₃ ≥ 1」这个触发条件在长窗上等价于窗长门。两条路：

- 改成对窗长不敏感的形式（例如按 k₃/λ₃ 的比值定阈，而不是按泊松尾概率）；
- 或者承认它只在 W ≲ 30 µs 上强于旧门，**限定适用窗长并明确标为调出来的判据**。

**现在这一版不建议进 v12。**

### 14.7 `f₃_norm = f₃ / f₃max` 这条最小修法**行不通**（实测，2026-09-11）

统筹提的最小修法是把 f₃ 按结构上限归一、阈值定在 1.0 附近，理由是缺陷实例的
f₃max = 0.5、f₃ = 0.500 ⇒ f₃_norm = 1.000 会被抓住。**这个 f₃max 算错了，实际是 1.000。**

f₃max 要按 (n, W, 死时间, 探头数) 构造：m = ⌊W/q⌋ 格里能放下的互不冲突的簇位是
c = ⌊(m−1)/20⌋ + 1 个（同探头两两间隔 ≥ 20 格），每簇最多 4 重，所以
**f₃max = min(1, 4c/n) = min(1, n_max(W)/n) = min(1, 1/saturation)**。

缺陷实例 W = 8 µs ⇒ m = 34 格 ⇒ **c = 2 个簇位** ⇒ 4c = 8 = n ⇒ **f₃max = 1.000**，
于是 f₃_norm = 0.500/1.000 = **0.500，和原来的 f₃ 一模一样，仍然被 `> 0.5` 放过。**

f₃max = 0.5 那个数来自第 10.1 节的「**只含一个簇**的候选 f₃ ≤ 4/8 = 0.5」——那是对**该
候选实际只出现了一个簇**这一观测的描述，**不是 (n, W) 的结构上限**。8 µs 的窗里放得下
两个四重簇，只是这一次只来了一个。两者不能互换。

**更根本的是它在整个池子上恒等于原判据**：f₃max < 1 需要 n > 4c，即 saturation > 1，
而 saturation > 1 意味着计数超过读出上限、实际不可能出现。池内 saturation 最大是 0.361
（闪电证实）、缺陷实例 1.000，**38 个候选的 f₃max 全是 1.000**，所以
**f₃_norm ≡ f₃，一个判决都不会变。**归一化是个空操作，不必再跑注入。

**顺带排除另一条**：按 k₃/λ₃ 的比值定阈同样不行，而且更糟——λ₃ ∝ W，所以比值 ∝ 1/W，
**比泊松尾概率更依赖窗长**，正好是要躲的那个病。

**所以现在能支持的结论是**：v11 的 `f₃ ≤ 0.5` 保持不变，那个缺陷实例作为已知限制写进
论文；真正把它和正常候选分开的是另外两个量，而且都已经量过——**saturation**（7 个闪电
证实最大 0.361、全池 2632 个无一 ≥ 0.5，缺陷实例 1.000）与**过境级的 `frac_ev_in3`**
（该次过境 0.78，38 个正常候选所在过境 8×10⁻⁴–1.7×10⁻²）。两者都还只当诊断列。

| −1.541 ms | 157.5 keV | 是 | 0.0002 |
| −0.541 ms | 161.6 keV | 是 | 0.0001 |
| +0.460 ms | 157.5 keV | 是 | 0.0001 |
| +1.460 ms | 157.5 keV | 是 | 0.0000 |

先前记的「±1 ms 内还有第二次同样的穿越」**就是 1 kHz 脉冲串里的下一发**；「四路沉积
143–168 keV 高度一致」也不再是粒子的证据——**脉冲簇能量中位就是 159.6 keV**，落在这个
区间正中。

### 15.5 脉冲的关断廓形

梳齿上的四重簇按 9.8 s 分箱：0–176.5 s 每箱约 7,300 个，176.5–186.3 s 掉到 4,762，
**之后全零**。**第 12.3 节记的「第 13→14 段之间 14 秒的格子里占比掉 200 倍」就是脉冲在
182.8 s 关掉**，不是「进出贯穿性粒子区」。

### 15.6 连带要改的结论

- **「`f₃ ≤ 0.5` 放过了一个真缺陷实例」这句的物理叙述整个换掉**：那个实例**不是穿星粒子，
  是标定脉冲**。作为"这道门放过了一个不该成为候选的东西"仍然成立，但**论文里写"已知
  限制"时不能说它是粒子**。
- **`saturation = 1.000` 那条诊断仍然有效，而且现在有物理解释**：脉冲一次点亮四路、落在
  同一个时戳格，8 µs 窗的 `n_max` 就是 8。
- **判脉冲过境应当用"四重簇间隔落在 `k × 4194.5` tick 梳齿上的占比"，不用 `frac_ev_in3`。**
  本次过境 98.8%、同日其余 19 次全为 0.000，**且与磁纬、速率都无关**——不存在"偷偷加一道
  磁纬门"的问题。若 03B 全任务只有这一次，那根本不必做成判据，**把脉冲过境当非观测时段
  剔除即可**。

### 15.7 **脉冲单独就能达到 `min_number = 8`——这是已证的危险，不是潜在的**

搜索的 `min_number = 8`、`max_duration = 1 ms`。1 kHz 的脉冲一发点亮四路 = 4 个计数，
所以**两发进同一个 1 ms 窗就是 8 个 = 正好等于 `min_number`**。

**实测（以每个四重簇为起点的 1 ms 窗）**：

| 窗内脉冲数 | 窗数 | 占比 | 脉冲贡献的计数 |
|---|---|---|---|
| 1 发 | 132,165 | 99.92% | 4 |
| **2 发** | **100** | **0.08%** | **8** |

**这一次过境里就有 100 个窗，脉冲单独凑满了 `min_number`。**

**机制要说清，因为它看起来不该发生**：周期 4194.7673 tick 比 1 ms（4194.304 tick）**长**
110.5 ns，照理两发永远装不进一个 1 ms 窗。**但时戳量化把相邻间隔打散成 4194 与 4195
两种**（实测 4194 占 22,919、4195 占 95,979），而 **4194 < 4194.304**——落到 4194 那一档
的相邻两发就装得进去。**所以「周期比窗长、装不下」这个推理在有量化的情况下不成立。**

**连带**：先前认为「脉冲频率离危险还有 2 倍余量」。**这个余量不存在**——基频就在阈上，
而且已经实际产出了一个显著候选（`2022-03-19T06:16:38`）。那个候选的窗只有 8.3 µs、
只装得下 1 发脉冲（4 个计数），另 4 个是本底，于是 `f₃ = 4/8 = 0.500` **正好顶在
`f₃ > 0.5` 这道门上被放过**——门的阈值与脉冲的结构上限精确重合，没有余地。

### 15.8 方法教训

**判别量要能把两种解释分开，而不是只与本底分开。** 第 12.3 节那三条实测（四路同戳、
能量一致、边界陡）**对"贯穿粒子"和"标定脉冲"给出的预期完全相同**，所以它们把异常与本底
分开了，却分不开两种异常。真正分得开的是**周期性**——而它当时没量。

## 16. `frac_ev_in3` 全任务逐过境扫描：不是孤例，而且磁纬关系是反的（2026-09-11）

全任务 **789 天 / 11,792 次过境**（硬断言：4 份 done 齐、Σdays_done = Σdays_expected = 789、
盖住归档天数），零 ERR，8 次事例太少。位置来源 `posatt 8666 / orbit_fit 1534 / none 1584`，
无位置秒数 1.34 Ms（全在 2024 年段）。脚本 `triple_rate_scan.py` + `triple_rate_summary.py`。

### 16.1 **不是 n = 1，是 609 次（5.17%），几乎每天一次**

| 阈 | 过境数 | 占比 |
|---|---|---|
| > 0.02 | 695 | 5.90% |
| **> 0.05** | **609** | **5.17%** |
| > 0.20 | 453 | 3.84% |
| > 0.50 | 104 | 0.88% |

**605 天 / 609 次 = 每天 1.01 次 ⇒ 散的、各天独立**，不成群。**一天一次这个节奏本身就指向
例行标定运行**，与第 15 节的脉冲发生器一致。所以判据三步验证第一步的答案是：**这一类很多，
而且是常规操作，不是偶发异常。**

### 16.2 **磁纬关系是反的——不是辐射带的影子，是"低磁纬门"**

| \|磁纬\| | frac_ev_in3 |
|---|---|
| 0–2° | 1.93e-2 |
| **6–12°** | **6.7–7.0e-2（峰）** |
| 18–24° | 6.5–8.3e-3 |
| **44–62°（辐射带核心）** | **4.4–8.1e-4（谷）** |
| 84–90° | 1.1–1.6e-2 |

**\|磁纬\| < 33° = 3.01e-2、≥ 33° = 1.79e-3，高/低 = 0.06，r = −0.593。**

**辐射带在高磁纬，而这个量在那里反而最低 17 倍**，所以「这道门是辐射带的影子」这个担心
**方向搞反了**。机制清楚：脉冲率恒定，高磁纬真实本底涨到 4.9×10⁴ c/s 把它冲淡。速率分层
是同一件事：<500 c/s 档 frac 中位 1.17e-2，>8000 c/s 档 7.55e-4，**单调下降**。

**但这对 TGF 更危险，不是更安全**：峰值恰在 **\|磁纬\| 6–12°**，而 **A 角 TGF 全在
\|磁纬\| < 33°**。**这道门是往信号区收的。**

**教训（已写进脚本）**：判"是不是磁纬门"必须看**符号**，不能只看 \|r\| 和比值大小。
同向（高磁纬更高）才是辐射带影子；反向是另一回事，而且对信号更危险。

### 16.3 真值检验通过，**但它的分辨力同样不够**

38 个显著候选（含全部 7 个闪电证实）所在过境的 `frac_ev_in3` 是 **8.5×10⁻⁴ – 1.69×10⁻²，
一个都不超 0.05**，余量 **2.96 倍**。

**但按第 14.3 节立的标准先算灵敏度**：全任务超阈比例 q = 0.0517 ⇒ 若候选随机落在过境上，
期望被否 1.96 个，**「38 个全过」的概率 (1−q)³⁸ = 0.133**；用速率匹配的档（候选全在
< 1100 c/s，该档 q = 0.034）重算是 **0.269**。**所以"0/38"单独不足以说明这道门安全。**

**真正撑住它的是分布形状**：

| frac 区间 | 过境数 | 占比 |
|---|---|---|
| 0.00–0.02 | 11,089 | 94.10% |
| **0.02–0.12（谷）** | **221** | **1.88%** |
| 0.20–0.90 | 453 | 3.84% |

**双峰，0.05 落在谷里**，不是把尾巴切一刀。**分布的谷 + 脉冲的物理机制**（梳齿占比 98.8%
对同日其余 0.000）才是依据，真值扫阈只是没证伪。

### 16.4 建议：剔除而不是判据，而且判脉冲要用梳齿不用 `frac_ev_in3`

609 次不是孤例，**当非观测时段剔除比做成判据合适**；但要先确认这 609 次是不是全是脉冲过境
（用 `pulser_comb.py` 的梳齿占比，尚未跑）。

**判脉冲请用梳齿占比，不要用 `frac_ev_in3`**：梳齿占比与磁纬、速率都无关；`frac_ev_in3`
实测与两者都强相关，**且方向对 TGF 不利**。
