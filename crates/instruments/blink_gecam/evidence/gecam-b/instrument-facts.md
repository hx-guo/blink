本文件记的是**与判据无关的仪器/数据事实**：能量梯版本、双增益重复、支路时戳延迟、

## 一、能量梯：B 星自始至终一把，没有 C 星那个细梯纪元

GECAM-C 实测早期纪元（2022-08-15）用的是 **896 行**的 EBOUNDS，`ch54` 在那把梯子里
是 **14.16–14.54 keV** 而不是 40 keV；`EboundsHdu::verify` 的尾部闸会把这种小时整小时
判 `corrupt_data`。B 星 2020-12-10 就发射，比 C 星早一年半，风险更高，所以逐日点过。

**结论：没有。** 2020-12 .. 2022-09 逐日抽一个小时，**646 天全部 498 行**，首见即
2020-12-10（B 星第一天有事例产品）。147 个已发表 TGF 所在的 **138 小时也全部 498 行**，
零例外：

```
ch0   = 2.00–2.09 keV
ch54  = 39.118–40.177 keV      ← MIN_CHANNEL 在 B 星确定是 40 keV
ch447 = 9920.97–10053.50 keV   ← 能量梯顶道
```

> **覆盖审计（2026-09-11）**：这条阴性结论**有覆盖**——C 星细梯纪元
> 2022-08-03 .. 2022-10-15 共 74 天，**B 星 74/74 天全部有事例产品、EBOUNDS
> 全部 498 行**。先前的扫描停在 2022-09-30、漏了最后 15 天，已补到 2022-10-20
> （81 天逐日查，全部 498 行）。
> **对照 A 星那条"逐日抽点 965 个文件全部 470 道、零例外"是零信息**——A 星
> 第一天数据 2022-10-21 比细梯结束还晚 6 天，**根本没有那个纪元的数据**。
> **不覆盖现象时间范围的样本给出的「零例外」不是证据。**

498 = **448 条能量梯 + 50 行溢出段**（25 路 × 2 个增益档）。C 星是 448 + 22 = 470。
**两颗星的差别只在溢出段行数（= 探头路数），能量梯本身逐道相同**，所以道号阈值在
B 与 C 之间可以直接搬——但这是对 470/498 这两把梯子说的，**对 896 那把不成立**。

一条顺带的印子：这 138 小时里有 **25 个**的 EBOUNDS 溢出段末行 `E_MAX = 0.0` 而不是
20000，与 OPEN-QUESTIONS 第 15 条 GECAM-A 那个「v0.9 pi 生成器把最后 50 道赋 0」是同
一回事，**B 星也有、但只在部分小时**。不影响 `verify`（它只查 ch447 收尾），也不影响
搜索；但要用「溢出段 `E_MIN` = 该支路满量程能量」这个技巧时，这些小时的末行得留神。

## 二、双增益重复：B 星占准入后计数的 24.75%，是 C 星的 7.6 倍

实测 2021-01-20 08h（147 个 TGF 里第一个所在的小时），25 路 GRD 全量：

| | GECAM-C（2023-06-15 12h，12 路） | **GECAM-B（本次，25 路）** |
|---|---|---|
| 原始事例 | — | 103,350,872 |
| 死时间内一高一低的对 / 原始事例 | 6.635% | **26.590%**（27,480,831 对） |
| 同档对（不并）/ 原始事例 | — | 0.006%（6,626 对） |
| 两条都过准入、被数两遍的计数 / 准入后事例 | **3.25%** | **24.75%**（11,449,016 / 46,263,237） |

**两个分母不能混**：26.590% 是「对数占原始事例」，24.75% 是「多余计数占准入后事例」。
（GECAM-A 那边同样的两个口径是 8.42–11.76% 与 25.1–29.0%。）

### 2.0 跨纪元稳定性（5 个小时，2021-01 .. 2024-01）

| 小时 | 原始事例 | 对/原始 | 时戳相等的覆盖率 | **多余计数/准入后** |
|---|---|---|---|---|
| 2021-01-20 08 | 103,350,872 | 26.59% | 88.44% | **24.75%** |
| 2021-07-13 05 | 70,924,847 | 36.54% | 85.85% | **25.90%** |
| 2022-06-15 18 | 142,097,790 | 15.32% | 85.82% | **23.29%** |
| 2022-08-30 11 | 156,731,089 | 14.23% | 85.77% | **19.72%** |
| 2024-01-11 03 | 78,719,719 | 22.71% | 85.82% | **20.44%** |

**「多余计数占准入后事例」在 19.7–25.9% 之间，跨三年稳定；「时戳相等的覆盖率」稳定在
85.8–88.4%。** 前者的波动来自各小时的能谱/本底不同（决定有多少对的两条都过准入），
后者几乎不动——那是电子学性质，不随环境变。

独立复核：`gb_feat.py` 走完全不同的代码路径（逐探头分段贪心，而 `gb_dupe.py` 只看相邻
对），同一小时报的整小时并掉比例是 **24.747%**，与上表 24.748% 一致。

**这一条把「B 星候选率比 C 星高两个数量级」从现象变成了机制**：泊松独立性被破坏的
程度差了近 8 倍。也解释了为什么 B 星非做这个去重不可。

### 2.1 旧判据「时戳完全相等」只覆盖 88.44%

`e34f560` 的 `dedupe_gain_pairs` 按「同探头同时戳」并，`3c017a2` 换成「同探头、死时间
内、一高一低」。**实测时戳相等只抓到全部对的 85.8–88.4%**（5 个小时、跨三年），漏掉的
11.6–14.2% 全落在约 100 ns（见第三节）——**正好是候选窗尺度**，而且因为时戳不同，
同戳类判据完全看不见。

折算到准入后计数：漏并约 2.9% 的计数。**所以用 `e34f560` 产物算出来的任何同戳量
（`multiplet_frac`、`f₂`、`f₃`）都系统性虚高**，不能与新口径混用。

### 2.2 两档 PI 不是同一把尺子（第 17 条「还没做的」第一项）

只取高增益条没饱和（`PI < 448`）的 11,517,746 对：

* PI 完全相同的占 **4.49%**（A 星 3.06%）
* 高 − 低 的差：中位 **−8 道**，5–95% **−31 .. +3**（A 星中位同样 −8 道）

**后果**：`MIN_CHANNEL = 54` 在两档里是两个能量，**去重保留低增益那条改变的不只是
计数，还有能阈**。

另有一条 A 星结论在 B 星不成立：「高增益支路 `PI >= 448` 占 0.00%」在 B 星是
**58.09%**——B 星的高增益条经常真的饱和进溢出道。低增益条 `PI >= 448` 只占 2.84%。
所以「保留低增益」这条规则在 B 星上比在 A 星上更是必须的。

## 三、支路时戳延迟：一个约 100 ns 的固定延迟（不是"89 和 119 两条线"）

双增益对的时戳差是**构造无关的仪器级测量**：同一个物理光子的两条记录，时戳差就是
两条支路的相对延迟，与任何选样标准无关。

**关键在于 q 必须按本小时的 MET 量级取，写死会把结论搞反。** 同一颗星、同一套电子学，
三个归档量化步长给出三对不同的"延迟值"：

| 小时 | MET 量级 | q | 时戳差的两条线（占全部对的比例） |
|---|---|---|---|
| 2021-01-20 08 | 6.48e7（< 2²⁶） | **7.45 ns** | **96.9 ns (6.01%)**、**104.3 ns (4.38%)**；89 ns 只剩 0.01% |
| 2021-07-13 05 | 7.98e7 | 14.9 ns | 104.3 (8.44%)、89.4 (3.44%) |
| 2022-06-15 18 | 1.09e8 | 14.9 ns | 104.3 (9.66%)、89.4 (3.93%) |
| 2022-08-30 11 | 1.16e8 | 14.9 ns | 104.3 (9.52%)、89.4 (3.88%) |
| 2024-01-11 03 | 1.59e8（> 2²⁷） | 29.8 ns | 89.4 (8.85%)、**119.2 (4.87%)** |

在最细的格子（q = 7.45 ns）上，两条线落在 **96.9 和 104.3 ns，相邻两格**。最简解释是
**一个约 100 ns 的固定延迟**，float64 存储把它摊到相邻两格上。

**所以 GECAM-A 实测的「89 ns 和 119 ns，3 个和 4 个量化步」不该读成两种延迟**——那是
这同一个约 100 ns 的延迟在 29.8 ns 格子上的投影；B 星在 2024-01-11（同样 q = 29.8 ns）
逐位复现了 89/119。**同一颗星换三个量化步长、三对不同的表观延迟，而底下只有一个数**
——这比任何一颗星单独测到的都硬。

对「把跨探头同戳按容差 τ 合并」这类方案：**τ 的物理尺度是「一个约 100 ns 的延迟 +
归档量化」**，不是「覆盖 89 和 119 两条线」。按这个图像，τ = 150 ns 能覆盖
（100 ns 延迟 + 29.8 ns 量化的最坏组合），而且解释了为什么 τ 加到 300 ns 不再增加。

### 3.1 B 星有三个量化纪元，第 18 条只记了两个

第 18 条现在写「GECAM-A/B 2023-04-01 变粗，之前 14.9 ns」。**但 B 星 2020-12-10 就有
数据，而 MET 跨过 2²⁶ 是在 2021-02-15T17:21:04**：

| B 星（MET 历元 2019-01-01） | q |
|---|---|
| 2020-12-10 .. **2021-02-15T17:21:04** | **7.45 ns**（2⁻²⁷） |
| .. **2023-04-03T10:42:08** | 14.9 ns（2⁻²⁶） |
| 之后 | 29.8 ns（2⁻²⁵） |

分界按 `MET = 2ⁿ` 精确算，不是抽样估的。第 18 条写的 2023-04-01（A/B）与 2023-02-19
（C，精确值 2023-02-16T17:21:04）都差两三天，多半是逐日抽样的分辨率。

147 个已发表 TGF 里 **4 个（3 个小时）落在 q = 7.45 ns 那一段**。占比小但不为零，
**任何按 q 归一化的量都必须逐候选取 `np.spacing(t0)`，不能按星按年查一个常数。**

## 四、量程上限：B 星堆在 ch447 单道，而 `PI < 448` 正好放行

逐 GTI 段（= 过境）、逐 25 路、逐增益档从 PI 直方图求 `edge`（**最后一个计数 ≥ 10 的
道**，与 A 星同口径）。**不查表**——第 19 条自己就栽在「只看了一天」上。

| epoch | 低增益 `edge`（整仪器 / 逐路范围） | `edge` 处的形态 |
|---|---|---|
| 2021-01-20 08h | **394** / 375–392（逐段中位 382，极差 12–17） | **没有堆积包**：包/平台 = 0.39×，谱单调降到悬崖（ch392 = 2,952 → ch393 = 10，300 倍） |
| 2022-06-15 18h | **447**（梯顶） | ch447 = **75,919**，ch446 = 19,479 → **3.9 倍单道尖峰** |
| 2024-01-11 03h | **447**（梯顶） | ch447 = **372,911**，ch446 = 3,194 → **117 倍单道尖峰** |

三条结论：

1. **B 星的 `edge` 在任务中途从 ch≈382–394 跳到 ch447。** 与 A 星「2022–2024 是 379、
   2025 起是 447」同一机制（ADC 满量程经 `c2e` 映射到道号），只是 B 星换得更早——与
   「B 星 `c2e` 从发射后就有在轨版本」自洽。**但 2021 年那一段仍然是被压下来的口径**，
   而那正是 147 个 TGF 里大半所在的时段。
2. **B 星没有 A 星那种 ch368–383 的宽堆积包**（A 星抬升 12.8–22×，B 星 0.39–0.52×，
   方向相反）。**所以「`PI >= 368` 占比」这个 A 星口径搬到 B 星量到的不是同一个东西**，
   两个都要记（`n_pi368` 与 `n_pi447`）。
3. **真正的污染在 ch447 单道，而 `PI < 448` 正好放行。** 这一道是能量梯顶
   （9921–10053.5 keV），进搜索就是「10 MeV 硬光子」。**B 星准入该补的上界是
   `PI < 447`** ——这是准入口径修正、不是新判据，但改的是搜索语义，**只报不改**。
   注意 2021 年那段 `edge` 是 382–394，切在 447 对那段没用；要做得逐小时从 EBOUNDS
   溢出段的 `E_MIN` 取（每行就是该 (探头, 增益) 支路的满量程能量），或逐过境求直方图。

### 4.1 EBOUNDS 溢出段查表 vs 直方图：对得上，但 18% 的小时没有输入

溢出段 50 行的 `E_MIN` 就是各 (探头, 增益) 支路的满量程能量。行序与 (探头, 增益) 的
对应关系归档里没标注，但**两档的满量程能量差一个数量级，按能量排序对半分就能分开**。
与直方图求的 `edge` 并排（`gb_fullscale.py`）：

| 小时 | 查表 高增益 | 直方图 高增益 | 查表 低增益 | 直方图 低增益 |
|---|---|---|---|---|
| 2022-06-15 18 | ch193–219（中位 207） | ch187–212（中位 201） | ch414–447（中位 427，7 行超梯顶被夹） | ch411–447（中位 423） |
| 2024-01-11 03 | ch225–261（中位 247） | ch200–226（中位 214） | ch447（25 行全部超梯顶） | ch424–447（中位 438） |
| 2021-01-20 08 | **溢出段 `E_MIN` 全是 0.0，没有输入** | ch150–162（中位 155） | 同左 | ch375–392（中位 382） |

**两条路子方向一致**：查表值系统性比直方图高十几到三十道，这是应该的——**查表给的是
满量程本身，直方图的 `edge` 是「最后一个计数 ≥ 10 的道」，统计量越少落得越低**。

**但 138 小时里有 25 个（18%）溢出段全是 0.0**（第一节那个 v0.9 生成器印子），查表法
在这些小时没有输入。**所以拿它做自适应准入上界必须带回退路径**，不能假定总有值。
（GECAM-C 的限定不同：896 道纪元里哨兵行**根本不在表里**——那是表结构缺失，B 星是
表在、值是零，两种失效模式都要挡。）

一条口径提醒：高增益档的「平台参照」不能用 ch200–300——B 星高增益 `edge` 只有
155–227，ch200–300 本身就在悬崖外，算出来的「抬升倍数」没有意义（表里高增益那一列
因此不报）。

## 五、`EVENTS` 的事例顺序（复刻 Rust 侧必需）

`EvtFile::into_iter` 是按时间的 k 路归并，`BinaryHeap<Reverse<(Event, index)>>` 而
`Event: Ord` 只比时间，所以**同时戳按探头下标升序**；之后 `events.sort()` 是稳定排序。
numpy 侧的等价写法是**数组按 `EVENTS01..25` 顺序拼好，再 `np.lexsort((det, time))`**。

按这个顺序 + 死时间去重复刻出来的窗内计数，与搜索报的 `count` 在 2021-01-20 08h 的
**31,262 个候选上逐条相等（100.0000%，差值分布只有 {0: 31262}）**。顺序或去重规则错
一处，这个数就下不来——所以它同时验了三件事：事例顺序、准入口径、去重判据。
