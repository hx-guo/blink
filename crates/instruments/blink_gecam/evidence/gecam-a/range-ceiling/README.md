# GECAM-A 的真实量程上限、死时间、以及双增益重复的残余

2026-09-10 实测。脚本在集群 `/scratchfs2/gecam/guohx/gecam_a/`：
`range_ceiling.py`（逐过境逐探头逐增益的道直方高能端）、`deadtime.py`（间隔直方图硬边沿）、
`gain_pairs.py`（双增益对的两档 PI 比较）。

## 一、`OVERFLOW_CHANNEL = 448` 在 2022-2024 段切错了：真实上限在 ch≈379

先看 2024-01-11 三个过境（h01/h02/h03，GTI 2803 / 3599 / 648 s），逐 25 路逐增益档。
**这个 379 只对 2022-2024 段成立**，2025 年起在轨 EC 上线后跳到 ch447——见下面
"跨年份"一节。

| | 低增益档（去重后保留的那支） | 高增益档 |
|---|---|---|
| 陡降位置（最后一个 ≥10 计数的道） | 中位 **379**，逐路 375–381 | 中位 **157**，逐路 149–160 |
| 对应能量 | **约 4.0 MeV** | **约 215 keV** |
| 陡降之下的堆积包抬升 | **12.8–14.4 倍**，最大 21.8 | 0.34–0.36（**没有包**） |
| `EVT_TYPE==1` 里 `PI >= 448` 的占比 | **0.00%**（25 路 × 3 过境） | 0.00% |

道—能量对照：`ch157 = 215.2`、`ch376 = 3866.9`、`ch379 = 4024.0`、`ch383 = 4243.3`、
`ch447 = 9921.0` keV。

**谱形**（2024-01-11 h02，`d01`，原始计数，逐道）：

```
ch355..367:  234 240 275 251 263 271 263 242 241 293 333 435 680
ch368..378: 2689 9750 7908 4709 2391 1812 1706 1943 2664 4022 3827
ch379..385:    3    2    2    1    0    0    0
```

平台约 250 计数/道，ch368 起暴涨到 9750（39 倍），撑到 ch378 = 3827，
**ch379 掉到 3——两个数量级的悬崖，上面全零。**

`d07` 峰在 ch370 = 14563，到 ch378 = 6 归零；`d14` 撑到 ch380 = 3468；
`d25` 撑到 ch378 = 3930。这就是超量程沉积堆在上限附近的形状，
与天格 GRID-03B 报的同一种缺陷。这些事例现在以 **3.9–4.2 MeV 硬光子**的
身份进搜索和谱硬度。

**高增益档没有堆积包**，是平滑跑完的——所以堆积只发生在低增益支路。

### 跨年份：上限随标定跳变，不是器件固定值

**这一节推翻了我先前只看 2024-01-11 一天得出的"位置不漂"结论。**
补测 5 个 epoch × 每天最多 3 个过境之后：

| epoch | 在轨 EC | 高增益 `edge`（逐过境） | 低增益 `edge`（逐过境） |
|---|---|---|---|
| 2022-10-21 | 无 | 156 | 379 |
| 2023-06-16 | 无 | 156 / 156 / **165** | 379 / 379 / **383** |
| 2024-01-11 | 无 | 157 / 157 / 156 | 379 / 379 / 379 |
| 2024-09-06 | 无 | 157 / 157 / 156 | 379 / 379 / 379 |
| **2025-06-15** | **有** | **227 / 230 / 233** | **447 / 447 / 447** |
| **2026-06-01** | **有** | **212 / 210 / 211** | **447 / 447 / 447** |

**台阶正好落在在轨 EC 开始的那条线上**（CALDB 的 `c2e` 从 2025/01 起才有 A 星）。
低增益从 ch379（4024 keV）跳到 **ch447（9921 keV，梯子顶）**，
高增益从 ch156（约 213 keV）跳到 ch210–233。

**所以这个"上限"不是硬件量程，是 ADC 满量程经过能量刻度映射到的道号。**
ADC 在固定的原始码值上饱和；它落在哪一道，取决于用的是哪份 EC。
用 1971 默认 EC 时落在 ch379，用在轨 EC 时落在 ch447——
**梯子本来就是按满量程 = 顶道设计的，2022-2024 段是标定把它压下来了。**

这与能标那边的结论互为印证（见 `../energy/README.md`）：默认 EC 在 1470 keV 处
低估 12%，而 EC 是分段二次的，**非线性使偏差随能量放大**——到满量程处
447 → 379 相当于低估 **40%**。双增益两档 PI 差随能量发散
（ch100–200 段 −13 道、ch200–300 段 −64 道）说的是同一件事。

### 过境间漂移：有，但逐 epoch 不同

| epoch | 高增益 `edge` 逐过境极差 | 低增益 |
|---|---|---|
| 2023-06-16 | 中位 **9** 道，max 11，**25/25 路 > 5 道** | 中位 4 道，max 7 |
| 2024-01-11 | 中位 2 道，max 2，0 路 > 5 | 中位 0，max 1 |
| 2024-09-06 | 中位 1 道，max 1，0 路 > 5 | 中位 0，max 1 |
| 2025-06-15 | 中位 **5** 道，max 7，**11/25 路 > 5 道** | 中位 0，max 5 |
| 2026-06-01 | 中位 1 道，max 51（1 路），1 路 > 5 | 中位 0，max 5 |

**2023-06-16 那天三个过境里 h16 整体偏高 9 道**（高增益 156/156/165，
低增益 379/379/383），25 路无一例外——是整仪器的增益偏移，不是个别探头。

**所以天格那种"逐次过境漂移"在 A 星上确实存在，只是不是每天都发生。**
我先前只看 2024-01-11（恰好是稳定的一天）就下"不漂"的结论，是抽样不足。

机制上说得通：增益随温度走，CALDB readme 自己就在用「1470keV峰位vs温度」做修正；
温度随轨道位置变，所以逐过境漂。2022-2024 段没有在轨 EC，这个漂移完全没被修。

**对方案的影响**：静态逐探头上限表**不够**——至少要按 epoch 分段（2025 前后是两个值），
而且在漂移活跃的日子里还要逐过境定。稳妥的做法是**从数据本身逐过境求 `edge`**
而不是查表。

### `PI < 448` 这半个准入条件是空转的

`EVT_TYPE == 1` 的事例里 `PI >= 448` 占 **0.00%**（25 路 × 3 过境无一例外）。
这与"`PI >= 448` 与 `EVT_TYPE == 2` 是同一集合"完全自洽：溢出段全部是
`EVT_TYPE == 2`，而准入已经要求 `EVT_TYPE == 1`。

**`Event::keep` 里真正缺的不是 448 这个上界，是随 epoch 变的那个满量程道。**
2022-2024 段它是 ch≈379，ch368–383 那个堆积包整个落在准入范围内；
2025 年起它是 ch≈447，堆积包落在 ch420–447，**恰好被现有的 448 挡住大半**。
所以这条缺陷的严重程度是分段的：**污染集中在没有在轨 EC 的 2022-2024 段，
也就是唯一能做闪电关联的那 370 小时。**

逐路差异是真的，而且在有在轨 EC 的段更大：2024-01-11 低增益逐路 375–381（6 道），
2026-06-01 是 420–447（**27 道**）。要切得逐探头切，一个全局常数不够。

## 二、死时间 = 4 µs，与 `DEAD_TIME` 列一致

`DEAD_TIME` 列**每路只有一个取值 = 4**（25 路 × 两档全部）。

同探头事例间隔直方图（0.1 µs/格，2024-01-11 h03 `d01`，精确同时戳合并后）：

```
  0.0-1.0 us:  5762 3199    7    3    7   16    6    6   14    6
  1.0-2.0 us:    10   17    1    5   11    3   11    9    5    9
  2.0-3.0 us:     5    3   15    7    0   13    4    5    9    5
  3.0-4.0 us:    11    3    4   12    7    5   14    3    5   35
  4.0-5.0 us:    29   25   68   28   27   75   24   63   31   37
  5.0-6.0 us:    63   27   23   62   28   32   66   27   27   63
```

0.2–3.9 µs 是 5–15 计数/格的近零区，**3.9–4.0 µs 起跳到 25–75 并维持**。
**硬边沿 ≈ 4 µs，与 `DEAD_TIME = 4`（单位 µs）对上了。**

按天格的提醒，这里用的是直方图硬边沿不是分位数——最小正间隔（30 ns）
比死时间小 130 倍，拿它当栅格会完全带偏。

## 三、死时间之下还有一批对：现有合并漏掉 15–16% 的双增益重复

上面那个直方图的 0–0.2 µs 尖峰（5762 + 3199 ≈ 9000 计数/路）落在死时间**之下**。
**死时间 4 µs 是硬约束：同探头间隔 < 4 µs 的相邻对不可能是两个独立光子。**

查它们是什么（2024-01-11 h03，精确同时戳合并**之后**）：

* 间隔 < 200 ns 的相邻对 218,991 个（占合并后事例 1.94%）
* 增益档组合：高→低 74,490，低→高 144,501，**高→高 0，低→低 0**
* **一高一低占 100.00%**
* 间隔取值：**89 ns（140,855）、119 ns（77,868）**，即 3 或 4 个量化步（29.8 ns）

即：**这些是双增益对，但两支的时戳差了 3–4 个 ulp 而不是完全相等，
所以按"时戳完全相同"合并的规则整批漏掉。**

放宽到整个死时间窗（< 4 µs）：

| | 2024-01-11 h03 | 2026-06-01 h21 |
|---|---|---|
| 准入后原始事例 | 12,508,284 | 3,415,307 |
| 精确同时戳合并掉 | 1,230,355（**9.84%**） | 200,368（**5.87%**） |
| 合并后仍有间隔 < 4 µs 的相邻对 | 224,878（**1.99%**） | 37,733（**1.17%**） |
| 其中一高一低 | **99.82%** | **96.61%** |
| **双增益重复总量** | **11.63%** | **6.97%** |
| **精确合并抓到的比例** | **85%** | **84%** |

**结论：`dedupe_gain_pairs` 按时戳完全相等合并，系统性地漏掉 15–16%。**
建议的判据是死时间——同探头相邻对间隔 < 4 µs 且增益档一高一低，就是同一个光子。

这批残余对绝大多数落在 89–119 ns，而 A 星候选窗 `bin_us` 中位是 **0.15 µs = 150 ns**，
所以它们往往整对落在候选窗内，**把 `n_core` 抬高 1 而不被 `multiplet_frac` 计入**
（时戳不同）。实测 2024-01-11 的 74,012 个候选里 **51.55% 至少含一对**，
中位 1 对，占窗内计数中位 5.88%。

## 四、两档不是同一把尺子

`gain_pairs.py`，只看高增益条未饱和的对。

| | 2024-01-11 h03 | 2026-06-01 h21（有在轨 EC） | 2022-10-21 h20 |
|---|---|---|---|
| 双增益对 | 1,230,355 | 200,277 | 180,461 |
| **高增益条 `PI >= 448` 饱和的** | **0.00%** | **0.00%** | **0.00%** |
| 高增益 PI 中位 / 低增益 PI 中位 | 105 / 118 | 168 / 188 | 110 / 124 |
| PI 差（高−低）中位 | **−8** | **−8** | **−9** |
| 完全相同 | 3.06% | **25.77%** | 3.30% |
| `\|差\| ≤ 2` | 15.08% | 32.40% | 15.84% |
| 高 < 低 | 71.51% | 65.97% | 73.94% |

**差随能量发散**（2024-01-11）：低增益 ch54–100 段差中位 **+2**，
ch100–200 段 **−13**，ch200–300 段 **−64**。
2026 有在轨 EC 的那天符合度明显好（完全相同从 3% 升到 26%），但仍然发散
（ch100–200 −11，ch200–300 −19，ch300–380 −27，ch380–448 −78）。

**对能阈的影响（`MIN_CHANNEL = 54`）**：高增益 ≥ 54 而低增益 < 54 的 0.137%，
反向 0.044%，合计 0.18% 的对会因"留哪条"而改变准入。折到全部事例是 0.02% 量级——
对计数可忽略，**对谱不可忽略**（差中位 −8 道 ≈ 11% 能量，高能段更大）。

**留低增益条是对的，但理由不是"高增益会饱和"**（实测 0.00% 饱和）：
是**两档量程差一个数量级**——低增益撑到 ch≈379（4.0 MeV），
高增益在 ch≈157（215 keV）就到顶。留高增益条会把 215 keV 以上整段丢掉。

排除过的干扰项：这些"对"会不会是同探头 29.8 ns 内的两个独立事例？
按单路 748 c/s 算，偶然同戳对的期望是 748² × 29.8e−9 × 648 s ≈ **11 对/路/过境**，
实测 49,214 对/路，**99.98% 是真双增益读出**。

## 五、这些器件效应解释不了 A 星的候选率

2024-01-11，74,012 个候选，逐级估算（按 `fa ≤ 20` 的搜索配置阈重算泊松显著性）：

| 步骤 | 剩余候选 | 较上一步 | 较现状 |
|---|---|---|---|
| 现状（已合并精确同时戳） | 74,012 | — | 100.0% |
| 再合并亚死时间对（< 4 µs） | 69,154 | −6.6% | 93.4% |
| 再切 ch ≥ 368 超量程沉积 | 59,275 | −14.3% | **80.1%** |

**两项器件效应全修完，候选只掉 20%。** A 星对 C 星的候选率比是 143 倍
（10.498 /s vs 0.0736 /s），修完仍是 114 倍。

超量程沉积在候选窗里的富集是真的——窗内 ch ≥ 368 占比中位 **0.25**，
本底窗只有 0.047，**富集 5.77 倍**；94.00% 的候选至少含一个 ch ≥ 368 的事例，
`pi_core_max` 中位 373。但它与 `multiplet_frac` 只是弱相关
（Pearson r = 0.142，Spearman ρ = 0.094）。亚死时间对与 `mf` 是**负**相关（−0.198）。

**所以：超量程沉积主要污染谱（硬度），不是候选率的主因；
候选率的主体仍是跨探头的真同戳，也就是带电粒子穿仪器。**
