## 「GTI 占空比低」这个说法要改口径

交接材料记的是「抽查某小时 GTI 只有 1303 s / 3600 s」，读起来像是一小时里有大段坏时间。
实测不是：**647 个文件里 593 个 GTI 只有一段，最多的也只有两段，GTI 占文件跨度 96.1%。**
文件内部几乎没有缺口。

真正的情况是**每个「小时文件」只覆盖一次短过境**，文件跨度本身就远小于 3600 s：
单文件 GTI 分位 5% = 213 s、25% = 1088 s、中位 2054 s、75% = 3118 s、95% = 3699 s。

所以 647 个名义小时对应 370.4 小时曝光（57.3%），损失来自文件覆盖不满一小时，
不是来自 GTI 挖洞。做曝光核算时按 GTI 秒数加总即可，不要按文件数 × 3600。

## CPD：2022-2024 一小时都没有

`GECAM_A/CPD_evt` 目录在 2025-03-12 之前**根本不存在**。抽查日期下 `GECAM_A/` 的子目录：

- 2023-06-16 / 2024-01-11 / 2024-09-06 / 2024-12-31 / 2025-01-17：
  `GRD_CPD_simevt  GRD_bspec  GRD_btime  GRD_evt  aux  posatt` —— 无 `CPD_evt`
- 2026-06-01：`CPD_btime  CPD_evt  GRD_CPD_simevt  GRD_bspec  GRD_btime  GRD_evt  aux  posatt`

CPD 事例产品逐月（去重后的 (天,小时) 数）：2025-03 起 90 / 335 / 655 / 325 / (2025-07 空) /
21 / 194 / 63 / 176 / 130，2026 年 226 / 96 / 79 / 103 / 32 / 239 / 32 / 91 / 39。

**后果：A 星在 WWLLN 覆盖内的 370 小时，CPD 粒子判别这条腿是空的**，`Signal::acd` 全零。
CPD 判据的定标只能靠 B / C 星。25 路 GRD 的同戳簇集不受影响。

这条与 CALDB 完全自洽：A 星 CPD 的 `c2e` 只有 `1971/01/01` 一个占位 epoch，
因为 2026 年之前根本没有 CPD 数据可标（见 `../caldb/README.md`）。
