# GECAM —— 已核实的事实与未决的问题

本文件记录 GECAM 三颗星接入 TGF 搜索时实地核对过的结论，以及还没做、
还没定标的部分。凡是"实测"字样，都指在 IHEP 集群上对归档文件直接统计的结果，
日期见各条。

## 一、三颗星与数据量（2026-09-10 勘测）

|---|---|---|---|
| 探头 | 25 GRD + 8 CPD | 25 GRD + 8 CPD | 12 GRD + 2 CPD |
| MET 历元 | 2019-01-01（MJDREFI 58484） | 同 A | 2021-01-01（59215） |
| 事例产品起止 | 2022-10-21 .. 2026 | 2020-12 .. 2026-09 | 2022-07 .. 2025-02 |
| 有数据的天 | 554 | 约 2100 | 818 |
| GRD 小时文件 | 4,609 | 约 52,700（含版本） | 19,624 |
| 单小时 | 974 MB / 5410 万事例 | 2.7 GB / 1.49 亿事例 | 297 MB / 1650 万事例 |
| 合计 | 约 4.5 TB | 约 110 TB | 约 5.8 TB |

GECAM-A 逐年的 GRD 小时文件数是 3 / 287 / 481 / 2693 / 1145（2022..2026），
**绝大多数在 2025 年以后**，落在 WWLLN 库（止于 2024-12-31）之外；2024 年底
之前只有 771 小时。GECAM-C 逐年 3228 / 8198 / 7419 / 779 小时（2022..2025），

归档路径：A/B 在 `/gecamfs/Archived-DATA/GSDC/LEVEL1/daily/{yyyy}/{mm}/{dd}/GECAM_{A,B}/`，

## 二、文件格式（三颗星一致）

逐小时 FITS：`PRIMARY` + `EBOUNDS` + `GTI` + 每探头一个 `EVENTS%02d`。
GRD 事例列 `TIME, PI, GAIN_TYPE, DEAD_TIME, EVT_TYPE, FLAG, EVT_PAIR`，
CPD 少 `GAIN_TYPE` 和 `EVT_PAIR`。整套结构与 SVOM/GRM 同源，`blink_svom_grm`
就是本 crate 的模板。

**能量梯。** EBOUNDS 的道 0..447 是一条连续单调的梯，2.00 keV 到 10053.5 keV，
相邻道 `E_MIN[k+1] == E_MAX[k]`，每道宽约 1.34%（低端疏、高端密，不是均匀对数：
ch0 = 2.0–2.2、ch50 = 35.0–36.0、ch54 = 39.1–40.2、ch100 = 100.1–101.8、
ch200 = 373.9–378.9 keV）。**B 与 C 逐道数值完全一致**，所以道号阈值三星通用；
但这是实测结论不是设计保证，`EvtFile` 载入时逐条核对（头尾、梯内连续性、
40 keV 是否仍落在 ch54），对不上就整小时报错。

**溢出道。** 道 448 及以上 `E_MAX` 一律 20000 keV、`E_MIN` 不单调（每探头每
增益档各占一行，B 有 50 行、C 有 22 行），能量不可信。实测 `EVT_TYPE == 2`
的事例 PI 正好全落在这一段（B 某小时单路 6.00%、C 15.11%）。

**增益。** `GAIN_TYPE` 0 高 / 1 低，两档共用同一套 PI 刻度（C 实测高增益
PI 11..448、低增益 179..460），所以道号可以直接比，不必分档处理。

**位姿。** `Orbit_Attitude` 表 1 Hz、一小时 3700 点（越过整点约 100 s）。位置
只给地固系直角坐标 `X/Y/Z_WGS84`，**单位是米**（|r| 实测 B 6.963–6.974e6、
C 6.855–6.870e6），要自己折成经纬高，见 `io::geodetic`。四元数模为 1。

**GTI 占空比低。** 抽查 GECAM-C 某小时 GTI 只有 1763 s / 3700 s（切成 4 段）、
GECAM-A 某小时 1303 s / 3600 s（1 段）。曝光按 GTI 算，事例流也按同一份 GTI
过滤——SVOM/GRM 上只在分母上用 GTI 而事例照单全收，缺口两端半秒数据的本底窗
伸进空区，造出过整整两类假信号。

## 三、当前判据

* 事例准入（`Event::keep`）：`EVT_TYPE == 1` 且 `54 <= PI < 448`。
* GTI 同时用于分子（事例过滤）与分母（曝光）。
* 单路探测器占比 > 0.8 的候选否决，按整候选窗算，四台仪器共用
  `blink_algorithms::detector_share`。
* 搜索窗 0 .. 1 ms，`false_positive_per_year = 20`，`min_number = 8`，
  `coincidence = 1`（各路 GRD 朝向不同，合成一路）。
* CPD 计数随每个候选记录在 `Signal::acd` 里（`AcdCounts` 的字段在 GECAM 上的
  含义见 `chunk::search::cpd_counts` 的文档注释）——**只统计，不否决**。
* 逐路 GRD 计数（候选窗与基线窗各一份）记录在 `Signal::detectors` 里，见
  `blink_core::DetectorCounts` 与下面第 13 条——同样是**只统计，不判**。

## 四、未决的问题

### 1. 能阈 40 keV 没有用 GECAM 自己的 TGF 定标

`MIN_CHANNEL = 54`（39.1–40.2 keV）是照 SVOM/GRM 的量级取的起点。SVOM 那个
42 keV 是拿 72 个闪电证实的 TGF 扫出来的：证实样本的窗内谱在更低的道上一律
低于本底、从 42 keV 起才反超，切在那里少 15% 信号、少 43% 本底，信噪反升。
GECAM 是 LaBr₃、能量梯一路到 10 MeV，谱学响应不同，这条结论不能直接搬。
**要做的**：等 GECAM 攒出闪电证实样本后按同样办法重扫，脚本可照
`scripts/plot_svom_threshold.py` 改。

### 2. CPD 判据未定标

CPD 是 GECAM 相对天格/SVOM 最大的优势——一路独立的带电粒子探测器，可以直接
回答"这个候选是不是粒子"。但"符合到什么程度算粒子"没有数据支撑，所以现在
只把计数存下来（`n_acd`、`n_acd_multi`、`n_acd_bg`），不做否决。
**要做的**：全量跑完后拿真候选看 `n_acd/n` 的分布，看它与闪电关联率的关系，
再定阈值。存原始计数而不是比例就是为了这一步能复议而不必重跑。

顺带：天格那 51 个"毫秒级软暴"至今说不清是什么（谱与本底重合、高磁纬、
无闪电、不成串）。如果 GECAM 上能找到同类事件，CPD 可以一次性回答它们
是不是带电粒子。这是做 GECAM 的一个主要动机。

### 3. `EVT_TYPE == 3` 的含义不明

实测 GECAM-C 某小时的 EVENTS02、EVENTS03 里出现过 `EVT_TYPE == 3`（EVENTS01
没有）。现在的 `keep` 只认 1，所以 3 被丢掉——安全，但不知道丢的是什么。
**要做的**：统计 3 的占比、PI 分布、是否集中在某几路探头。

### 4. `FLAG` 标的是双增益对里的角色（已答，2026-09-10）

实测 GECAM-B 某小时单路 `FLAG` 只有 0（89.98%）和 10（10.02%）两个取值，
FLAG=10 的 PI 中位是 448、与溢出道重合，先前记的是「看着像溢出标志」。
拆双增益重复记录时拿到了答案：**同一路探头同一时戳的事例对，`FLAG` 组合
100% 是 (0,10) 或 (10,0)**——它标的是这条记录在双增益对里是哪一支，
「FLAG=10 的 PI 中位是 448」只是「高增益那支常常饱和」的表象。

判据没有用 `FLAG`，也不打算用：去重走的是「同探头同时戳」这个实测事实，
见第 17 条。

### 5. 姿态四元数的分量顺序未核实

表里是 `Q1..Q4`，`blink_core::Attitude` 只收三个分量，现在原样取前三个。
标量分量到底在 Q1 还是 Q4 没有核实。姿态目前只作元数据随候选记录、不参与
任何判据，所以不影响搜索结果；但**做流强/光子谱就会卡在这里**——SVOM 上
就是卡在同一个问题上（响应矩阵要靠姿态定入射方向）。

### 6. `min_number = 8` 在 GECAM 的高本底下是否合适

GECAM-B 单路 GRD 实测约 894 c/s，25 路合计约 22 kc/s（能阈过滤前）；
SVOM/GRM 三路合计不到 1 kc/s。`min_number` 是计数下限，本底高时基本不起
作用（泊松判据先绑定），但没有实测确认。**要做的**：一天全量跑完后看
候选的计数分布，确认这条不是在无意义地卡着或无意义地放行。

### 7. 窗长上限 1 ms 未按 GECAM 复核

沿用 SVOM/GRM 的 1 ms。SVOM 上验过 5 ms：候选多 47% 而闪电关联数为纯本底，
82 个证实 TGF 一个不多一个不少。GECAM 的证实样本还没有，复核不了。
**要做的**：攒出样本后量 T90，同 SVOM 的办法。

### 8. GECAM-B 的内存开销

一小时 1.49 亿事例。事例列驻留约 2.5 GB，过滤后的 `Vec<Event>` 还要一份，
排序再要一份，估计峰值 8–10 GB/小时。GECAM-C（1650 万）无压力。
**要做的**：上 GECAM-B 之前实测一小时的峰值内存，据此定 `hep_sub -mem`；
必要时把 `dead_time`/`gain_type`/`flag` 改成按需读取而不是全量驻留。

### 9. GTI 与 SAA 的关系未核实

SVOM 上验过 GTI 缺口全部落在南大西洋异常区，因而不必另立 SAA 掩模。GECAM
的缺口更多更长，但没验过它们落在哪。**要做的**：取一批 GTI 缺口的中点，
用 posatt 查经纬度，看是否也集中在 SAA。若不是，说明缺口另有来源（过境
安排、降压停数），曝光核算的口径要重新想。

### 10. 与已发表的 GECAM TGF 结果未做交叉验证

GECAM 有公开发表的 TGF 观测。**要做的**：找到已发表样本的时刻表，检查我们
的搜索能不能复现，像 GBM 那样做一次目录对比（`scripts/cluster/gbm_catalog_compare.py`
是现成的模板）。这是判断判据是否合理最直接的一把尺子。

### 11. 三星符合未做

A 与 B 同期在轨、C 在 2022–2024 与它们重叠。同一个 TGF 被两颗星同时看到，
既是最硬的真伪判据，也能定位。**要做的**：全量跑完后按时刻对齐三颗星的
候选表。注意三颗星的 MET 历元不同，比对必须先折回 UTC。

### 12. 代码里重复的 GTI 处理

`GtiHdu`（本 crate 与 blink_svom_grm 各一份）、`union_intervals`（blink_fermi_gbm）
做的是同一件事。现在照抄一份是为了不动正在跑全量的 crate。**要做的**：等
GECAM 稳定后把 GTI 处理提到 `blink_core` 或 `blink_algorithms`，三处合一。

### 13. 用探头数做方向：原料已存，分析未做

25 路 GRD 朝向各不相同，逐路计数的相对高低就编码了入射方向——这是 GECAM 相对
天格（4 路）和 SVOM/GRM（3 路）的第二个结构性优势，也是这次把逐路计数写进
`Signal::detectors` 的原因：**候选表落盘后事例流就不在手边，事后要补方向分析
就得重跑全量**（GECAM-C 5.8 TB、GECAM-B 110 TB），所以哪怕分析还没开工，
向量也得当场存。

**原料。** CALDB 里有现成的方向相关蒙卡响应：
`/gecamfs/soft/CALDB/data/gecam-{a,b}/grd/bcf/mc_rsp/gamma_T{θ}_P{φ}/bg{01..25}_x_*.rsp`，
401 个方向 × 25 路，每个是标准 OGIP 响应（300 入射能 × 1080 道）。目录名里的
T/P 是星体坐标系下的天顶角与方位角，六位定点（`T002306` = 23.06°）。
CPD 有同样一套。GECAM-C 的 CALDB 在同一棵树下（`log_HEBS.txt`）。

**分两档做。**

*第一档，不需要姿态，也不需要响应矩阵。* 拿闪电证实的 TGF 样本，看它们点亮
的是哪几路，和本底的逐路分布比。朝地的那几路会系统性地亮——这等于用数据
自己标出"哪边是地球"，绕开了第 5 条那个没核实的四元数约定。有了这条，
"从天上来还是从地球来"就能判，而这正是 TGF 与 GRB、TGF 与 TEB 的分界，也正是
天格上卡住的那个问题（那 51 个毫秒级软暴至今说不清是什么）。

*第二档，完整定位。* 用 `mc_rsp` 对 401 个方向逐一算期望计数向量，与实测
向量做泊松似然比，得到方向和误差圆。再结合卫星位置和 TGF 产生高度（约 15 km）
投影到地面，就能给出源的地面足迹——**那样闪电关联就从"800 km 半径内"变成
"落不落在误差圆里"，是强得多的判据**。这一档需要先解决第 5 条：把星体坐标系
和四元数约定核实清楚，否则 T/P 折不到地固系。

**要做的**（按顺序）：先攒出闪电证实样本 → 第一档的逐路分布对比 → 核实姿态
约定 → 第二档似然定位。第一档在有样本之后就能做，不依赖任何未决项。
### 14. 候选数比配置的假阳性率高四个数量级：根因已定位，判据还没定标

**现象。** GECAM-C 单日（2023-06-15）全量搜索出 **3385 个候选**，而
`false_positive_per_year = 20` 一天该有 0.055 个，差四个数量级。

**排除掉的解释**（都是实测）：本底估计不稳——局部率与搜索本底率的中位比是
1.00，没有一个候选差到 2 倍；假阳性公式算错——`sf × trials` 与报出的 `fa`
精确吻合。

**根因：带电粒子穿过整台仪器，泊松独立性被破坏。** 把最显著那个候选的原始
光子打出来：窗长 0.15 µs、12 个计数，其中 **7 路不同探头在同一个时戳
（dt = 0.9835 µs）上各响一个**；第二显著的候选是 6 路同戳。定量：
**97.3% 的候选窗内含同戳簇**（3295/3385），参与同戳簇的事例占比中位 0.625，
最长同戳串中位 3、最大 9。CPD 在 ±10 µs 内有计数的候选占 **14.1%**，
纯本底该是 3.4%。

**离线判据（`scripts/cluster/gecam_features.py` 的 `multiplet_frac`）。**
量的是参与任何同戳簇的事例占比，不是最长的那一串——GECAM 有 12 路（A/B 25 路），
一个窗里往往有几个各自独立的小簇，最长串只有 2、除以 8 就成了 0.25，看着像
不同戳。阈值有个理论锚点：时戳量化约 0.03 µs，8 个计数落在 84 µs 窗里偶然
撞上一对的概率只有 1.0%，而偶然撞一对给出的占比正好 2/8 = 0.25，所以
0.25–0.3 是"偶然"与"结构"的分界。切完剩 **528 个/天**（`≤ 0.3`，15.60%）
或 473 个（`≤ 0.25`），恰好为 0 的只有 90 个。

**这条判据经过一轮正规检验：有效，但不充分。**（GECAM-C 2023-06-15，
3385 个候选；判据量是「候选窗 ±half 内有没有 CPD 计数」的**观测/期望**，
期望按当地实测 CPD 率算 `μ = r·(bin + 2·half)`、逐候选求 `Σ(1−e^−μ)`。）

*方法自检先过。* 两组零假设对照，同一套机器：把每个候选窗整体平移 ±0.2/±0.5 s
（窗长不变，13540 次），obs/exp = 1.008 / 1.004 / 0.987 / 1.005（±10 µs /
±100 µs / ±1 ms / ±10 ms），|z| ≤ 1.4；GTI 内均匀抽时刻、窗长从候选分布抽
（13540 次），1.009 / 1.002 / 1.001 / 1.003。**CPD 与 GRD 没有共同读出假象，
期望值算法无偏。**

*有效。* ±10 µs 口径的 obs/exp，幸存 / 被切：

| bin_us | 幸存 | 被切 | z |
|---|---|---|---|
| < 10 | 1.37 | 16.08 | −7.18 |
| 10–50 | 2.58 | 12.08 | −4.51 |
| 50–200 | 3.13 | 8.84 | −6.29 |
| 200–1000 | 1.83 | 3.35 | −2.95 |
| 合计 | 1.90 | 8.40 | −14.89 |

四个窗长箱**没有一个是反的**，±100 µs 同样。收紧 `fa` 时两边一起动，幸存者
1.90 → 2.37（fa ≤ 1e-3），被切者 8.40 → 21.18，**分离在扩大不是缩小**。
判据把 CPD 可见的紧符合粒子签名压掉约 **4.4 倍**。

*不充分。* 扣掉高粒子环境（CPD 本底率 > 500 c/s，占幸存者 14%，全样本只有
4.1%）之后，幸存者的 ±10 µs 超出反而升到 **2.92**；再按 fa 收紧，`fa ≤ 0.01`
的 18 个低本底幸存者里 3 个在 ±10 µs 内有 CPD 计数、期望 0.23，
P(≥3|0.23) ≈ 0.2%。样本只有 3 个事例，但方向明确：**显著端的幸存者仍有约
15–20% 是粒子。** 残留份额上限 ≤ 12%（±10 µs 口径）/ ≤ 30%（±100 µs）。
**这条判据有效但不能单独用。**

*拆成跨探头同戳救不回来。* `xdet_frac`（只算跨探头同戳）在同样阈值下幸存者
多一倍（923 vs 528）而 obs/exp 反而更高（2.00 vs 1.90）；即使要求窗内一对
跨探头同戳都没有（293 个），残留还有 1.80。**残留不是定义粗造成的，
`multiplet_frac` 的定义不用改。**

*但它对「亮而长的粒子暴」系统性失效，这是个真的失效模式。* `multiplet_frac`
是个占比，分母是窗内计数，所以会被计数稀释：2023-06-15T14:08:35–14:08:59
那 0.63 s 里搜出 22 个重叠候选，个个 n ≈ 68、窗长约 980 µs（顶到 1 ms 上限）、
**12 路探头全亮**、CPD 命中率 **100%**、`pi_ratio` **1.03**（谱与本底完全重合），
`mf ≤ 0.3` 全部放行；同日 22:51:16 还有一个同型的。粒子暴越亮越长，越容易
从这条判据下漏过去，而那正是显著端。

*配套的第二道判据（新）*：**CPD 本底环境率 ≤ 500 c/s**。±10 ms 口径的那个
反常（幸存者 1.45）**100% 来自高本底环境的候选**，扣掉后降到 1.02，一点不剩。

*谱比的问题还在，而且判据帮倒忙。* 幸存者 `pi_ratio` 中位 1.25、被切者 1.38、
全样本 1.36——**切完之后样本反而变软了**，与 TGF 该有的方向相反（天格短硬暴
是 3.0）。这条没有解释，只能等闪电关联来判。

**两条已经证伪的路子，记下来免得重走：**

1. **把同戳数按偶然撞车期望归一化**（`期望对数 = n(n−1)/2·q/W`）当判据——
   坏统计量。窗长到亚微秒时槽位数 `W/q` 少于事例数，生日问题饱和，比值把
   选择整个倒过来：它优先留下「0.1 µs 窗内 8–12 个计数、点亮 7–11 路探头」
   这种最典型的粒子穿越。亚微秒窗里撞车本来就该发生，按偶然期望归一化在
   那一档没有分辨力。
2. **最小窗长判据**——白搭。亚微秒候选（365 个，10.8%）的 `mf` 中位是 0.875，
   早被 `mf ≤ 0.3` 切光了，再加 `bin ≥ 10 µs` 只从 528 减到 520。不要动
   `min_duration`。

**一条方法上的纪律：任何按 `fa` 分层的统计都要先做 episode 去重。** 3385 个
候选按 1 s 聚簇只是 3114 个 episode，减少 8%——但最大的两个 episode 各含 22
和 10 个重叠候选、都是粒子暴，**它们能把显著端的统计整个带偏**（先前据此
误得出「fa ≤ 0.01 的幸存者 CPD 命中 9 个、期望 0.6」，去重后是 5 个、
正规期望 6.25）。每簇取最显著的一个代表。

**另一条已经证伪的机制假说**：「擦边入射的粒子只穿一两路探头，表现为单路
大沉积 + 余辉/堆积，跨探头同戳为零因而漏过判据」。否证：幸存者的
`det_frac_max` 中位在**每一个 fa 档上都是 0.250**，p90 ≤ 0.404，`fa ≤ 0.01`
的幸存者里没有一个 ≥ 0.6；被切侧中位同样是 0.250。单路集中这个形态在
幸存者里根本不存在。**顺带**：这也说明 `MAX_DETECTOR_FRACTION = 0.8` 那条
单路毛刺判据在 GECAM-C 上等于空转——全样本 `det_frac_max` 的 p90 才 0.375，
根本没有东西给它拦。别以为它在干活。

**要做的**：

* **闪电反标定**：拿 WWLLN 证实的候选看它们在 `multiplet_frac` 上怎么分布。
  这是外部真值，比任何内部一致性都硬。正确问法是「证实样本的分布长什么样」，
  不是「阈值切完还剩几个关联」——若证实样本的分布与全样本无差别，说明同戳量
  根本不携带真伪信息，那也是结论。
* **CPD 判据的定标主战场移到 GECAM-B**：8 路 CPD 对 25 路 GRD，而 C 星只有
  2 路对 12 路，14.1% 的命中率天生偏低、分辨力弱，在 C 星上调阈值是在跟统计
  噪声较劲。B 星定出来的判据再回头套 C 星。

**在闪电反标定给出答案之前，同戳量只是离线分析量，Rust 搜索侧一个字不动。**

**一个还没评估的替代方案**（比候选级否决干净，但改的是搜索语义，要先获批）：
不在候选级否决，而在**事例流层面把同戳的跨探头计数并成一个事例**再交给搜索。
一次粒子穿越在泊松意义上本来就是一个事件，并了之后独立性从源头恢复，本底
估计也跟着一致地修正；而 TGF 的光子彼此独立，落进同一个 0.03 µs 格子的很少，
代价很小。这条没有实测支撑，只是设计上的判断。

### 15. GECAM-A 的标定库停在 2022-01-14 之前的生成器（加载器已放行）

标定库 readme 原话：`v0.9 pi：最后50道超高不再从read_highlow_threshold_kev
读取并计算，而是直接填0`；`2022-01-14 软件重大更新。之前50道超高都赋值0，
现在下阈改为4096道对应的能量；上阈改为20MeV`。GECAM-B/C 跟进了新版，
**GECAM-A 的 `pi/` 只有 2023-01-10 那一版，一直在用旧生成器**，所以 A 星
全部 4,609 小时的 ch448 `E_MAX` 都是 0.0 而不是 20000——实测 9 个 epoch
横跨 2022-10 到 2026-06、24 个文件无一例外。

原来那条"`E_MAX` 必须是 20000"的溢出道校验因此把 A 星整颗星拒之门外
（试跑 2024-01-11：3 小时 `corrupt_data` + 21 小时 `missing_data`，
搜索小时数为零）。现在两个哨兵值都放行；道 0..447 的连续性、头尾、
40 keV 落在 ch54 这几条一条没松，A 星与 B 星那把梯子逐道完全一致、全程都过。

**还没做的**：A 星的 `c2e`（能量刻度）只有 9 个 epoch——1971/01/01 那份默认，
加 2025/01..04 和 2026/03..06。**2022-10 .. 2024-12 完全没有在轨 EC**，
而这段正是 A 星唯一落在 WWLLN 覆盖内的部分；2025-05 .. 2026-02 也是空的。
对照 GECAM-B 的 `c2e` 有 67 个 epoch、2020-12 发射后立刻起一路密集到 2026-06。
判据只用道号（`54 <= PI < 448`），所以这是能阈口径的系统误差而不是正确性
问题，但幅度要量：拿 LaBr₃ 的 ¹³⁸La 内禀本底线（约 1470 keV，落在 ch300
附近）分增益档、逐 25 路量峰位，看 2022-2024 段相对 2025-06 有 EC 的段移了
多少、往哪边移，折成 keV 报 ch54 实际落在哪；同时比两段的 `PI >= 448` 占比。
`mc_rsp`（401 方向 × 25 路）倒是齐全的，所以第 13 条的定位那一档 A 星不缺原料。

### 16. GECAM-A 在 2025 年之前没有 CPD 事例产品

不是缺几天，是 `CPD_evt` 目录根本不存在：2023-06-16 / 2024-01-11 / 2024-09-06 /

**后果**：A 星在 WWLLN 覆盖内的那 647 小时，`Signal::acd` 全零，**CPD 粒子

### 17. 双增益重复计数（已修，2026-09-10）

**同一个物理光子会被 ADC 的两个增益支路各写一行。** 实测 GECAM-C
2023-06-15 12h 全 12 路 GRD：

* 同探头同时戳的事例对占原始事例 **6.635%**（EVENTS01 单路 7.855%）
* 这些对 **100%** 是 `GAIN_TYPE` 一高一低，PI 相同的占 **0%**
  （高增益那条中位 448 = 溢出道，低增益那条中位 377）
* `FLAG` 组合 **100%** 是 (0,10) 或 (10,0)
* `EVT_PAIR` 是 (N,2) 的布尔列，同戳对两端 **100%** 为真，
  非同戳事例只有 5.0% 为真

多数时候高增益那条已经饱和进溢出道、被 `Event::keep` 的 `PI < 448` 挡掉，
一个物理事例只剩一条（占 98.8%）。**但剩下的 1.2% 两条都过了准入**，于是
约 **3.25%** 的准入后计数是重复计数——而候选窗内这个比例是 **6.82%**，
富集 2.1 倍，**50.4% 的候选窗里至少含一对重复**。两条记录时戳完全相同，
泊松独立性直接破掉，跟带电粒子跨探头同时点亮是同一类机制，只是发生在
一路探头内部。

粗估影响（把每个候选的 `count` 扣掉同探头同戳的多余事例、本底率同步降
3.25%，用 (count, mean, fa) 反标定试验数 T ≈ 9.6e9 后重算 `fa`；
**这是近似，T 的四分位有 ±20% 散布**）：

| `fa` 阈 | 修前 | 修后 |
|---|---|---|
| ≤ 20 | 3385 | 2435（剩 72%） |
| ≤ 1 | 1707 | 1337（剩 78%） |
| ≤ 0.01 | 896 | 732（剩 82%） |

**约 28% 的候选是双增益重复计数造出来的。**

**修法**：`search` 里在 `events.sort()` 之后加一道 `dedupe_gain_pairs`——
同一路探头、同一时戳的两条并成一条，**保留低增益那条**（高增益支路会饱和，
低增益那条永远是有效测量）。判据用「同探头同时戳」这个实测事实，不用
`EVT_PAIR` 那一列：实测 `EVT_PAIR` 为真的事例占 19.9% 而同戳对只占 7.9%，
两者对不上（伴侣可能被上游过滤掉、或差一个时戳格），语义没核实清楚之前
不拿它当判据。并掉的条数记在 `merged_gain_duplicates` 诊断量里，不静默。

**还没做的**：

* **两档的 PI 是不是同一把尺子没有核实。** 先前记的是「两档共用同一套 PI
  刻度，所以道号可以直接比」，但实测双增益对里 PI 相同的占 0%。这个 0% 有
  可能全是「高增益已饱和」造成的（饱和条一律 448），也有可能两档本来就是
  两把尺子。**要做的**：只取高增益条 PI < 448（没饱和）的那些对，看两档的
  PI 差怎么分布。若两档不是同一把尺子，`MIN_CHANNEL = 54` 在两档里就是两个
  能量，去重留哪条会改变能阈，而不只是改变计数。
* **这个修正之前跑出来的所有 GECAM 结果都要重跑**，包括 GECAM-C 的 30 天
  和已经落盘的特征表。
* GECAM-A / GECAM-B 上的重复率没有量过，只在 C 星实测。A/B 是 25 路 GRD，
  比例未必一样。

### 18. 时戳量化步长是 2⁻²⁶ s（已答，2026-09-10）

实测 **1.49012e−8 s = 2⁻²⁶ s ≈ 14.9 ns**，不是先前记的 0.03 µs。
`min_dt_us` 的非零取值全是它的整数倍：1–5 倍是 0.015 / 0.030 / 0.045 /
0.060 / 0.075（三位小数四舍五入），6 倍 0.0894、7 倍 0.1043——**后两个不是
0.015 的整数倍，正说明真值略小于 0.015**。天格是 2⁻²² s = 0.2384 µs，
同一个族（都是 2 的负整数次幂秒）。

这个常数会传进任何「偶然同戳」的期望计算，差 0.7% 就传进判据，所以钉死。
第 14 条那个「8 个计数落在 84 µs 窗里偶然撞上一对的概率 1.0%」的锚点要按
14.9 ns 重算（大致减半）；「撞一对给出的占比正好 2/8 = 0.25」这一条不受影响。
