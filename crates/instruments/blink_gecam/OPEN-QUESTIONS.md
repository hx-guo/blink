# GECAM —— 已核实的事实与未决的问题

本文件记录 GECAM 三颗星接入 TGF 搜索时实地核对过的结论，以及还没做、
还没定标的部分。凡是"实测"字样，都指在 IHEP 集群上对归档文件直接统计的结果，
日期见各条。

## 一、三颗星与数据量（2026-09-10 勘测）

|---|---|---|---|
| 探头 | 25 GRD + 8 CPD | 25 GRD + 8 CPD | 12 GRD + 2 CPD |
| MET 历元 | 2019-01-01（MJDREFI 58484） | 同 A | 2021-01-01（59215） |
| 事例产品起止 | 2022-10-21 .. 2026 | 2020-12 .. 2026-09 | 2022-07 .. 2025-02 |
| 有数据的天 | 554 | 约 2100 | 818 |

| 单小时 | 974 MB / 5410 万事例 | 2.7 GB / 1.49 亿事例 | 297 MB / 1650 万事例 |
| 合计 | 约 4.5 TB | 约 110 TB | 约 5.8 TB |

GECAM-A 逐年的 GRD 小时文件数是 3 / 287 / 481 / 2693 / 1145（2022..2026），
**绝大多数在 2025 年以后**，落在 WWLLN 库（止于 2024-12-31）之外；2024 年底
之前只有 771 小时。GECAM-C 逐年 3228 / 8198 / 7419 / 779 小时（2022..2025），

归档路径：A/B 在 `/gecamfs/Archived-DATA/GSDC/LEVEL1/daily/{yyyy}/{mm}/{dd}/GECAM_{A,B}/`，

## 二、文件格式（三颗星一致）

逐小时 FITS：`PRIMARY` + `EBOUNDS` + `GTI` + 每探头一个 `EVENTS%02d`。
GRD 事例列 `TIME, PI, GAIN_TYPE, DEAD_TIME, EVT_TYPE, FLAG, EVT_PAIR`，
CPD 少 `GAIN_TYPE` 和 `EVT_PAIR`。整套结构与 SVOM/GRM 同源，`blink_svom_grm`
就是本 crate 的模板。

**能量梯。** EBOUNDS 的道 0..447 是一条连续单调的梯，2.00 keV 到 10053.5 keV，
相邻道 `E_MIN[k+1] == E_MAX[k]`，每道宽约 1.34%（低端疏、高端密，不是均匀对数：
ch0 = 2.0–2.2、ch50 = 35.0–36.0、ch54 = 39.1–40.2、ch100 = 100.1–101.8、
ch200 = 373.9–378.9 keV）。**B 与 C 逐道数值完全一致**，所以道号阈值三星通用；
但这是实测结论不是设计保证，`EvtFile` 载入时逐条核对（头尾、梯内连续性、
40 keV 是否仍落在 ch54），对不上就整小时报错。

**溢出道。** 道 448 及以上 `E_MAX` 一律 20000 keV、`E_MIN` 不单调（每探头每
增益档各占一行，B 有 50 行、C 有 22 行），能量不可信。实测 `EVT_TYPE == 2`
的事例 PI 正好全落在这一段（B 某小时单路 6.00%、C 15.11%）。

**增益。** `GAIN_TYPE` 0 高 / 1 低，两档共用同一套 PI 刻度（C 实测高增益
PI 11..448、低增益 179..460），所以道号可以直接比，不必分档处理。

**位姿。** `Orbit_Attitude` 表 1 Hz、一小时 3700 点（越过整点约 100 s）。位置
只给地固系直角坐标 `X/Y/Z_WGS84`，**单位是米**（|r| 实测 B 6.963–6.974e6、
C 6.855–6.870e6），要自己折成经纬高，见 `io::geodetic`。四元数模为 1。

**GTI 占空比低。** 抽查 GECAM-C 某小时 GTI 只有 1763 s / 3700 s（切成 4 段）、
GECAM-A 某小时 1303 s / 3600 s（1 段）。曝光按 GTI 算，事例流也按同一份 GTI
过滤——SVOM/GRM 上只在分母上用 GTI 而事例照单全收，缺口两端半秒数据的本底窗
伸进空区，造出过整整两类假信号。

## 三、当前判据

* 事例准入（`Event::keep`）：`EVT_TYPE == 1` 且 `54 <= PI < 448`。
* GTI 同时用于分子（事例过滤）与分母（曝光）。
* 单路探测器占比 > 0.8 的候选否决，按整候选窗算，四台仪器共用
  `blink_algorithms::detector_share`。
* 搜索窗 0 .. 1 ms，`false_positive_per_year = 20`，`min_number = 8`，
  `coincidence = 1`（各路 GRD 朝向不同，合成一路）。
* CPD 计数随每个候选记录在 `Signal::acd` 里（`AcdCounts` 的字段在 GECAM 上的
  含义见 `chunk::search::cpd_counts` 的文档注释）——**只统计，不否决**。
* 逐路 GRD 计数（候选窗与基线窗各一份）记录在 `Signal::detectors` 里，见
  `blink_core::DetectorCounts` 与下面第 13 条——同样是**只统计，不判**。

## 四、未决的问题

### 1. 能阈 40 keV 没有用 GECAM 自己的 TGF 定标

`MIN_CHANNEL = 54`（39.1–40.2 keV）是照 SVOM/GRM 的量级取的起点。SVOM 那个
42 keV 是拿 72 个闪电证实的 TGF 扫出来的：证实样本的窗内谱在更低的道上一律
低于本底、从 42 keV 起才反超，切在那里少 15% 信号、少 43% 本底，信噪反升。
GECAM 是 LaBr₃、能量梯一路到 10 MeV，谱学响应不同，这条结论不能直接搬。
**要做的**：等 GECAM 攒出闪电证实样本后按同样办法重扫，脚本可照
`scripts/plot_svom_threshold.py` 改。

### 2. CPD 判据未定标

CPD 是 GECAM 相对天格/SVOM 最大的优势——一路独立的带电粒子探测器，可以直接
回答"这个候选是不是粒子"。但"符合到什么程度算粒子"没有数据支撑，所以现在
只把计数存下来（`n_acd`、`n_acd_multi`、`n_acd_bg`），不做否决。
**要做的**：全量跑完后拿真候选看 `n_acd/n` 的分布，看它与闪电关联率的关系，
再定阈值。存原始计数而不是比例就是为了这一步能复议而不必重跑。

顺带：天格那 51 个"毫秒级软暴"至今说不清是什么（谱与本底重合、高磁纬、
无闪电、不成串）。如果 GECAM 上能找到同类事件，CPD 可以一次性回答它们
是不是带电粒子。这是做 GECAM 的一个主要动机。

### 3. `EVT_TYPE == 3` 稀有到无关紧要（已答，2026-09-10）

抽 GECAM-C 三个不同月份的整点小时：

```
2022-08-15 03h  事例 227,843,552  type3 =  2  (0.0000%)
2023-01-30 07h  事例  23,239,879  type3 = 24  (0.0001%)
2023-06-15 12h  事例  19,966,568  type3 = 13  (0.0001%)
```

性质三个小时高度一致：**PI 全部落在 `keep` 窗 [54, 448) 内**（中位 170–415，
`>= 448` 占 0%）、`GAIN_TYPE` 全是 0（高增益）、`FLAG` 全是 0、散在 3–4 路
探头上、时间不成簇（相邻间隔中位 27–590 s，`< 1 ms` 占 0%）、GTI 内占 50–85%。

**每小时整仪器只有个位到二十几个，占事例的 1e-6 量级**，一天全仪器约 300 个
摊在 12 路 × 86400 s 上。能量、增益、标志、成簇性都看不出是什么特殊物态，
但量级上不值得再追。**`keep` 只认 1 不改。**

顺带一条已经实测钉死的：**`PI >= 448` 的占比与 `EVT_TYPE == 2` 的占比逐日
逐位完全相同**（GECAM-A 7 个 epoch 全部），所以两者不是包含关系，**是同一个
集合**——第二节里原来写的"`EVT_TYPE == 2` 的事例 PI 正好全落在这一段"可以
加强成这一条。GECAM-C 上同样自洽：那三个小时 `EVT_TYPE == 2` 占 11.9–17.3%，
而 `type3` 的 PI 全 < 448、`type1` 的分布也没有溢出，448 以上全归 `type2`。
`Event::keep` 里那两条冗余判据照旧都留着——**但它们否的都是同一批事例，
真正缺的上界见第 19 条。**

### 4. `FLAG` 标的是双增益对里的角色（已答，2026-09-10）

实测 GECAM-B 某小时单路 `FLAG` 只有 0（89.98%）和 10（10.02%）两个取值，
FLAG=10 的 PI 中位是 448、与溢出道重合，先前记的是「看着像溢出标志」。
拆双增益重复记录时拿到了答案：**同一路探头同一时戳的事例对，`FLAG` 组合
100% 是 (0,10) 或 (10,0)**——它标的是这条记录在双增益对里是哪一支，
「FLAG=10 的 PI 中位是 448」只是「高增益那支常常饱和」的表象。

判据没有用 `FLAG`，也不打算用：去重走的是「同探头同时戳」这个实测事实，
见第 17 条。

### 4b. 审计的基线窗不是搜索的本底窗（已改注释，窗不动）

`cpd_counts` 与 `detector_counts` 取的基线是候选两侧各
`CPD_BASELINE_SECONDS = 1 s`，而 `search_new` 用的是两侧各 `neighbor / 2`
= **0.5 s**——**审计窗正好是搜索窗的两倍宽**。原注释写的是"与搜索的
`neighbor` 同一量级"，是错的。除此之外还差两件事：**审计不挖空窗**
（搜索从本底里挖掉候选两侧各 `hollow / 2` = 5 ms），**审计不夹 GTI**
（搜索把本底窗夹到候选所在的那段活时间里再算时长，审计的
`baseline_seconds` 是标称的 2 s、不是活时间）。

**后果**：`n_acd_bg / baseline_seconds` 只有在本底率**平稳且窗内没有 GTI
缺口**时才是"该候选处的 CPD 率"。GECAM 的候选恰恰常落在率剧变的地方
（GTI 边界、高磁纬进出、粒子增强期），而 GECAM 的 GTI 一小时常被切成
一到四段——**窗跨了缺口就低估率，跟着高估任何「观测/期望」的超出**。
第 14 条里那些 obs/exp 的数如果是用这个标称分母折的率算的，方向就是
偏大的一侧；要准得回 CPD 事例流按活时间自己数。**另外不能拿这些计数去
反推搜索的 `mean`，会差两倍。**

**实测偏差在 GECAM-C 上可忽略，但要按仪器分别量。** 3385 个候选逐条比
「基线窗与 GTI 的交集时长」和标称 1.98 s：`t_bg` 中位 1.9800、1–95 分位
全是 1.98，**只有 0.38%（13 个）被 GTI 切到**（那 13 个 `t_bg` 中位 1.137 s、
朴素法把率低估中位 1.74 倍）。全样本 obs/exp 正确 3.533 对朴素 3.535，
**差 0.1%**；判据链那条 `CPD 本底率 ≤ 500 c/s` 两种算法各留 3246 个、
**逐条不一致的 0 个**。所以 C 星现有的 obs/exp 不用改。**但 C 星占空比
62.7%、缺口中位 393 s（长而稀），贴边的候选才少；GECAM-B 的 GTI 切得更碎，
那边必须重新量。**

**正确的做法是分子分母都夹 GTI**（`evidence/gecam-c/gc_cpd_norm.py` 就是
这么做的）：本底事例按 GTI 过滤，分母取「基线窗与 GTI 的交集时长」而不是
标称窗宽；两个零假设对照（平移窗 + GTI 内随机时刻，各 13540 次）在四个
符合半宽上都回到 obs/exp = 1.00 ± 0.4%，**随机对照必然抽到贴边位置，
回得到 1.00 说明分母没有在 GTI 边界上系统性虚低**。

**决定：不改窗，只把话说清楚。** 两倍窗给的统计量更多、更稳，而改窗会让
已经落盘的候选表前后不可比。关系钉在
`the_audit_baseline_window_is_twice_the_search_one` 这条测试里。

### 4c. 探头级停机：GTI 不表达，只有逐路基线看得见

GTI 是**全仪器**概念。25 路里掉一路，仪器照样"活着"，只是有效面积在变，
而 `mean` 的分母不会跟着改、`fa` 就偏低。HXMT 那边查明的机制是**整个机箱
静默好几秒**（不是 30 ms 级短缺口），停摆前每 100 ms 的计数被顶到上限
约 972 的 FIFO 饱和平台，三个箱先后停摆，逐路基线向量给出的
`111111000000000000` 一字不差对上时序。**他们的全量还没跑完，87 个样本里
83 个是列车成员、可能早被摘掉，所以这在 HXMT 上还不是已确认的缺陷。**

GECAM 25 路 / 12 路同理，而我们已经把逐路基线向量存进 `Signal::detectors`
了，**查这个几乎零成本**。**GECAM-C 未观察到**（2023-06-15 全部 3385 个候选、12 路基线向量）：有零格
的候选 **0 / 3385**，逐路零格次数全 0，基线计数分位 1/5/50/95 =
64 / 507 / 1069（最低的 1% 也有 64 个计数 / 2 s，离零很远）。
**记成「未观察到」而不是「不存在」——只有一天。**

**还要做的**：GECAM-A（25 路）与 GECAM-B（25 路）上同样统计一遍，路数多一倍，掉一路的概率更高。

### 5. 姿态四元数的分量顺序未核实

表里是 `Q1..Q4`，`blink_core::Attitude` 只收三个分量，现在原样取前三个。
标量分量到底在 Q1 还是 Q4 没有核实。姿态目前只作元数据随候选记录、不参与
任何判据，所以不影响搜索结果；但**做流强/光子谱就会卡在这里**——SVOM 上
就是卡在同一个问题上（响应矩阵要靠姿态定入射方向）。

### 6. `min_number = 8` 比已发表样本低了整整一档

GECAM-B 单路 GRD 实测约 894 c/s，25 路合计约 22 kc/s（能阈过滤前）；
SVOM/GRM 三路合计不到 1 kc/s。`min_number` 是计数下限，本底高时基本不起
作用（泊松判据先绑定）。

**已发表目录给了一把尺子**（见第 10 条）：147 个真 TGF 的 `NetCounts`
中位 **66.9**、5–95% 21.2–185、最小 8.7，**只有 3.4% 少于 20 计数**。
而我们 GECAM-C 一天的候选计数中位 **10**、只有 10.4% ≥ 21。**我们的阈值比
已发表样本低了整整一档，也就是说我们和他们不是在找同一批东西。** 这解释了
候选量超出的一部分，但不是全部——见第 14 条的验收线。

**要做的**：先做第 14 条里那个零成本实验（把已落盘的候选按等效显著性阈切
一刀），再决定 `min_number` 要不要动。

### 7. 窗长上限 1 ms：两个已发表目录给出相反的证据，**不要关掉**

沿用 SVOM/GRM 的 1 ms。SVOM 上验过 5 ms：候选多 47% 而闪电关联数为纯本底，
82 个证实 TGF 一个不多一个不少。

**支持 1 ms 够用的**：已发表的 GECAM TGF 目录（第 10 条）147 个事件的
`Duration_us` 中位 179.5 µs、95% 分位 372、**最大 670.9，100% 短于 1 ms**。

**反对的**：Fermi/GBM 那一路拿已发表 GBM 目录做完备性检验，**时长 > 1 ms
的那一档找到率只有 82.9%、达显著 43.9%**，而 < 0.5 ms 那档是 98.0% / 79.7%——
直接对应 `max_duration: 1 ms` 的损失。

**两者不矛盾，但要先对齐口径才能判**，至少三种解释：

* **时长定义不同。** GECAM 目录的 `Duration_us` 是 **Bayesian Block 块长**，
  不是 T90，也不是半高全宽；GBM 目录那一列是什么口径还没核。BB 与 T90 在
  低计数下的偏向方向不同，不能直接比。
* **选择效应不同。** GECAM 那 147 个是触发式样本、判据严到 P < 2e-21，
  **亮而短的容易入选，长事件通常暗、会被系统性丢掉**——所以"100% 短于
  1 ms"不能读成"TGF 都短于 1 ms"，它跟 GBM 找到更长的一批是自洽的。
* **仪器真看到不同的东西。** GBM 有效面积大得多，探得到更长更暗的一批。

**要做的**：核实两个目录各自的时长定义，口径对齐后再判。**如果长事件是
真的，1 ms 上限就是四个仪器共同的已知损失**，该写进每一路的记录，而不是
某一路单独关掉它。GECAM 自己的复核要等闪电证实样本攒出来后量 T90，同
SVOM 的办法。

### 8. GECAM-B 的内存与总量（已实测，2026-09-10）

**总量是 35.8 TB，不是 110 TB。** 逐文件 `find -printf "%s %p"` 实测：
GRD `.fits` 共 52,766 个（含全部版本 65.6 TB）；**每小时取最大版本后
26,761 小时 / 35.80 TB**，版本冗余占 43%、搜索一个都不读；再要求
GRD+CPD+posatt 三件齐全（`from_epoch` 的硬条件），**可搜 26,751 小时 /
35.78 TB**，只有 10 个小时缺件。原来那个 110 TB 是拿「52,700 × 2.7 GB」
外推的，而 **2.7 GB / 1.49 亿事例那个小时是 p93 不是典型小时**：去重后单
小时中位 1.23 GB（约 6,800 万事例）、均值 1.34 GB、p95 2.91 GB、最大
11.9 GB（约 6.6 亿事例）。事例行 `D,I,B,E,B,B,B` = 18 B，与 2.7 GB / 1.49 亿
= 18.1 B/事例 相符，所以字节数可以直接折事例数。

**逐日覆盖 1,813 天、平均 14.76 小时/天，只有 262 天是满 24 小时。**
26,751 可搜小时折合 1,115 个满天（GTI 还没扣）。逐年（去重）：2021 5,183 /
2022 6,901 / 2023 3,872 / 2024 3,928 / 2025 5,852 / 2026 1,024 小时。
**WWLLN 覆盖内（2021–2024）19,884 小时 / 27.6 TB，占 74%**——CPD 判据定标
（第 2 条）能用的就是这一段。

**峰值内存实测**（作业 81204578，1 s 采样 `VmHWM` 并记录当时打开的 FITS
路径，所以每个采样点能归到具体小时）：典型小时 1.1 GB 文件 → 峰值 2.15 GB，
1.5 GB 文件 → 3.18 GB，**全归档第三大的 11.1 GB 小时 → 峰值 20.37 GB，
没被 OOM**。峰值/文件字节约 **1.84–2.1**。载入 1.1 GB 约 5 s（约 220 MB/s），
整小时墙钟约 100 s——**时间花在搜索不在 I/O**。

一个作业跑一整天时内存由那天最大的小时定：day-max 中位 1.84 GB（→ 约
3.8 GB RSS）、p90 3.52 GB（→ 约 7 GB）、p99 8.21 GB（→ 约 16 GB）、最大
11.90 GB（→ 约 22 GB）。所以 **`-mem 25000` 一档覆盖全部 1,813 天**；想省
资源可分两档：`-mem 12000` 覆盖 day-max ≤ 5.7 GB 的 1,734 天（95.6%），
余下 79 天单独用 `-mem 25000`。

**`RAYON_NUM_THREADS` 是空设置。** `rayon` 在本仓库零命中（连 `Cargo.lock`
里都没有这个包）。串行链：`blink/src/main.rs` → `blink_search::process` →
`blink_workflow` 的 `for day_offset in 0..total_days` 裸循环 →
`blink_search` 的 `for hour in 0..24` 裸循环。**一个进程同一时刻只驻留一
小时**，所以上面那些峰值就是单进程峰值，作业脚本里那行 `export
RAYON_NUM_THREADS=2` 什么也没做。

**HHMMSS 命名的文件（已修）。** 2021 年有 2,384 个 GRD 文件把小时字段写成
HHMMSS（`gbg_evt_210228_190000_v00.fits`），而 `io/file.rs` 原来拼的是
`..._19_v`，`starts_with` 匹不上，这批文件对搜索不存在。按小时去重后这种
写法覆盖 1,559 小时，其中 **102 小时是独苗**（分布在 32 天、全在 2021），
占 0.4%——**原本判断为"只记不改"**。

**改口的理由**：**已发表的 147 个 TGF 里有 2 个（1.4%）正落在这种小时上**
（2021-03-25 09、2021-05-02 16）。匹不上就等于连数据都读不到，完备性检验
量的就成了文件名匹配而不是搜索算法。0.4% 的曝光不值得改，1.4% 的外部真值
值得。

现在两种写法都认，三类产品一起放宽。**版本号要单独解析出来比大小，不能
靠整串文件名排序**：两种写法混在一起时 `_190000_v01` 会排在 `_07_v00`
前面（`'0' < '_'`），照字典序取最后一个就会拿到低版本。放宽也不能顺带
放宽小时——`_19` 之后只许接 `_v` 或四位数字 MMSS 再接 `_v`，三条都有测试。

### 11. 双星符合：共视曝光只有 6 小时，不是一条产线

先前记的是"A 与 B 同期在轨、C 在 2022–2024 与它们重叠，同一个 TGF 被两颗星
同时看到既是最硬的真伪判据也能定位"。**实测下来这条要大打折扣。**

**A∩B 的 GTI 重叠是 119.2 小时**（A 与 B 的 MET 历元相同，GTI 可直接比、
不必折 UTC；跟 C 星比才要折）。A 星 2022–2024 曝光 370.4 h，其中 310 个小时
B 星也有文件（47.9%、覆盖 124 天），真重叠 **119.2 h = 4.97 天**，占 A 星总
曝光的 32.2%。

**但同时刻不等于共视。** 从 posatt 的 `X/Y/Z_WGS84` 算星间距离（抽 40 个重叠
小时、10 s 一格、8,904 个采样点）：**星下点地面距离中位 7,861 km**
（5–95% 571–18,098 km）。按距离阈算时间占比：

| 星下点距离 | 时间占比 |
|---|---|
| < 400 km | 3.7% |
| **< 800 km**（TGF 可见半径常用值） | **5.2%** |
| < 1,600 km | 5.8% |
| < 3,000 km（掠射，衰减严重） | 24.8% |

这符合 GECAM 双星星座的设计——A 与 B 分布在轨道两侧才能全天覆盖，**代价就是
它们绝大多数时间看的不是同一片地球**。

**所以 WWLLN 覆盖内能做双星符合的曝光是 119.2 h × 5.2% ≈ 6.2 小时。** 按
GECAM-A 现在 10.5 候选/s 的率，那 6.2 小时里 A 就会出 23 万个候选，而真 TGF
的期望是零点几个量级——**先淹死在假候选里，判据做好了也没有统计量。**

**结论：把"双星符合"从近期路线里拿掉**，它不该跟"跑 183 天"并列，差两个
数量级。真要保留就改成一个**便宜的定向检验**而不是产线：两边都有候选表之后，
按 UTC 对齐，只看那 6.2 小时共视窗内有没有毫秒级同时的对。**有就是极硬的真
TGF 证据（假候选是各星独立的粒子，不可能跨星同时）；没有也在预期之内、不构成
任何否定。** 成本是一次表连接。

**两条限定：**

* **2025–2026 段的账不一样。** A 星那段有 3,838 个小时文件、按 57.3% 的 GTI
  折约 2,190 h 曝光，B 星那段基本满覆盖，所以共视可能到 **114 小时**，比
  WWLLN 段多 18 倍。**但那段没有闪电真值**（库止 2024-12-31），只能走
  "两星互为真值"而不是"闪电为真值"。双星符合真要做，该放到 post-2024。
* **800 km 这个阈没有 GECAM 自己的数据支撑**，属于未决。放宽到 3,000 km 是
  24.8%，但那个角度上大气衰减很重、探测效率极低，不建议拿它算可用曝光。
* **定位精度还没到能评估的地步**：就算共视，两星的方向重建误差圆（第 13 条
  第二档，还没做）能不能小到有用，不知道。

### 13. 用探头数做方向：原料已存，分析未做

25 路 GRD 朝向各不相同，逐路计数的相对高低就编码了入射方向——这是 GECAM 相对
天格（4 路）和 SVOM/GRM（3 路）的第二个结构性优势，也是这次把逐路计数写进
`Signal::detectors` 的原因：**候选表落盘后事例流就不在手边，事后要补方向分析
就得重跑全量**（GECAM-C 5.8 TB、GECAM-B 110 TB），所以哪怕分析还没开工，
向量也得当场存。

**原料。** CALDB 里有现成的方向相关蒙卡响应：
`/gecamfs/soft/CALDB/data/gecam-{a,b}/grd/bcf/mc_rsp/gamma_T{θ}_P{φ}/bg{01..25}_x_*.rsp`，
401 个方向 × 25 路，每个是标准 OGIP 响应（300 入射能 × 1080 道）。目录名里的
T/P 是星体坐标系下的天顶角与方位角，六位定点（`T002306` = 23.06°）。
CPD 有同样一套。GECAM-C 的 CALDB 在同一棵树下（`log_HEBS.txt`）。

**分两档做。**

*第一档，不需要姿态，也不需要响应矩阵。* 拿闪电证实的 TGF 样本，看它们点亮
的是哪几路，和本底的逐路分布比。朝地的那几路会系统性地亮——这等于用数据
自己标出"哪边是地球"，绕开了第 5 条那个没核实的四元数约定。有了这条，
"从天上来还是从地球来"就能判，而这正是 TGF 与 GRB、TGF 与 TEB 的分界，也正是
天格上卡住的那个问题（那 51 个毫秒级软暴至今说不清是什么）。

*第二档，完整定位。* 用 `mc_rsp` 对 401 个方向逐一算期望计数向量，与实测
向量做泊松似然比，得到方向和误差圆。再结合卫星位置和 TGF 产生高度（约 15 km）
投影到地面，就能给出源的地面足迹——**那样闪电关联就从"800 km 半径内"变成
"落不落在误差圆里"，是强得多的判据**。这一档需要先解决第 5 条：把星体坐标系
和四元数约定核实清楚，否则 T/P 折不到地固系。

**要做的**（按顺序）：先攒出闪电证实样本 → 第一档的逐路分布对比 → 核实姿态
约定 → 第二档似然定位。第一档在有样本之后就能做，不依赖任何未决项。
### 14. 候选数比配置的假阳性率高四个数量级：根因已定位，判据还没定标

**现象。** GECAM-C 单日（2023-06-15）全量搜索出 **3385 个候选**，而
`false_positive_per_year = 20` 一天该有 0.055 个，差四个数量级。

**排除掉的解释**（都是实测）：本底估计不稳——局部率与搜索本底率的中位比是
1.00，没有一个候选差到 2 倍；假阳性公式算错——`sf × trials` 与报出的 `fa`
精确吻合。

**根因：带电粒子穿过整台仪器，泊松独立性被破坏。** 把最显著那个候选的原始
光子打出来：窗长 0.15 µs、12 个计数，其中 **7 路不同探头在同一个时戳
（dt = 0.9835 µs）上各响一个**；第二显著的候选是 6 路同戳。定量：
**97.3% 的候选窗内含同戳簇**（3295/3385），参与同戳簇的事例占比中位 0.625，
最长同戳串中位 3、最大 9。CPD 在 ±10 µs 内有计数的候选占 **14.1%**，
纯本底该是 3.4%。

**离线判据（`scripts/cluster/gecam_features.py` 的 `multiplet_frac`）。**
量的是参与任何同戳簇的事例占比，不是最长的那一串——GECAM 有 12 路（A/B 25 路），
一个窗里往往有几个各自独立的小簇，最长串只有 2、除以 8 就成了 0.25，看着像
不同戳。阈值有个理论锚点：时戳量化约 0.03 µs，8 个计数落在 84 µs 窗里偶然
撞上一对的概率只有 1.0%，而偶然撞一对给出的占比正好 2/8 = 0.25，所以
0.25–0.3 是"偶然"与"结构"的分界。切完剩 **528 个/天**（`≤ 0.3`，15.60%）
或 473 个（`≤ 0.25`），恰好为 0 的只有 90 个。

> **⚠️ 2026-09-11 撤回：本节下面一整段（"有效但不充分"、判据压掉粒子
> "约 4.4 倍"、"残留粒子份额 ≤ 12% / ≤ 30%"、"显著端幸存者仍有 15–20% 是粒子"）
> 的论证依据已经不成立。** 那套论证的标签是「候选窗内 CPD 紧符合超出 ⇒ 带电
> 粒子」，而 **CPD 是塑料闪烁体、对 TGF 的伽马有真实的康普顿响应**：已发表的
> GECAM TGF 目录自带 `CPDtoGRDcountsRatio` **中位 0.040**——这是目录作者自己
> 的测量，与我们的口径无关，**说明真 TGF 在 CPD 里本来就有可观计数**。
> 所以"CPD 有超出"分不开粒子与 TGF，以它为标签得出的每一个数都失去依据。
>
> **观测事实仍然成立，失效的是解释**：四个窗长箱的 obs/exp 确实一个都不反，
> 但那不再能读成"判据在挑光子"。**方法自检那两组零假设对照（平移窗 + GTI 内
> 随机时刻，obs/exp 回到 1.00 ± 0.4%）不受牵连**——它测的是期望值算法无偏，
> 与标签对错是两回事，那部分照旧有效。
>
> **一条上升为全队规矩的教训**：任何「在否决探测器里有命中 ⇒ 是粒子」的标签，
> 必须先量出**确认的真事件**在该探测器里的响应并按它归一化；未归一化的命中率
> 一律无效。这已经是同一失效模式的第三次——GECAM 上「CPD 命中率 93%」那次
> （93% 正是那个本底率下的偶然期望）、这一次、以及 HXMT 上 ACD 判据被实测
> 证伪（对 REP 与 TGF 的响应没有差别）。
>
> **配套那条 `CPD 本底率 ≤ 500 c/s` 还有第二个毛病：阈是绝对计数率，跨星
> 不可迁移。** C 星 2 路 CPD，500 c/s 等于每路 250 c/s；B 星 8 路，照搬过去
> 等于收紧 4 倍。**要用就写成"每路 250 c/s"。**

**这条判据经过一轮正规检验：有效，但不充分。**（GECAM-C 2023-06-15，
3385 个候选；判据量是「候选窗 ±half 内有没有 CPD 计数」的**观测/期望**，
期望按当地实测 CPD 率算 `μ = r·(bin + 2·half)`、逐候选求 `Σ(1−e^−μ)`。）

*方法自检先过。* 两组零假设对照，同一套机器：把每个候选窗整体平移 ±0.2/±0.5 s
（窗长不变，13540 次），obs/exp = 1.008 / 1.004 / 0.987 / 1.005（±10 µs /
±100 µs / ±1 ms / ±10 ms），|z| ≤ 1.4；GTI 内均匀抽时刻、窗长从候选分布抽
（13540 次），1.009 / 1.002 / 1.001 / 1.003。**CPD 与 GRD 没有共同读出假象，
期望值算法无偏。**

*有效。* ±10 µs 口径的 obs/exp，幸存 / 被切：

| bin_us | 幸存 | 被切 | z |
|---|---|---|---|
| < 10 | 1.37 | 16.08 | −7.18 |
| 10–50 | 2.58 | 12.08 | −4.51 |
| 50–200 | 3.13 | 8.84 | −6.29 |
| 200–1000 | 1.83 | 3.35 | −2.95 |
| 合计 | 1.90 | 8.40 | −14.89 |

四个窗长箱**没有一个是反的**，±100 µs 同样。收紧 `fa` 时两边一起动，幸存者
1.90 → 2.37（fa ≤ 1e-3），被切者 8.40 → 21.18，**分离在扩大不是缩小**。
判据把 CPD 可见的紧符合粒子签名压掉约 **4.4 倍**。

*不充分。* 扣掉高粒子环境（CPD 本底率 > 500 c/s，占幸存者 14%，全样本只有
4.1%）之后，幸存者的 ±10 µs 超出反而升到 **2.92**；再按 fa 收紧，`fa ≤ 0.01`
的 18 个低本底幸存者里 3 个在 ±10 µs 内有 CPD 计数、期望 0.23，
P(≥3|0.23) ≈ 0.2%。样本只有 3 个事例，但方向明确：**显著端的幸存者仍有约
15–20% 是粒子。** 残留份额上限 ≤ 12%（±10 µs 口径）/ ≤ 30%（±100 µs）。
**这条判据有效但不能单独用。**

**「残留 ≤ 12%」这个数带一个大前提：它假定 CPD 的粒子标记效率就是实测的那
14.1%。** GECAM-C 只有 2 路 CPD 对 12 路 GRD，也就是说**约 86% 的粒子 CPD
根本认不出来**。所以 CPD 命中率这个指标**只在相对比较里可信（幸存者 vs
被切者、这个尺度 vs 那个尺度），绝对值不可信**，任何由它推出的"污染份额是
多少"都只是下界。等 GECAM-B 的 8 路 CPD 对 25 路上来（覆盖比约翻倍）才谈得上
定量。

**另一条口径纪律**：本节里大量结论是几十到几百个样本的比例（`0/405`、
`53/53`、`3/18`），**这些数都该带区间**——`0/405` 的 95% 置信上限是 0.74%
而不是 0。天格那个"阈 0.35、真暴最大 0.333、余量 0.017"就是余量看着有、
其实落在样本涨落之内的例子。

*拆成跨探头同戳救不回来。* `xdet_frac`（只算跨探头同戳）在同样阈值下幸存者
多一倍（923 vs 528）而 obs/exp 反而更高（2.00 vs 1.90）；即使要求窗内一对
跨探头同戳都没有（293 个），残留还有 1.80。**残留不是定义粗造成的，
`multiplet_frac` 的定义不用改。**

*但它对「亮而长的粒子暴」系统性失效，这是个真的失效模式。* `multiplet_frac`
是个占比，分母是窗内计数，所以会被计数稀释：2023-06-15T14:08:35–14:08:59
那 0.63 s 里搜出 22 个重叠候选，个个 n ≈ 68、窗长约 980 µs（顶到 1 ms 上限）、
**12 路探头全亮**、CPD 命中率 **100%**、`pi_ratio` **1.03**（谱与本底完全重合），
`mf ≤ 0.3` 全部放行；同日 22:51:16 还有一个同型的。粒子暴越亮越长，越容易
从这条判据下漏过去，而那正是显著端。

*配套的第二道判据（新）*：**CPD 本底环境率 ≤ 500 c/s**。±10 ms 口径的那个
反常（幸存者 1.45）**100% 来自高本底环境的候选**，扣掉后降到 1.02，一点不剩。

*谱比的问题还在，而且判据帮倒忙。* 幸存者 `pi_ratio` 中位 1.25、被切者 1.38、
全样本 1.36——**切完之后样本反而变软了**，与 TGF 该有的方向相反（天格短硬暴
是 3.0）。这条没有解释，只能等闪电关联来判。

**两条已经证伪的路子，记下来免得重走：**

1. **把同戳数按偶然撞车期望归一化**（`期望对数 = n(n−1)/2·q/W`）当判据——
   坏统计量。窗长到亚微秒时槽位数 `W/q` 少于事例数，生日问题饱和，比值把
   选择整个倒过来：它优先留下「0.1 µs 窗内 8–12 个计数、点亮 7–11 路探头」
   这种最典型的粒子穿越。亚微秒窗里撞车本来就该发生，按偶然期望归一化在
   那一档没有分辨力。
2. **最小窗长判据**——白搭。亚微秒候选（365 个，10.8%）的 `mf` 中位是 0.875，
   早被 `mf ≤ 0.3` 切光了，再加 `bin ≥ 10 µs` 只从 528 减到 520。不要动
   `min_duration`。

**同戳类判据原理上抓不到「亮而长的粒子暴」，换分母也救不了。** 把 9 个
亮暴（去重后 `count ≥ 30`）逐条摊开：8 个的**同戳簇最大探头数是 1、跨探头
同戳占比 0.000**——窗内一对跨探头同戳都没有，它们那点 `mf`（0.03–0.15）
全部来自同探头的双增益重复（见第 17 条），不是粒子签名。物理上说得通：
单个粒子穿整台仪器才会在同一时戳点亮多路，而**簇射/粒子暴是几十个粒子在
1 ms 里陆续到达，各有各的时戳，本来就不该同戳**。`max_d ≤ 2` 对 45 个
`count ≥ 30` 的候选放行 45/45，`max_d ≤ 1` 放行 37/45。**能抓住它们的只有
CPD**：9 个全部 `cpd10 ≥ 1`，CPD 本底率中位 2557 c/s，谱比中位 1.07。

`mf ≤ 0.3` 的通过率随窗内计数单调上升，正是这个稀释：

| 窗内计数 | n | 通过率 | 窗长中位 | 点亮 | 谱比 |
|---|---|---|---|---|---|
| 8–10 | 2444 | 9.2% | 66.7 µs | 6 路 | 1.39 |
| 10–15 | 550 | 30.0% | 209.3 µs | 7 路 | 1.31 |
| 15–30 | 111 | 53.2% | 711.6 µs | 8 路 | 1.29 |
| ≥ 60 | 5 | 100% | 978.6 µs | 12 路 | 1.12 |

**一条方法上的纪律：一次持续的粒子增强会被搜索抓成几十次独立短暴，做统计
之前要按人群摘掉。** 2023-06-15T14:08:35–14:08:59 那 0.63 s 里就有 22 个候选，
同日 22:51 还有 10 个。**注意这不是管线漏并**——共用的 `snapshot_stepping`
里 `Candidate::mergeable` 早就把严格重叠的候选并掉了（HXMT v6 实测重叠对数
为 0），那 22 个是窗长短、彼此不重叠，所以是**人群问题不是归并问题**。

**不要按 episode（时间聚簇）归并。** HXMT 实测残留的 61 个多成员 episode
跨度中位 11 ms、分散在几十个日期，154 个成员里有 17 个带闪电关联——
**TGF 本身就有毫秒级多脉冲结构，按 episode 并会把物理抹掉**。该用的是
`blink_wwlln` 里那条列车密度判据 `neighbors_10min`：数每个候选 ±600 s 内
**全量初始候选池**（含亚阈）里有多少邻居，超阈就摘。HXMT 实测认证 REP
切 98.8%、认证 TGF 只误切 0.7%；`is_train=1` 的候选按 1 s 归并压缩 86.1%
而 `is_train=0` 的只压缩 0.98%，**亚秒堆积和分钟级列车是同一批物理事件**。
**但这条判据在 GECAM-C 上实测双向失效，不要照搬。** 一天 3385 个候选的
±600 s 邻居数：中位 53、四分位 45–63、5–95% 31–75、最大 97（均匀分布下
的期望是池率 × 1200 s = 47.0）。绝对阈 34 **坐在分布的第 8 百分位**，
摘掉 92.2%、把 `fa ≤ 0.01` 的干净幸存者 15 个全摘光；按池中位缩放的
`max(34, round(3.78 × 53)) = 200` **高过分布最大值 97，一个都摘不掉**，
等于关掉判据。

**更要命的是它对检验样本零分辨力**：那两串粒子增强（14:08 的 36 个散在
0.63 s、22:51 的 17 个）的 `neighbors_10min` 分别是 61 和 85，**就是池中位
的水平**——一次 0.63 秒的增强在 ±600 s 的计数窗里根本看不见。按邻居数
分五档之后，真伪相关的量全平（`mf` 通过率 15.6/13.6/15.7/13.2/21.1%、
CPD 命中率 12.6/14.0/15.4/13.0/14.7%、谱比 1.35–1.37），**唯一单调的是
地理纬度**（|lat| 中位 70.7° → 40.3° → 33.3° → 21.0° → 14.8°）。
**在 GECAM-C 上 `neighbors_10min` 携带的是轨道位置信息，不是真伪信息。**

**根因是尺度不匹配，正确的做法是按人群扫尺度。** GECAM-C 要的是**亚秒**
尺度（0.63 s 里 36 个候选），天格要的是**几十秒**——天格把窗从 ±600 s 换成
±30 s 之后，17 个高磁纬软暴的同类尖峰数中位 **182**（范围 10–508，17/17
全有）而 29 个短硬暴（含 7 个闪电证实）只有 **4**，泊松期望约 2 个/分钟，
超出 90 倍，据此定性为磁层沉降电子微暴。两台仪器独立指向同一件事。
**要做的**：±0.5 / 5 / 30 / 60 / 600 s 各扫一次，把整条分离度曲线报出来，
别只报某一个尺度下的结论——天格早先在 ±600 s 上量到「软暴不成串」，
换到 ±30 s 结论完全相反。

（先前据 22 个未摘的候选误得出「fa ≤ 0.01 的幸存者 CPD 命中 9 个、期望 0.6，
15 倍超出」；摘掉之后是 5 个、正规期望 2.47，2.0 倍。**期望值差 5 倍是因为
用全局 330 c/s 代替了当地实测率**——那 21 个里有几个在 2500–3400 c/s 的
环境里。全局率不能代替当地率。）

**另一条已经证伪的机制假说**：「擦边入射的粒子只穿一两路探头，表现为单路
大沉积 + 余辉/堆积，跨探头同戳为零因而漏过判据」。否证：幸存者的
`det_frac_max` 中位在**每一个 fa 档上都是 0.250**，p90 ≤ 0.404，`fa ≤ 0.01`
的幸存者里没有一个 ≥ 0.6；被切侧中位同样是 0.250。单路集中这个形态在
幸存者里根本不存在。**顺带**：这也说明 `MAX_DETECTOR_FRACTION = 0.8` 那条
单路毛刺判据在 GECAM-C 上等于空转——全样本 `det_frac_max` 的 p90 才 0.375，
根本没有东西给它拦。别以为它在干活。

**要做的**：

* **闪电反标定**：拿 WWLLN 证实的候选看它们在 `multiplet_frac` 上怎么分布。
  这是外部真值，比任何内部一致性都硬。正确问法是「证实样本的分布长什么样」，
  不是「阈值切完还剩几个关联」——若证实样本的分布与全样本无差别，说明同戳量
  根本不携带真伪信息，那也是结论。
* **验收线（`main` 定的）**：GECAM-B 在 274.5 天里 147 个已发表 TGF =
  **0.54 个/天**，而且是在轨道倾角 29°、只覆盖 TGF 主产区的条件下。
  C 星 12 路 GRD（B 的一半面积）、太阳同步轨道，量级只会更低。
  **在候选率降到每天几个之前，任何判据组合都不算收敛。** 现在切完剩
  377 个/天，高出 2–3 个数量级。
* **零成本的第一个实验**：已发表判据是 P < 2e-21，折成我们的口径约是
  `fa ≤ 7e-7 /年`（我们的 `fa ≤ 20` 对应 sf ≈ 5.5e-14，两者差约 3e7 倍）。
  拿已落盘的候选表切一刀就行，不用重跑。**两种结局都有信息**：剩下个位数
  且 CPD 干净，说明超出主要是阈值口径差异；剩下个位数但全带 CPD 标记，
  说明粒子污染一路顶到最显著端、判据链仍然没有分辨力。所以**不要只报剩
  几个，同时报剩下那几个的 CPD 标记率和同戳占比**。
* **分组符合（`coincidence = 2`）已评估，暂不做**：带电粒子穿仪器恰恰是
  同时点亮多路（C 星最显著候选 7 路同戳、A 星 `n_det_hit` 中位 7），
  任何分组下都会同时越两组的线，**对我们的主要污染源结构性无效**；它拦的
  是「计数挤在一路」的毛刺，而那种形态在 A 和 C 上都不存在。另外已发表
  判据里的「GRD 组」是按指向的物理分组，我们不知道 25 路的真实分组。
* **CPD 判据的定标主战场移到 GECAM-B**：8 路 CPD 对 25 路 GRD，而 C 星只有
  2 路对 12 路，14.1% 的命中率天生偏低、分辨力弱，在 C 星上调阈值是在跟统计
  噪声较劲。B 星定出来的判据再回头套 C 星。

**在闪电反标定给出答案之前，同戳量只是离线分析量，Rust 搜索侧一个字不动。**

**一个还没评估的替代方案**（比候选级否决干净，但改的是搜索语义，要先获批）：
不在候选级否决，而在**事例流层面把同戳的跨探头计数并成一个事例**再交给搜索。
一次粒子穿越在泊松意义上本来就是一个事件，并了之后独立性从源头恢复，本底
估计也跟着一致地修正；而 TGF 的光子彼此独立，落进同一个 0.03 µs 格子的很少，
代价很小。这条没有实测支撑，只是设计上的判断。

### 15. GECAM-A 的标定库停在 2022-01-14 之前的生成器（加载器已放行）

标定库 readme 原话：`v0.9 pi：最后50道超高不再从read_highlow_threshold_kev
读取并计算，而是直接填0`；`2022-01-14 软件重大更新。之前50道超高都赋值0，
现在下阈改为4096道对应的能量；上阈改为20MeV`。GECAM-B/C 跟进了新版，
**GECAM-A 的 `pi/` 只有 2023-01-10 那一版，一直在用旧生成器**，所以 A 星
全部 4,609 小时的 ch448 `E_MAX` 都是 0.0 而不是 20000——实测 9 个 epoch
横跨 2022-10 到 2026-06、24 个文件无一例外。

原来那条"`E_MAX` 必须是 20000"的溢出道校验因此把 A 星整颗星拒之门外
（试跑 2024-01-11：3 小时 `corrupt_data` + 21 小时 `missing_data`，
搜索小时数为零）。现在两个哨兵值都放行；道 0..447 的连续性、头尾、
40 keV 落在 ch54 这几条一条没松，A 星与 B 星那把梯子逐道完全一致、全程都过。

**还没做的**：A 星的 `c2e`（能量刻度）只有 9 个 epoch——1971/01/01 那份默认，
加 2025/01..04 和 2026/03..06。**2022-10 .. 2024-12 完全没有在轨 EC**，
而这段正是 A 星唯一落在 WWLLN 覆盖内的部分；2025-05 .. 2026-02 也是空的。
对照 GECAM-B 的 `c2e` 有 67 个 epoch、2020-12 发射后立刻起一路密集到 2026-06。
判据只用道号（`54 <= PI < 448`），所以这是能阈口径的系统误差而不是正确性
问题，但幅度要量：拿 LaBr₃ 的 ¹³⁸La 内禀本底线（约 1470 keV，落在 ch300

### 18. 时戳量化不是仪器参数，是 float64 的 ulp（已答，2026-09-10）

先前记的「时戳量化约 0.03 µs」错了，而正确答案不是换一个常数就完事。

实测 GECAM-C 2023-06-15：最小正间隔 **1.49012e−8 s，正好 = 2⁻²⁶ s**，把
相对时刻除以 2⁻²⁶ 余数中位 0、p99 0、最大 0（完全整除）。而 **2022-08-15
的最小正间隔是 7.4505806e−9 s = 2⁻²⁷ s，正好是一半**。TIME 列是 `D`
（float64）秒、TSTART = 7.737e7 s，**`np.spacing(TSTART)` 与实测值比值
1.0000**——所谓「量化」是归档把时刻存成 float64 秒造成的，**跨过 2ⁿ 秒就
粗一倍**：

| | q 变粗的日期 | 之前 | 之后 |
|---|---|---|---|
| GECAM-C（历元 2021-01-01） | **2023-02-16T17:21:04**（MET = 2²⁶ s） | 7.45 ns | 14.9 ns |
| GECAM-A / B（历元 2019-01-01） | **2023-04-03T10:42:08**（MET = 2²⁷ s） | 14.9 ns | 29.8 ns |

**GECAM-B 有三个纪元不是两个（2026-09-11 补）。** B 星 2020-12-10 就有数据，
而它跨过 **2²⁶ s 是在 2021-02-15T17:21:04**，所以 B 星是：

| GECAM-B | q |
|---|---|
| 2020-12-10 .. 2021-02-15T17:21:04 | **7.45 ns**（2⁻²⁷） |
| .. 2023-04-03T10:42:08 | 14.9 ns |
| 之后 | 29.8 ns |

147 个已发表 TGF 里有 **4 个（3 个小时）落在 7.45 ns 那一段**。上面三个日期是
按 `2ⁿ` 精确算的；先前写的 2023-02-19 / 2023-04-01 是逐日抽样的分辨率。
**正确的实现是逐候选取 `np.spacing(t0)`，不要查表。**

**那个「支路延迟」是单一的约 100 ns，89 / 96.9 / 104 / 119 全是量化产物
（2026-09-11 实测）。** 双增益对的时戳差在同一颗星（GECAM-B）、同一套电子学上，
三个归档量化步长给出三对不同的"延迟值"：

```
q = 7.45 ns   →  96.9 (6.01%)   104.3 (4.38%)     2021-01-20
q = 14.9 ns   →  89.4 (3–6%)    104.3 (4–10%)     2021-07 .. 2022-08
q = 29.8 ns   →  89.4 (8.85%)   119.2 (4.87%)     2024-01-11
```

96.9 与 104.3 只差一个 ulp，最简解释是**一个约 100 ns 的固定延迟被 float64
存储摊到相邻两格上**。所以 GECAM-A 上量到的「89 ns 和 119 ns 是 3 步和 4 步」
**不该读成两种延迟**，它是同一个延迟在 29.8 ns 格子上的投影。外部旁证：
GECAM-C 时序标定论文（arXiv 2308.11362）给的探头间相对定时精度 0.1 µs。

**A 星的数据绝大多数在 2025 年以后，q = 29.8 ns，是 C 星的两倍粗**；
任何按 q 归一化的判据都必须**按卫星、按日期取 q**，而且在任务中途会跳一次。
仪器真实时间分辨率 ≤ 7.45 ns，被归档格式抹掉了、拿不回来——所以
「GECAM 的时间分辨率是 15 ns」这种说法在对外材料里是错的，要改口径。

**天格不是这么回事，别照搬。** 天格历元 2018-01-01、数据在 2022–2024，
MET ≈ 1.3–2.1e8 s，float64 在这个量级的 ulp 是 2⁻²⁵–2⁻²⁶ s（15–30 ns），
而天格实测的量化步是 **2⁻²² s = 238 ns，粗 8–16 倍**，所以那个多半是真的
仪器/编码量化。

顺带修正第 14 条那个锚点：8 个计数、84 µs 窗、q = 14.9 ns 时偶然撞一对的
期望是 **0.50%**（先前写的 1.0% 用的是 0.03 µs）；三路同戳的期望是 1.8e−6，
n = 70 / 1 ms 时也只有 1.2e−5。**但「窗内出现三路同戳就是粒子、零参数零阈值」
这句话已被证伪，见第 14 条末尾新增的那一段**——它只说明本底不会误触发，没说
真 TGF 不会。「撞一对给出的占比正好 2/8 = 0.25」这一条不受 q 影响。

### 19a. GECAM-A 的原始记录：ch≈379 与那个宽堆积包

天格上实测过一类缺陷：每个探头有自己的量程上限，上限之下一个超量程沉积的
堆积包、之上基本为零，而准入只把最高道当溢出道，于是这些沉积以"1.2–1.9 MeV
硬光子"的身份进了搜索和谱硬度——扣掉之后他们 TGF 群的硬度中位从 **4.24 掉到
2.06**。

**GECAM-A 上确实有（2024-01-11，3 个过境、逐 25 路逐增益档实测）：**

| | 低增益档（去重后保留的那一支） | 高增益档 |
|---|---|---|
| 陡降位置（最后一个 ≥10 计数的道） | 中位 **379**，逐路 375–381 | 中位 **157**，逐路 149–160 |
| 对应能量 | ch376 = 3867、ch379 = 4024、ch383 = 4243 keV | ch157 ≈ 215 keV |
| 陡降之下的堆积包抬升 | 中位 **12.8–14.4 倍**，最大 21.8 倍 | 0.34–0.36 倍（**没有包**） |

谱形（h02，`d01`，原始计数）：平台约 250 计数/道，`ch368` 起暴涨到 9750
（39 倍），撑到 `ch378 = 3827`，`ch379` 掉到 3——**两个数量级的悬崖，上面
全是零**。`d07` 峰在 ch370 = 14563，`d25` 撑到 ch378 = 3930 后归零。
**这就是超量程沉积堆在上限附近的形状，与天格一模一样。**

**先前记的"位置不漂、是器件固定值、可以做静态逐探头上限表"是错的**——那是
只看了 2024-01-11（恰好是稳定的一天）得出的，抽样不足。跨 5 个 epoch 重测之后
结论变了两次：

**这个"上限"根本不是硬件量程，是 ADC 满量程经过能量刻度映射到的道号。**
ADC 在固定的原始码值上饱和，它落在哪一道取决于用哪份 `c2e`：

| epoch | 在轨 EC | 高增益 `edge` | 低增益 `edge` |
|---|---|---|---|
| 2022-10-21 | 无 | 156 | 379 |
| 2023-06-16 | 无 | 156 / 156 / **165** | 379 / 379 / **383** |
| 2024-01-11 | 无 | 157 / 157 / 156 | 379 / 379 / 379 |
| 2024-09-06 | 无 | 157 / 157 / 156 | 379 / 379 / 379 |
| **2025-06-15** | **有** | **227 / 230 / 233** | **447 / 447 / 447** |
| **2026-06-01** | **有** | **212 / 210 / 211** | **447 / 447 / 447** |

**台阶正好落在 CALDB 的 `c2e` 从 2025/01 起有 A 星的那条线上**：低增益从
ch379（4024 keV）跳到 **ch447（9921 keV，梯子顶）**——**梯子本来就是按
"满量程 = 顶道"设计的，是 2022–2024 段的标定把它压下来了。** 这与第 15 条
的能标偏差互为印证：默认 EC 在 1470 keV 处低估 12%，而 `c2e` 是分段二次的、
非线性使偏差随能量放大，到满量程处 447 → 379 相当于**低估 40%**；双增益两档
PI 差随能量发散（ch100–200 −13 道、ch200–300 −64 道）说的是同一件事。
**三条独立的测量指向同一个结论。**

**逐过境漂移确实存在，只是不是每天都发生：** 2023-06-16 那天三个过境里 h16
整体偏高 **9 道**（**25/25 路无一例外**，是整仪器的增益偏移不是个别探头），
2025-06-15 有 11/25 路极差 > 5 道；而 2024-01-11 / 2024-09-06 极差只有 0–2 道。
机制说得通——增益随温度走（CALDB readme 自己就在用「1470 keV 峰位 vs 温度」
修正），温度随轨道位置变，**而 2022–2024 段没有在轨 EC，这个漂完全没被修**。

**所以静态上限表不够**：要按 epoch 分段（2025 前后两个值），漂移活跃的日子还
要逐过境定。稳妥做法是**从数据本身逐过境求 `edge`，不查表**——那是一次直方图，
成本相对读 5400 万事例可忽略。

**污染是分段的，而且集中在最要紧的那一段：**

| | 2022–2024 段 | 2025+ 段 |
|---|---|---|
| 满量程道 | ch≈379 | ch≈447 |
| 堆积包位置 | **ch368–383** | ch420–447 |
| 现有 `PI < 448` 的准入 | **整个包都放进来了** | 挡住大半 |

**谱污染集中在没有在轨 EC 的 2022–2024 段——也就是 GECAM-A 唯一能做闪电关联的
那 370 小时。** 2025 年之后现有的 448 上界基本是对的（堆积包顶端 ch420–447
那截仍会漏进来）。逐路差异在有 EC 的段反而更大：2024-01-11 低增益逐路 375–381
（6 道），2026-06-01 是 **420–447（27 道）**。

**`PI < 448` 这半个准入条件是空转的**：`EVT_TYPE == 1` 的事例里
`PI >= 448` 占 **0.00%**（25 路 × 3 过境无一例外），溢出段与 `EVT_TYPE == 2`
是同一个集合。**`Event::keep` 里真正缺的不是 448 这个上界，是 ch≈379。**
现在 ch368–383 那个堆积包整个在准入范围内。

**还没做的**：

* GECAM-B / GECAM-C 上有没有同样的上限与堆积包，位置在哪、漂不漂。**B/C 的
  `c2e` 从发射后就有在轨版本（B 星 67 个 epoch），所以按上面的机制推，它们的
  满量程道本来就该在 ch447 附近、堆积包被现有上界挡住大半**——但这是推断，
  没测过。
* **准入上界怎么定还没定案。** 一个候选做法是 `EvtFile` 载入一小时时逐探头
  逐增益从 PI 直方图求满量程道、上界取 `edge − margin`，好处是自适应、
  CALDB 再更新一次也不失效，坏处是**引入"从数据自己定准入边界"的依赖**：
  统计量太少的过境（A 星有 GTI 只有 19 s 的文件）会把 `edge` 拖低而误切，
  所以要有下限保护。**这是搜索语义的修改，定案前先量"按正确口径切之后还剩
  什么"。**
* **超量程沉积与同戳簇是不是同一批事例。** 粒子沉积大、最容易超量程，
  若强相关，那么一个逐探头量程上限的准入上界可能**同时砍掉谱污染和一大块
  假候选**——而且这是**纯准入口径修正，不是新判据**。验法：把候选按"窗内
  事例落在 ch368 以上的占比"分组，看它与 `multiplet_frac` 是否正相关。
* 在这条查清之前，**所有谱学结论（谱比、硬度比、`HardnessRatio_200keV`）
  都带着这批 3.9–4.2 MeV 的假硬光子**，不能当定论。

### 20. `DEAD_TIME`：A/B 是 4 µs 常数（已答），C 星不是常数（未解释）

`DEAD_TIME` 列**每路只有一个取值 = 4**（GECAM-A 25 路 × 两档全部），**单位
没标**。同探头事例间隔：高增益档 p0.1% = 5.72 µs、p1% = 23.48 µs、中位
1439 µs；低增益档 p0.1% = 6.71 µs、p1% = 47.39 µs、中位 3779 µs。

若 `DEAD_TIME = 4` 的单位是 µs，它与实测间隔下沿（5.7–6.7 µs）差 40–70%。
**但这里用的是 p0.1% 分位而不是硬边沿，所以这条列为「没验成」**——死时间是
**分布的硬边沿**（直方图从零跳到峰的那个格），不是极小值，也不能拿最小正
间隔去推（天格实测最小正间隔比死时间小几十倍，会被偶发毛刺带偏）。
**要做的**：画事例间隔直方图找硬边沿，再与 `DEAD_TIME` 对。

**已答（2026-09-11）：单位是 µs，硬边沿 3993.5 ns。** 正确的问法不是"同探头
事例间隔的下沿在哪"（那被双增益重复对污染了——同一个物理光子的两条记录时戳差
只有 0–119 ns，远小于死时间），而是**"同探头、增益档相同的相邻事例对"**，那才
是两个真独立事例。GECAM-A 实测三个小时各 406 / 690 / 104 对落在 4 µs 内，
**时戳差全部恰好 3993.5 ns，p0 = p50 = p100 一个值、没有分布**。3993.5 ns 与
4 µs 差 0.16%，就是 float64 量化。

**但 `DEAD_TIME` 在 GECAM-C 上不是常数（2026-09-11 实测，仍未解释）。**
A 星 25 路 × 两档全部是 4；C 星 2023-06-15 12h 实测**有上百个取值、4.0–204.0 µs、
量化步 0.8 µs，分成不相连的两族**：短族 4.0–6.4，长族 69.6–204.0，中间是空的。
`dedupe_gain_pairs` 拿 `dead_time` 当合并窗，所以**在 C 星上合并窗最宽能到
204 µs**。这不是零代价：把低增益支路时戳整体平移 0.37 s 后重配做偶然对照，
**72,237 / 1,735,222 = 4.16% 的"对"是偶然的**；按旧的"时戳严格相等"口径只配到
约 132.5 万对，**死时间口径多配 31%**。**要做的**：查清那两族是什么（长族像是
某种触发/读出模式），以及候选窗内（事例密度高几个数量级）的偶然配对率——
那个数才是"去重误并了多少真事例"。

### 22. 事例流层面的跨探头合并（τ ≈ 150 ns）：已报批，门槛已定，未实现

第 14 条末尾那个"还没评估的替代方案"现在有了带实测常数的方案：**在 `search`
里排序、双增益去重之后，加一道跨探头单链接合并——相邻事例时戳差 ≤ τ 且探头号
不同，并成一个事例。** 一次带电粒子穿越在泊松意义上本来就是一个事件，并了
之后独立性从源头恢复，本底估计同步一致地修正。

**τ 是量出来的，标尺与候选/搜索/阈值全部无关**：双增益对（同一路、死时间内、
一高一低）是物理上确定的同一个光子，它们的时戳差就是电子学给同一件事打不同
时戳的幅度。三个量化纪元一致指向**一个约 100 ns 的固定延迟**（见第 18 条）。
平台检验：被并掉的计数占比 100→150 ns 还涨 0.35–0.51 个百分点，150→200 ns
只涨 0.03–0.05；簇内跨度 p50 = 60 ns / p99 = 149 ns，**簇不是被 τ 截断的**；
偶然期望富集 58–104 倍；多成员簇 100% 跨探头（同探头一对都没有，死时间保证）。
**τ 应当是常数、不随 q**：底下的量与量化格无关，q 只决定能不能分辨开；若改成
q 的倍数，C 星（q = 7.45/14.9 ns）的 τ 会缩到 30–60 ns，连那条 ~100 ns 的线
都盖不住。

**效果（A 星 2024-01-11，7050 s）**：`fa ≤ 20` 的候选 62,830 → 4，
8.9 /s → 5.7e-4 /s；τ 在 150–300 ns 之间结果不动。

**放行门槛（统筹定，四条，缺一不可）**：

1. **先做泊松性检验，它不过后面三条都不用做。** 取安静区间，合并后的到达间隔
   是不是指数分布、方差是不是等于均值。**若仍然过离散，`fa` 就仍然是错的，
   只是错得少一点**，整套显著性还是不能用。
2. **逐个已发表 TGF 报合并前后的净计数、显著性、`bin_size_best`，不止报
   "在不在"。** 147 个全都活着但净计数系统性掉了 15%，说明合并在吃真光子。
3. **损失率不许用解析式 `1 − exp(−n·τ/W)`，要往真实本底里注入测**，扫 (n, W)
   平面、特别是短而亮那一角，**而且注入模板要用真 TGF 的实测形态**（前沿陡、
   有拖尾；同样的 n 和 W 下光子挤在一起的程度完全不同，而挤在一起正是被 τ
   吃掉的条件——均匀撒点会把损失率系统性低估，正好偏在让判据显得安全的方向）。
4. **幸存者要逐个完整取证**，别因为它们是幸存者就默认是真的。

**这是搜索语义修改，所有既有 GECAM 目录与它不可比**，版本边界要在产物目录里
写死。代码在获批前只在分支上、标"未验证"。

### 23. `f₃ > 0` 不是与亮度无关的一刀（2026-09-11，修正第 14/18 条）

"窗 ≥ 10 µs 时 `f₃ > 0` 即粒子，三重偶然期望 ≤ 1e-5，零参数零阈值"——
**这句话只说明它不误杀本底，没说不误杀信号。** 单链接分簇的解析式
（`p = 1 − e^{−nτ/W}`，`P(至少一个三重) ≈ 1 − exp(−(n−2)p²)`，均匀撒点是下界）：

| 样本 | n | W (µs) | τ = 0 | τ = 150 ns |
|---|---|---|---|---|
| 典型 TGF | 30 | 111.4 | 0.18% | 4.29% |
| 亮 TGF | 100 | 111.4 | 6.60% | **78.89%** |
| **亮而短** | 100 | 30.0 | **58.37%** | 100% |

**连 τ = 0（时戳精确相等）的版本对亮而短的真 TGF 都要误杀 58%**，而那正是最
在意的一群。**正确用法是逐候选按它自己的 (n, W, τ) 算偶然期望，不是一刀切。**

反过来用它验最显著的一批（GECAM-A 2024-01-11，过了准入上界与窗长 ≥ 10 µs 之后
`fa ≤ 7e-7` 的 28 个）：这 28 个自己的 τ=150 三重偶然期望中位 0.048、最大
0.181，没有一个 > 0.5，**而实测 `f₃ > 0` 是 28/28**——偶然解释不了，
**这 28 个最显著的候选是粒子**。

### 24. 成串判据在 A 星与 C 星都是空的，而且原因不同

* **GECAM-C**：`neighbors_10min` 双向失效是**尺度不匹配**——粒子增强是亚秒
  尺度（0.63 s 里 36 个候选），而 ±600 s 的计数窗看不见它。换到 ±30/±60 s
  分离度就回来了（AUC 1.000）。
* **GECAM-A**：五个尺度（±0.5 / 5 / 30 / 60 / 600 s）幸存者对均匀期望之比
  全平在 1.0 ± 0.1。根因不是尺度，是**整个池子被均匀污染**——相邻候选间隔
  中位 0.076 s，而均匀泊松池的期望中位是 0.0778 s，**池子在时间上就是均匀的**。
  A 星的同戳簇是 25 路仪器上宇宙线穿越的**稳态本底**，不是发作式增强。

**两颗星合起来的结论：成串判据能不能用，取决于污染是不是发作式的；这件事要
逐仪器先量池子的时间均匀性，不能从别的任务搬。**

### 25. CPD 空壳文件拖死整小时好数据（2026-09-11 实测，待修）

`from_epoch` 的规则是「只放过找不到 CPD 文件；文件在却读坏了仍旧报错」。
**但归档里有一类占位空壳**——文件在、大小 28,800 字节、两个 `EVENTS` 表
**零行零列**，于是报 `corrupt_data: Cannot find column "TIME"`，**整小时被扔**，
连同那一小时完好的 GRD 数据。

实测追到的例子（GECAM-C 2023-01-30 那一小时，就是 30 天旧账里 searched 654 ≠
应有 655 差的那一个）：GRD 有 `v00` 空壳和 `v01` 的 269 MB / 1,481 万事例好文件，
**版本选择正确取了 v01**（版本号解析那条修复在起作用）；拖死它的是只有 `v00`
的 CPD 空壳。

全任务扫（按最大版本的 `EVENTS` 表有没有列判）：

```
CPD 空壳（零列） 217 小时      GRD 空壳（零列） 206 小时
CPD 空壳而同一小时 GRD 是好文件（> 1 MB）的: 20 小时  ← 白丢的
```

**20 小时 = 0.10%**，量不大但是纯损失。**建议的窄修法**：CPD 文件存在但
`EVENTS` 表零列/零行 → 与「找不到 CPD 文件」同等对待（降级成这一小时没有 CPD，
`acd = None`，GRD 照常搜）；**GRD 空壳必须照旧致命。** 空壳与真损坏形态上分得开
（零行零列，不是读到一半乱码），所以这个放宽不会顺带放过坏数据。

### 26. GECAM-C 是太阳同步轨道，LST 判别量在 C 星上不可用（已答，2026-09-11）

从 posatt 直接量，不查文献：1,610 个升交点、886 天（2022-08-03 .. 2025-02-13），
**升交点地方时（LTAN）锁在 22.5 h 附近，913 天只漂 +0.81 h**（逐 60 天中位
22.509 → 22.527 → 22.797 → 23.469 h，四分位极紧）。对照非同步轨道
（Fermi 倾角 25.6°）进动周期约 53 天、会走遍 24 h。**判定：太阳同步。**

**后果是当地太阳时（LST）成分拟合这条判别量在 C 星上前置检验不通过：**

```
磁纬带       采样点    LST 覆盖的 2h 格数   最大格/最小格   变异系数
 0–10°       17183         2/12              8595          2.24
10–20°       17218         2/12              8630          2.24
20–30°       17202         2/12              8606          2.24
30–40°       17244         6/12              8441          2.17
40–55°       26272         6/12             10444          1.74
55–90°       57447        12/12                 5.7         0.61
```

**在 TGF 主产区（|磁纬| < 30°）12 个两小时格里只有 2 个有曝光，最大/最小 8,600 倍**
（全样本 LST 逐小时曝光两个尖峰在 10 时与 22 时、各占 23.2%；2–7 时与 14–19 时
合计不到 5%）。**用两个地方时点拟合雷暴日变化曲线是不可能的。** 只有
|磁纬| > 55° 那一带铺得开（12/12、变异系数 0.61），而那是极冠、不产 TGF。

**"GECAM-C 的轨道使 LST 判别量不可用"——这句可以直接写进论文限制。**
太阳同步轨道的升交点地方时被锁死是它的**定义性质**，不是"可能有"的风险。
GECAM-A/B 倾角 29°，属于会进动的一类，前提大概率通过，但**仍要各自量一遍**
（A 星有效数据只有 554 天且零散，进动可能没走完整周）。

**一条口径**：GTI 缺口落在极冠这个形态是**高倾角**的指纹，不是**太阳同步**的
指纹——极冠穿越对任何近极轨道都成立，太阳同步是对轨道面进动率的额外约束，
靠 GTI 形态区分不了，必须看 LTAN 漂不漂。

### 27. `multiplet_frac ≤ 0.3` 作为硬判据已出局（2026-09-11，外部真值判的）

规矩是**任何判据只要切掉正样本里任何一个就不能用**。拿 147 个已发表 TGF 量：

* 按我们匹配上的最佳格量，`mf ≤ 0.3` 放行 **128/140 = 91.4%**，切掉 12 个。
* 担心"最佳格可能落在 TGF 旁边的粒子尖峰上而不是 TGF 本身"，所以另做了一次
  **构造无关**的复测：完全不用我们的最佳格，只锚目录 UT，在 ±3 ms 里用固定
  100 µs 滑窗找计数最高的一格。放行 **133/145 = 91.7% [86.1, 95.2]**，
  **与按最佳格量的 91.4% 一致——所以那 8.3% 的损失是真的，不是选窗选出来的。**

**而且损失集中在暗端，正是我们的候选所在的地方**：按目录 `NetCounts` 分档，
< 30 只放行 **47.4% [27.3, 68.3]**，30–60 是 97.3%，≥ 60 是 100% / 95.2%。
**根因是 `mf` 的分母是窗内计数**——计数少就被偶然撞的一对顶上去，而我们候选的
计数中位是 9，比这里最差那一档还低。

**这条与第 14 条里"`mf ≤ 0.3` 通过率随窗内计数单调上升"是同一件事的两面**：
在污染上它表现为"亮而长的粒子暴漏过去"，在信号上它表现为"暗而短的真 TGF 被
切掉"。**一个会被计数稀释的占比，两头都靠不住。**

**它仍可以当离线诊断量记录，不要当硬判据。**

### 28. CPD 的正确用法是亚微秒时戳差，不是"窗内有没有计数"（方向确定，阈未定）

第 14 条那个 ±10 µs 的"有没有 CPD 计数"没有分辨力（第 14 条开头的撤回说明了
为什么）。换成**最近的 CPD 计数与 GRD 计数的时戳差**之后，分离出来了：

| | 真 TGF（145 个峰窗） | 对照（40,800 个池候选最佳格） |
|---|---|---|
| 窗内 CPD 计数 | 363 | 30,342 |
| `\|Δt\|` 中位 | 0.268 µs | **0.000 µs** |
| **`\|Δt\| == 0` 的 CPD 计数占** | **5.79%** | **62.04%** |
| `\|Δt\| ≤ 1 µs` 的占 | 81.54% | 75.26% |

**分离 10.7 倍，而且全部集中在 0–0.1 µs；窗开到 1 µs 两边就几乎相等**——
这正解释了原来那个 ±10 µs 口径为什么没有分辨力。物理上说得通：**粒子穿仪器时
CPD 与多路 GRD 记的是同一次沉积、同一个时戳；而真 TGF 在 CPD 里的计数是另一个
伽马散射来的，没有理由与任何 GRD 计数同戳。**

**还不能直接当否决用**：按候选级"有 ≥1 对同戳就否决"切掉真 TGF
**11.72% [7.45, 17.97]**、切掉池 35.34%，净富集只有 3.0×。**该用占比不是有无，
阈要在新口径池上重扫。** 标"方向确定、阈值未定"。

一条口径优势：**CPD 表没有 `GAIN_TYPE`、不参与双增益去重，所以这条量基本不受
去重口径变动的影响。**

### 29. LST 判别量：A/B 可用，C 不可用；模板要借 HXMT（2026-09-11）

**0a（模板对比度）GECAM 过关**：147 个已发表 TGF（触发目录，**不是闪电认证的**
——任何经闪电关联认证的样本都带 WWLLN 夜间效率造成的约 6 小时相位偏置，
HXMT 实测关联样本峰在 LST 1.5 h、未关联样本峰在 16.5 h）的 LST 分布
**瑞利 R = 0.163、Z = 3.90、p = 0.0199**，极小值 09–12 h、最大值 15–18 h。
对照 SVOM 的 83 个闪电证实样本 p = 0.82（塌了）。

**跨仪器互校是这一条里最值钱的**：与 **HXMT 未关联那 4677 个**比
**χ² = 3.86 / 7，形状一致**。两个独立仪器、倾角 29° vs 43°、触发目录 vs
我们的搜索，峰谷全对上——**同时验了三件事**：LST 算法没错、HXMT 那批确实以
TGF 为主、我们可以借它的大模板。

**但 147 个的模板直接用会系统性压低 `f_TGF`，这是回归稀释不是统计涨落**：
观测 `Σ(p − 1/8)² = 0.01415`，纯多项式涨落就占 `7/(8·147) = 0.00595`，去偏后
真实偏离只有 0.00820，衰减因子 0.58。蒙卡（300 次）实测偏差**不随 N 缩小**：
N = 100,000、f = 0.20 → f̂ 0.123；f = 0.50 → f̂ 0.307。换成 HXMT 那 4677 个当
模板偏差基本消失、σ 还小一倍。**建议：用 HXMT 未关联当模板报相对纯度
`g = f_D/f_T`（合法性来自 χ² = 3.86/7），要绝对纯度就用 147 个那份并把 0.58
显式解卷积回去、把它自己的不确定度传上。两者分开报，别混。**

**三条限定：**
1. **陆海拆分方向对但分离弱**：陆 41 个（R = 0.273、p = 0.046、圆均值 18.79 h）
   vs 海 106 个（R = 0.130、p = 0.166、圆均值 21.02 h），**两个子模板圆均值只
   差 2.2 h，不是一个午后一个凌晨**；而且目录给的是**星下点**不是源位置，沿海
   的会分错。**这也是借 HXMT 模板的风险所在**：B 星倾角 29°、样本 72% 在海上，
   HXMT 倾角 43° 能覆盖中纬大陆雷暴区，**借模板要带纬度带失配的限定。**
2. **模板的对比度全部来自暗的那一半**：亮半（n = 74）R = 0.093、p = 0.43
   **是平的**；暗半（n = 73）R = 0.321、p = 0.006；两半形状不一致（χ² = 17.90/7，
   p ≈ 0.012）。而我们要拟的候选（计数中位 9）比模板（`NetCounts` 中位 66.9）
   暗得多。
3. **0b（曝光平坦性）三星分别判**（见第 26 条）：

| | 抽样 | 跨度 | 升交点 LST 范围 | 圆集中度 R | 判 |
|---|---|---|---|---|---|
| GECAM-A | 79 天 | 1411 天 | 0.35 .. 23.72 h | 0.156 | 通过（χ² = 5.8/7） |
| GECAM-B | 204 天 | 2073 天 | 0.09 .. 23.86 h | **0.018** | 通过 |
| GECAM-C | 176 天 | 913 天 | **22.49 .. 23.52 h** | **0.998** | **不通过，太阳同步** |

C 星那条还有一条**用完全不同输入的独立验证**：本底候选（`fa > 1`，30 天
52,823 个）逐磁纬带的 LST 分布，**|磁纬| < 40° 的每条带子里候选只落在两个
3 小时格、其余六格恰好是零**（χ² 两万量级），非空的两格是 09–12 h 与 21–24 h，
与升交点地方时 22.5–23.5 h 差约 12 h，自洽。

**A 星不能靠轨道判型免掉曝光平坦性检验**：轨道管"能看到哪些 LST"，观测计划管
"实际记了哪些"，而 A 星 2024-02..06 长期每天固定 3 小时。

**一个共用的坑**：POSATT 里有 `X = Y = Z = 0` 的坏行，两条独立做这件事的脚本
都被它坑过（一条把某天算成上百个假升交点、首轮得出 B 星 R = 0.645 的错数）。
**按 `|r|` 过滤。**

**0b-ii 的正确问法（2026-09-11 补，这条会咬别的仪器）**：不是"实测的候选 LST
分布平不平"，而是**"实测结构比只由轨道相位造成的结构多多少"**。做法是拿同期
posatt 按曝光加权算一份"纯轨道预期"的 LST 直方当分母，再跟实测比。

理由是量出来的。把升交点 LST 减去一个线性漂移再扫漂移率、取圆集中度最大的那个：

| | 漂移率 | 折合进动周期 | 对齐后 R |
|---|---|---|---|
| GECAM-A | **−0.4953 h/天** | **48.5 天** | 0.696 |
| GECAM-B | **−0.4946 h/天** | **48.5 天** | 0.973 |
| GECAM-C | **+0.0008 h/天** | 约 3 万天 | 0.999 |

A 与 B 的漂移率到小数点后三位一致（同一星座同一条轨道，本该如此，也是这个扫描
没算错的旁证）；C 星慢 600 倍，与"913 天漂 +0.81 h"对得上。

**所以 A 星现有那 3 天的候选表跑出来的"本底强结构化"（`fa > 1` 的 21,399 个、
全样本 R = 0.368、`|磁纬| 0–10°` 有 70.12% 挤在 15–18 h、三个格恰好为零）
不能当 A 星的 0b-ii 结论**：3 天只走完进动周期的 6.2%，**一段短于进动周期的
曝光 LST 覆盖必然结构化，这与观测计划无关，是轨道本身。** 3 天的样本没有能力
区分"轨道相位没走完"和"观测计划挑了地方时"，报"A 星本底不平"会把轨道的账算到
计划头上。

B 星虽然跨 2073 天、走了 42 个进动周期，**但逐磁纬带分完之后每格的有效天数会
掉下来，这个分母仍然该算。**
